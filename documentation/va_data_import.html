📥 Data File Import

Upload tab-delimited VA data files and import directly into iDash — no SSMS, no file shares, no copy-paste.

Overview

The Data File Import tool replaces the manual process of running SQL scripts in SSMS to import asset data from VA data extracts. It handles everything automatically:

  1. Parses the tab-delimited file
  2. Streams rows to SQL Server using high-speed bulk copy
  3. Maps raw data to the iDash schema (EPC tags, SP locations, company IDs)
  4. Inserts new locations and assets
  5. Normalizes legacy data (SP prefixes, status values, location links)

Import Modes

The tool supports two modes to handle different data scenarios:

ModeWhen to UseWhat It Does
Force Site Number Single-site files (e.g., Prescott 649 data extract) All rows get the station number you enter. Fills in blank STATION NUMBER values.
Auto-detect from File Multi-site files with different stations per row Uses the STATION NUMBER column from each row as-is. Rows with blank stations get a fallback company ID of 0.
When in doubt, use Force Site. Most VA data extracts are single-site and some rows may have blank station numbers. Force Site ensures every row gets the correct station assignment.

How It Works

Step 1: File Parsing

The uploaded file is read on the web server and parsed into a structured format. You can preview the first 20 rows before committing.

Step 2: Bulk Streaming

All rows are streamed to the SQL Server staging table (dbo.AssetFileRaw) using SqlBulkCopy in batches of 2,000. This is the same mechanism that SSMS uses internally — fast and reliable.

Step 3: Data Transformation

The merge logic performs the following transformations (matching va_dbupdate.sql):

  • Name computation: [StationNumber] EE[EntryNumber] (with duplicate-prefix guard)
  • EPC/rfidtag generation: Computed from the cleaned name with F-padding
  • Company mapping: Matches first 3 digits of station number to company name prefix
  • Location normalization: All locations get SP prefix; blanks become SPZZUNKNOWN
  • Date normalization: Converts inventory dates to datetimeoffset format
  • Use Status: Blank statuses default to IN USE
  • Description cleanup: Strips quotes and special whitespace characters

Step 4: Insert & Link

  • New locations are inserted (deduplicated against existing)
  • New assets are inserted (deduplicated by name+company and rfidtag)
  • All unlinked assets get their locationid linked
  • Legacy data across the entire database gets SP prefix and company ID corrections

PowerShell CLI Alternative

For command-line imports (e.g., from remote machines without browser access), use the PowerShell script:

# Force Site mode (single-site file)
.\Import-PrescottData.ps1 -SqlServer "VA-SQL-HOST" -ForceSite "649"

# Auto-detect mode (multi-site file)
.\Import-PrescottData.ps1 -SqlServer "VA-SQL-HOST"

# Dry run (staging only, no merge)
.\Import-PrescottData.ps1 -SqlServer "VA-SQL-HOST" -ForceSite "649" -DryRun

Troubleshooting

File too large

The upload limit is set to 50MB. If your file exceeds this, use the PowerShell CLI script instead (no size limit).

Assets not inserted (all skipped)

This means assets with the same name+company already exist in the database. The import is additive — it never overwrites existing data. Run a SELECT query to verify.

Wrong company mapping

The import matches the first 3 digits of the station number against the first 3 characters of company names. If a company record doesn't exist, one is auto-created as [StationNumber] Unknown. Rename it after import to the correct site name.

Location names look wrong

All locations are prefixed with SP (Service Pointer). If the raw data already has SP, the tool strips it first then re-adds it to prevent double-prefixing (SPSP...).

Best practice: Always use "Preview First 20 Rows" before importing to verify the file was parsed correctly and columns are in the expected order.

🔎 IIS & App Log Analyzer

IIS W3C Logs Serilog App Logs Read-Only — No DB Required Login Audit
🔎 What This Page Does: The IIS & App Log Analyzer is an advanced, read-only log analysis tool for iDash administrators. It parses raw IIS web server access logs and .NET application logs directly from the server's file system and presents them in a searchable, filterable dashboard — complete with KPI summaries, bar charts, and an automated error diagnosis engine.

Module Purpose

When something goes wrong with the iDash portal or the iDash backend service, this page is where you start your investigation. It reads two types of logs:

  • IIS Web Server Logs (Tab 1 — Default): The raw access log written by IIS (Windows web server) for every single HTTP request that hits the server. Think of it like a security camera log for your web site — every page visit, every API call, every error response is recorded here.
  • Application Service Logs (Tab 2): The structured log written by the iDash .NET background service using the Serilog logging library. This is where authentication failures, database connection errors, and application startup problems are recorded.
  • Login Audit Trail (Tab 4): A persistent audit log of every sign-in attempt to iDash. Records username, IP address, timestamp, role, and whether the login succeeded or failed. Auto-trimmed at 90 days or 5,000 entries.
⚠ Login Required: This page requires an administrator login using the iDash admin account (idashadmin). The login gate appears automatically when you open the page. Once authenticated, your session is remembered for the browser session.

Tab 1 — IIS Web Server Logs

IIS logs are W3C Extended Format text files stored in C:\inetpub\logs\LogFiles\W3SVC1\. A new file is created each day, named like u_ex260425.log (year+month+day).

What You See

  • KPI Cards: Total requests, 2xx successes, 3xx redirects, 4xx/5xx errors, unique client IPs, average response time in milliseconds, and total megabytes sent.
  • Top Pages Chart: Bar graph showing the 8 most-requested pages/endpoints on the server.
  • Top Client IPs Chart: Bar graph showing the 8 most active client IP addresses (loopback excluded).
  • Status Code Breakdown: Visual breakdown of 2xx / 3xx / 4xx / 5xx response groups.
  • Filterable Log Table: Every matching request shown with date, time, client IP, HTTP method, URI, query string, status code, response time, and browser.

Tab 2 — Application Service Logs

Application logs are written by the iDash .NET background service using Serilog structured logging. Files are stored in C:\logs\ with .txt or .log extensions. Each line in the file represents one log entry, formatted like: 

2026-04-15 11:27:15.492 -04:00 [ERR] Unable to acquire authentication token. GetTokenEndpoint failed.

Log Level Badges

Each log entry is color-coded by severity level:

ERR / FTL Error or Fatal — something broke. These need attention. Red background on the row.
WRN Warning — something unusual happened but the service kept running. Yellow background.
INF Informational — normal operational activity (service started, request handled, etc.).
DBG / VRB Debug or Verbose — very detailed developer messages. Usually not shown unless debugging.

KPI Cards on App Logs Tab

  • Total Entries: Total log entries in the selected file.
  • Errors [ERR]: Count of ERR + FTL entries — the ones that need investigation.
  • Warnings [WRN]: Count of warning-level entries.
  • Info [INF]: Count of normal informational entries.
  • Unique Messages: Number of distinct log messages — high ratios indicate spam/flooding.
  • Top Error Repeat -: The single most repeated error message — its repeat count. A high number means the same crash is happening over and over.

Auto-Diagnosis Banner

The analyzer automatically scans the loaded log file for known failure patterns and displays a highlighted warning banner at the top when issues are found. Currently it detects:

  • Authentication token failures — detected when errors mention GetTokenEndpoint, openid-configuration, or Unable to acquire authentication token. Root cause: the iDash API / IdentityServer process at http://localhost/ is not running. Fix: start it in IIS.
  • High-frequency error spam — when the same error appears 5 or more times, the banner calls it out with the repeat count. This indicates a crash loop that is flooding the log file and should be fixed urgently.
  • Startup messages logged as ERR — indicates a misconfigured Serilog minimum level setting.

Access Control

The page uses a simple session-based admin guard. The login credentials are the iDash SQL administrator account. Upon a successful login, Session["IsAdminAuthenticated"] is set to true, unlocking the main dashboard panels. Clicking Logout clears the session flag and returns to the login screen.

🔒 Security Note: The admin credentials for this page are the same as the iDash SQL admin account configured in web.config. Do not share this password with non-administrative staff. The credential is stored in the application's session — it is not transmitted on each request after login.

Frequently Asked Questions

  • Q: The IIS log dropdown is empty. What happened?
    A: The IIS log directory C:\inetpub\logs\LogFiles\W3SVC1\ does not exist or contains no log files. Verify that IIS logging is enabled for the site in IIS Manager.
  • Q: The App Logs dropdown is empty. What happened?
    A: No .txt or .log files were found in C:\logs\. The iDash service may not have written any logs yet, or the Serilog output path may be configured differently.
  • Q: I see hundreds of "Unable to acquire authentication token" errors. What should I do?
    A: The iDash API (IdentityServer) is not running. Open IIS Manager, find the iDash API site, and start it. Then wait 1–2 minutes — the errors should stop appearing in new log files.
  • Q: Can I delete or clear log files from this page?
    A: No. This page is read-only for IIS and app logs. If you need to clear logs, do so manually via the server file system or via the System Logs & DB Automation page for iDash-specific logs.

Tab 4 — Login Audit Trail

The Login Audit tab shows every sign-in attempt recorded by iDash. Events are logged on both successful and failed logins from the main index.aspx login handler.

KPI Cards

CardMetric
Logins TodaySuccessful logins since midnight
Failures TodayFailed login attempts since midnight
Unique Users (7d)Distinct usernames with successful logins in the last 7 days
Total EntriesTotal entries in the audit log file

Table Columns

Timestamp, Username, IP Address, Role, Result (OK / FAILED). Shows the last 100 entries, newest first.

Storage & Size Control

Stored in logs/login_audit.jsonl (JSON Lines). File is auto-trimmed at 90 days or 5,000 entries, keeping the file under ~500 KB.

The same data is also visible on the User Management page (va_user_management.aspx) in the Login History card.

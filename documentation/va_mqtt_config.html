⚡ Key Concepts

⚡ MQTTnet Embedded Broker (Print Only): AssetWorx has a built-in MQTTnet embedded broker running inside the IIS worker process (w3wp) on port 8883. This broker handles label printing only. You do NOT need to install a separate broker for printing.
🐇 Fixed Reader Tag Data (RabbitMQ): Tag observation routing from FX9600 readers uses a separate RabbitMQ 4.3.5 broker on port 1883 (TCP). This was deployed to address a routing defect in the AssetWorx embedded broker. See RabbitMQ Setup Guide for details.
⚠️ Important: The mqttclient table is NOT used for printing. Those are for subscribing to data feeds. Printing uses the printclient table exclusively.

🖨 Print Flow

End-to-end path of a label print job through the MQTT system:

  1. User triggers print from iDash (Asset Master, Excel Import, Scanning, etc.)
  2. AssetWorx Web App publishes a print job to the embedded MQTT broker (port 8883)
  3. The AssetWorx Print Server service subscribes to print topics and receives the job
  4. Print Server authenticates using its printclient credentials
  5. Print Server sends the label to BarTender which renders and sends to the physical printer
✅ All On-Premise: The entire print flow runs locally. No cloud services, no internet dependency. The embedded broker, Print Server, and BarTender all run on the same machine (LINGCOD).

🌐 Multi-Site Printing

The Problem

The AssetWorx installer only lets you enter one print client username per installation — meaning one Print Server install = one site. For a centralized server managing all VA sites, this is limiting.

The Solution: Master Print Client

A MasterPrint client was created in the printclient table and mapped to all 6 sites via the printclientcompany table. This allows a single Print Server instance to handle jobs from every site.

UsernameSites MappedMachine
MasterPrint 512 Baltimore, 517 Beckley, 540 Clarksburg, 581 Huntington, 613 Martinsburg, 688 Washington DC LINGCOD

💻 Print Server Installation

Prerequisites

  • AssetWorx Web Server running (provides embedded MQTT broker on port 8883)
  • BarTender installed and licensed (Print Engine or higher)
  • BarTender templates in the expected path
  • MQTT enabled in applicationsetting with all subscriptions checked

Installation Steps

  1. Run the installer — use the AssetWorx installer, select only Print Server component
  2. Configure credentials — enter MasterPrint / V5MqttPrint2026! as the print client
  3. Register the service — run the setup script in an elevated PowerShell: 
    & 'C:\inetpub\wwwroot\AssetWorx.WebClient\iDash\Assets\install_print_server.ps1'
  4. Verify — check Windows Services for "AssetWorx Print Server" (should be Running)
  5. Check logs — C:\Logs\PrintServer_log*.txt

📡 MQTT Client Management (Data Subscriptions)

The MQTT Client Management section on the iDash page handles mqttclient records. These are for subscribing to data feeds, not printing. Each site gets its own MQTT client with configurable access permissions:

  • Alarms — receive alarm notifications
  • Events — receive event messages
  • Gateway — receive gateway status messages
  • Tag Moves — receive tag movement notifications
  • Tag Observations — receive raw tag read data
  • Sensors — receive sensor reading data
💡 Tip: The "Create Client for Each Site" button auto-generates one MQTT client per company with all permissions enabled and a random password.

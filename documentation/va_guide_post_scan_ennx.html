📋 Post-Scan: ENNX Export & Email

Fill in the four filter fields as shown. All four are required for an accurate daily ENNX report.

📅 Step 5 — From Date

Enter today’s date (the date the room scans were performed). The format is mm/dd/yyyy. Leave To Date blank to cover the full day.

🏢 Step 6 — Site

Select 613 from the Site dropdown. This filters results to your facility’s assets only.

👤 Step 7 — User

Select your username from the User dropdown. Only users who have scan sessions for the selected date will appear in this list. If your name is missing, verify the scanner sync was completed.

✅ Step 8 — Tagged Items Only (Filter Option)

Check this box only if your team is actively conducting a tagging initiative and you strictly want to report on newly tagged items.
Leave unchecked if you are performing routine inventory sweeps or general location audits — leaving this blank ensures all scanned assets in the room are reported regardless of whether they were recently tagged.

Example of correctly filled-in filters: From Date = scan date, Site = 613, User = your username. (Leave “Tagged Items Only” unchecked when reporting on all scanned assets).

⚠ User not in dropdown? If your username does not appear in the User list, verify that the scan session was committed on the scanner. In iDash Inventory, tap Commit Scans while connected to the network, then reload this page.
9 Click “Build ENNX”
Click the Build ENNX button. The tool will query the database and populate the ENNX Text Preview box and the Data Details grid below it.

After clicking Build ENNX — the ENNX Text Preview fills in with location and asset IDs, and the Data Details table shows each asset with its current and previous location. Review to confirm the data looks correct.

💡 Review the data before emailing. Scan the Data Details grid to confirm assets and locations look as expected for today’s scan session. If something looks wrong, check your filter settings.

🔢 How the ENNX Trailer Total (***END***^N) is Calculated

At the very bottom of every generated ENNX file is a trailer line formatted as ***END***^N (e.g., ***END***^29). This number is an integrity checksum used during intake into VA Vista / AEMS-MERS and automated systems.

👤 For Users & Auditors: What N Means

N is the total count of content payload lines between the top ENNX header and the trailer line.

N = 1 (ID line) + (Location Headers) + (Scanned Asset Barcodes)

Example: A scan session covering 2 rooms with 15 assets:
• 1 (ID line) + 2 (Rooms) + 15 (Assets) = 18
• Trailer line: ***END***^18
Why it matters: Vista / AEMS-MERS checks this total against the parsed records upon import. If a record was truncated or dropped, Vista immediately halts the intake to prevent database corruption.

🖥️ For Developers: Calculation & Parsing Logic

Total lines in file = N + 2 (excluding only line 1 ENNX and the trailer line itself).

// C# Backend (va_ennx.aspx.cs / Runner)
int count = 1; // initialized to 1 for the 'ID' line
foreach (var grp in groups) {
  count++; // +1 for room/location header
  foreach (DataRow row in grp) {
    if (Clean(row["Name"]).Length > 0)
      count++; // +1 for each asset barcode
  }
}
sb.AppendLine("***END***^" + count);

Alternative Line Count: body.TrimEnd().Split('\n').Length - 1 (subtracts 1 for the ENNX header).
Parsers: Always skip lines starting with ***END*** when processing assets, and split on ^ to validate line count checksum.

ENNX File Line-by-Line Anatomy:
ENNX                       ← Line 1: Header keyword (always excluded from N)
ID                          ← Line 2: Prefix identifier [Count = 1]
SP-ROOM-101                 ← Line 3: Location header [+1]
512 EE18193                 ← Line 4: Asset barcode [+1]
512 EE18194                 ← Line 5: Asset barcode [+1]
SP-ROOM-102                 ← Line 6: Next location header [+1]
512 EE18200                 ← Line 7: Asset barcode [+1]
***END***^6                 ← Line 8: Trailer where N = 6 (1 ID + 2 locations + 3 assets)

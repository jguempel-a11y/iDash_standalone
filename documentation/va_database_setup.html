🛠 iDash Database Setup Guide

Rev. 2026-07-22 SQL Server Developer & Admin Reference

This is a hands-on, script-by-script guide for creating the iDash database from scratch. It covers every table, view, and index that iDash depends on — with copy-paste SQL scripts that a developer can execute directly in SQL Server Management Studio (SSMS).

💡 When to use this guide: You are deploying iDash to a brand-new server that has never had iDash installed and you do not have a .bak backup file to restore. If you DO have a backup, simply restore it via SSMS or va_db_restore.aspx — the database schema is already complete inside the backup.
Prerequisites 1. Create Database 2. Core Tables 3. Views 4. iDash-Only Tables 5. Seed Data 6. Staging DB 7. Verify Column Reference

Prerequisites

  • SQL Server 2016+ (or SQL Server Express — free edition works fine)
  • SQL Server Management Studio (SSMS) installed
  • A SQL login with dbcreator and sysadmin privileges (for initial setup only)
  • The iDash web.config connection string ready (see Deployment Guide)
⚠ Important: The iDash database was originally created by the iDash installer. The scripts below replicate the minimum schema that iDash requires to function. The full iDash product creates additional tables and stored procedures used by the .NET API and thick client. This guide gets iDash running — if you later install the full iDash product, it will add its own tables without conflicting with these.
1

Create the Database

Open SSMS, connect to your SQL Server instance, open a New Query window, and run:

-- =============================================
-- Step 1: Create the iDash database
-- Run this ONCE on a new server.
-- =============================================

IF DB_ID('iDash') IS NULL
BEGIN
    CREATE DATABASE [iDash];
    PRINT 'Database [iDash] created successfully.';
END
ELSE
    PRINT 'Database [iDash] already exists. Skipping.';
GO

Then create the SQL login that iDash will use:

-- Create the SQL login (change password for production!)
IF NOT EXISTS (SELECT 1 FROM sys.server_principals WHERE name = 'idashadmin')
BEGIN
    CREATE LOGIN [idashadmin]
        WITH PASSWORD = 'idashadmin',
        DEFAULT_DATABASE = [iDash],
        CHECK_POLICY = OFF;
END
GO

USE [iDash];
GO

-- Map login to database user with db_owner role
IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = 'idashadmin')
BEGIN
    CREATE USER [idashadmin] FOR LOGIN [idashadmin];
    ALTER ROLE db_owner ADD MEMBER [idashadmin];
END
GO

-- Grant server-level roles
-- sysadmin: required for Database Restore page (orphan fix + normalization after .bak restore)
-- bulkadmin: required for BCP/bulk data import operations
ALTER SERVER ROLE [sysadmin] ADD MEMBER [idashadmin];
ALTER SERVER ROLE [bulkadmin] ADD MEMBER [idashadmin];
GO
💡 Why sysadmin? When restoring a .bak backup from another server (e.g., a tagging cart), the idashadmin database user becomes "orphaned" (SID mismatch). The Database Restore page needs sysadmin to fix this orphan and run post-restore data normalization (creating companies, fixing companyid mappings, SP location prefixes, etc.). For SQL Express tagging systems: you can also grant this from a command prompt:
sqlcmd -S .\sqlexpress -E -Q "ALTER SERVER ROLE [sysadmin] ADD MEMBER [idashadmin]"
2

Create Core Tables

These are the foundational tables that the iDash system (and iDash) depends on. Run them in order — company first, then location, then asset, then sysuser.

2a. dbo.company — Site / Facility Registry

Each VA medical center is a "company" identified by its 3-digit station number prefix (e.g., 688 Washington DC).

USE [iDash];
GO

IF OBJECT_ID('dbo.company', 'U') IS NULL
BEGIN
    CREATE TABLE dbo.company (
        id          INT IDENTITY(1,1) PRIMARY KEY,
        name        NVARCHAR(255) NOT NULL,
        description NVARCHAR(500) NULL,
        created     DATETIMEOFFSET DEFAULT SYSDATETIMEOFFSET()
    );
    PRINT 'Created table: dbo.company';
END
GO

2b. dbo.location — EIL Location Registry

Each asset is assigned to an EIL (Equipment Inventory Listing) location. Location names look like SP688-BD. 7.

IF OBJECT_ID('dbo.location', 'U') IS NULL
BEGIN
    CREATE TABLE dbo.location (
        id          INT IDENTITY(1,1) PRIMARY KEY,
        name        NVARCHAR(255) NOT NULL,
        site        NVARCHAR(255) NULL,
        companyid   INT NOT NULL DEFAULT 0,
        description NVARCHAR(500) NULL,
        created     DATETIMEOFFSET DEFAULT SYSDATETIMEOFFSET()
    );
    CREATE NONCLUSTERED INDEX IX_location_name ON dbo.location(name);
    CREATE NONCLUSTERED INDEX IX_location_companyid ON dbo.location(companyid);
    PRINT 'Created table: dbo.location';
END
GO

2c. dbo.asset — The Master Asset Table

This is the single most important table in the system. Every RFID-tagged piece of VA equipment is a row here. The text1–text20 columns are customizable — in the VA deployment they map to specific field meanings (see the Column Reference below).

IF OBJECT_ID('dbo.asset', 'U') IS NULL
BEGIN

        id                      INT IDENTITY(1,1) PRIMARY KEY,

        rfidtag                 NVARCHAR(255) NULL,
        assettype               NVARCHAR(100) NULL,

        -- Foreign keys
        companyid               INT NOT NULL DEFAULT 0,
        locationid              INT NULL,

        text1                   NVARCHAR(500) NULL,   -- Manufacturer
        text2                   NVARCHAR(500) NULL,   -- Model
        text3                   NVARCHAR(500) NULL,   -- Serial Number (CDW)
        text4                   NVARCHAR(500) NULL,   -- Category
        text5                   NVARCHAR(500) NULL,   -- Service Pointer
        text6                   NVARCHAR(500) NULL,   -- Station+Location
        text7                   NVARCHAR(500) NULL,   -- Station Number
        text8                   NVARCHAR(500) NULL,   -- CMR Number
        text9                   NVARCHAR(500) NULL,   -- Purchase Order
        text10                  NVARCHAR(500) NULL,   -- Inventory Date
        text11                  NVARCHAR(500) NULL,
        text12                  NVARCHAR(500) NULL,
        text13                  NVARCHAR(500) NULL,
        text14                  NVARCHAR(500) NULL,
        text15                  NVARCHAR(500) NULL,

        text17                  NVARCHAR(500) NULL,

        -- List value fields (dropdowns)
        listvalue1              NVARCHAR(255) NULL,   -- Status (In Use / Not In Use)
        listvalue2              NVARCHAR(255) NULL,
        listvalue3              NVARCHAR(255) NULL,
        listvalue4              NVARCHAR(255) NULL,
        listvalue5              NVARCHAR(255) NULL,

        -- Date fields
        date1                   DATETIMEOFFSET NULL,

        date3                   DATETIMEOFFSET NULL,

        nextmaintenance         DATETIMEOFFSET NULL,

        maintenancemethod       INT NULL,
        maintenanceintervalmonths INT NULL,

        -- RFID / VTag hardware fields
        maxunseentime           INT NULL,
        nearestfixed            INT NULL,
        sensorreadinghistoryid  INT NULL,
        alertingactionid        INT NULL,
        sensorstatshistoryid    INT NULL,
        readerid                INT NULL,
        assetparentid           INT NULL,
        assetchildcount         INT NULL,
        vtagboxx                FLOAT NULL,

        vtagboxwidth            FLOAT NULL,
        vtagboxheight           FLOAT NULL,

        vtagalgorithmtype       INT NULL,
        batterylevel            INT NULL,

        vtagtype                INT NULL,
        parentvtag              INT NULL,

    PRINT 'Created table: dbo.asset';
END
GO

-- Performance indexes for iDash queries
CREATE NONCLUSTERED INDEX IX_asset_name ON dbo.asset(name);
CREATE NONCLUSTERED INDEX IX_asset_companyid ON dbo.asset(companyid);
CREATE NONCLUSTERED INDEX IX_asset_locationid ON dbo.asset(locationid);
CREATE NONCLUSTERED INDEX IX_asset_rfidtag ON dbo.asset(rfidtag);
CREATE NONCLUSTERED INDEX IX_asset_lastmodified ON dbo.asset(lastmodified);
CREATE NONCLUSTERED INDEX IX_asset_text8 ON dbo.asset(text8); -- CMR lookups
GO

2d. dbo.sysuser — iDash / RFID Scanner Users

Scanner operator accounts used by the RFID handheld devices and RFID mobile scanner. Managed via va_aw_user_management.aspx.

IF OBJECT_ID('dbo.sysuser', 'U') IS NULL
BEGIN
    CREATE TABLE dbo.sysuser (
        id                    INT IDENTITY(1,1) PRIMARY KEY,
        username              NVARCHAR(255) NOT NULL,
        password              NVARCHAR(500) NULL,
        firstname             NVARCHAR(255) NULL,
        lastname              NVARCHAR(255) NULL,
        email                 NVARCHAR(255) NULL,
        phone                 NVARCHAR(100) NULL,
        cardid                NVARCHAR(255) NULL,
        rfidtag               NVARCHAR(255) NULL,
        usertype              NVARCHAR(50) NULL,
        companyid             INT NULL,
        hideadminpopups       BIT DEFAULT 0,
        inventorylimiteduser  BIT DEFAULT 0,
        restricteditmobile    BIT DEFAULT 0,
        created               DATETIMEOFFSET DEFAULT SYSDATETIMEOFFSET()
    );
    CREATE UNIQUE NONCLUSTERED INDEX IX_sysuser_username ON dbo.sysuser(username);
    PRINT 'Created table: dbo.sysuser';
END
GO
3

Create Views

iDash reads from views rather than directly from the base tables in many reporting queries. This allows the iDash API to add computed columns without breaking iDash.

3a. dbo.v_asset — Asset View

Most iDash dashboards query v_asset instead of asset directly. This view joins the asset to its location and company for convenience.

IF OBJECT_ID('dbo.v_asset', 'V') IS NOT NULL
    DROP VIEW dbo.v_asset;
GO

CREATE VIEW dbo.v_asset AS
SELECT
    a.*,
    l.name     AS locationname,
    c.name     AS companyname
FROM dbo.asset a
LEFT JOIN dbo.location l ON a.locationid = l.id
LEFT JOIN dbo.company  c ON a.companyid  = c.id;
GO

PRINT 'Created view: dbo.v_asset';
GO

3b. dbo.v_sysuser — User View

Used by TagTeam Scan and Inventory to populate scanner operator dropdowns.

IF OBJECT_ID('dbo.v_sysuser', 'V') IS NOT NULL
    DROP VIEW dbo.v_sysuser;
GO

CREATE VIEW dbo.v_sysuser AS
SELECT
    u.*,
    c.name AS companyname
FROM dbo.sysuser u
LEFT JOIN dbo.company c ON u.companyid = c.id;
GO

PRINT 'Created view: dbo.v_sysuser';
GO

3c. dbo.v_locationhistory — Location History View

Used by the Previous Location page for asset movement tracking. This is a placeholder — the full iDash product populates a locationhistory base table that this view wraps.

IF OBJECT_ID('dbo.v_locationhistory', 'V') IS NOT NULL
    DROP VIEW dbo.v_locationhistory;
GO

-- Minimal stub: create the locationhistory table if it doesn't exist
IF OBJECT_ID('dbo.locationhistory', 'U') IS NULL
BEGIN
    CREATE TABLE dbo.locationhistory (
        id          INT IDENTITY(1,1) PRIMARY KEY,
        assetid     INT NOT NULL,
        locationid  INT NULL,
        readerid    INT NULL,
        timestamp   DATETIMEOFFSET DEFAULT SYSDATETIMEOFFSET()
    );
END
GO

CREATE VIEW dbo.v_locationhistory AS
SELECT
    lh.*,
    a.name   AS assetname,
    l.name   AS locationname
FROM dbo.locationhistory lh
LEFT JOIN dbo.asset    a ON lh.assetid    = a.id
LEFT JOIN dbo.location l ON lh.locationid = l.id;
GO

PRINT 'Created view: dbo.v_locationhistory';
GO
4

Create iDash-Only Tables

These tables are created by iDash itself and do not exist in the standard iDash schema. They support iDash-specific features.

4a. dbo.EnnxLiveSession — Live Scan Session Log

Records every live scanning session (ENNX Live, EIL Live). Queried by the daily cron job for automated reports.

IF OBJECT_ID('dbo.EnnxLiveSession', 'U') IS NULL
BEGIN
    CREATE TABLE dbo.EnnxLiveSession (
        Id            INT IDENTITY(1,1) PRIMARY KEY,
        Station       NVARCHAR(50) NULL,
        CreatedBy     NVARCHAR(255) NULL,
        StartedUtc    DATETIME2 NULL,
        EndedUtc      DATETIME2 NULL,
        Summary       NVARCHAR(MAX) NULL,
        JsonPayload   NVARCHAR(MAX) NULL,
        EnnxText      NVARCHAR(MAX) NULL,
        CreatedLocal  DATETIME2 DEFAULT GETDATE()
    );
    PRINT 'Created table: dbo.EnnxLiveSession';
END
GO

4b. dbo.AWPushStaging — Supply Chain Bridge Staging

Used by the VA FHIR Bridge (va_fhir_bridge.aspx) for staging asset data before pushing to VistA.

IF OBJECT_ID('dbo.AWPushStaging', 'U') IS NULL
BEGIN
    CREATE TABLE dbo.AWPushStaging (
        Id              INT IDENTITY(1,1) PRIMARY KEY,
        AssetName       NVARCHAR(255) NULL,
        Station         NVARCHAR(50) NULL,
        LocationName    NVARCHAR(255) NULL,
        PushStatus      NVARCHAR(50) DEFAULT 'Pending',
        CreatedUtc      DATETIME2 DEFAULT GETUTCDATE(),
        ProcessedUtc    DATETIME2 NULL,
        ErrorMessage    NVARCHAR(MAX) NULL
    );
    PRINT 'Created table: dbo.AWPushStaging';
END
GO
💡 Note: Two additional temporary tables (dbo.assettemp, dbo.locationtemp) are created and dropped dynamically by the Field Sync merge script. You do not need to create them manually. Similarly, dbo.AssetFileRaw is a temporary staging table created during database update imports.
5

Seed Initial Data

At minimum, you need one company record per VA site and one scanner user.

5a. Add Sites (Companies)

Add one row per VA medical center. The name must start with the 3-digit station number:

-- Add your VA sites (change station numbers and names!)
INSERT INTO dbo.company (name) VALUES
    ('688 Washington DC'),
    ('613 Martinsburg'),
    ('512 Baltimore'),
    ('460 Wilmington'),
    ('693 Wilkes-Barre'),
    ('595 Lebanon');
GO

PRINT 'Seeded company records.';
GO

5b. Add a Default Scanner User

-- Add a default scanner operator for field testing
INSERT INTO dbo.sysuser (username, password, firstname, lastname, usertype, companyid)
VALUES ('admin', NULL, 'Admin', 'User', 'Admin',
    (SELECT TOP 1 id FROM dbo.company));
GO

PRINT 'Seeded default sysuser.';
GO
✅ That's the minimum data needed. You can now import real asset data using iDash's built-in tools: the Manual DB Update (va_dbupdate.aspx) two-pass workflow, or by dropping a .bak file into the autoload directory for the Field Server Sync pipeline.
6

Create the Staging Database (Field Sync Only)

If you plan to use the Field Server Sync feature (va_field_sync.aspx), you need a staging database. The sync process restores a field server .bak file into this database, then merges it into the main iDash database.

IF DB_ID('idash_staging') IS NULL
BEGIN
    CREATE DATABASE [idash_staging];
    PRINT 'Created staging database: [idash_staging]';
END
GO

-- Grant the iDash login access to the staging DB
USE [idash_staging];
GO

IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = 'idashadmin')
BEGIN
    CREATE USER [idashadmin] FOR LOGIN [idashadmin];
    ALTER ROLE db_owner ADD MEMBER [idashadmin];
END
GO
💡 The staging database will be overwritten (via RESTORE DATABASE ... WITH REPLACE) every time a field sync runs. Its contents are ephemeral — it just needs to exist so the restore command has a target.
7

Verify the Setup

Run this verification script to confirm all required objects exist:

USE [iDash];
GO

SELECT 'Tables' AS Category, name, type_desc
FROM sys.objects
WHERE type = 'U' AND name IN (
    'asset', 'company', 'location', 'sysuser',
    'EnnxLiveSession', 'AWPushStaging', 'locationhistory'
)
UNION ALL
SELECT 'Views', name, type_desc
FROM sys.objects
WHERE type = 'V' AND name IN (
    'v_asset', 'v_sysuser', 'v_locationhistory'
)
ORDER BY Category, name;
GO

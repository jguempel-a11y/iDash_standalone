📤 Site Data Export & Import

Database Connected File Export File Import Admin Tool

Overview

Site Data Export & Import (va_sitedata_export.aspx) is a bidirectional data migration tool for iDash / AssetWorx. It lets you:

  • Export — pull a complete snapshot of one site's asset data to a tab-delimited (.txt) or CSV file.
  • Import — load a previously exported file back into the database on any other iDash server, with optional dry-run preview before committing.
This page is accessible only from the Admin & Database Tools section of the iDash Hub, which requires an admin login.

Why We Use This Tool

VA VISN sites occasionally need to share or migrate asset records between iDash installations. Common scenarios include:

  • New VISN server deployment — seed a fresh installation with data from the hub server.
  • Field server merge — export individual company (site/station) data before consolidating into a central database.
  • Data backup — create a flat-file audit trail of all asset records at a point in time.
  • Cross-site refresh — push corrected or enriched records back to a remote site without running a full DB script.

Export — How to Use

  1. Open va_sitedata_export.aspx from the Admin Tools tile on the Hub.
  2. Under Export Options, choose the Company / Site from the dropdown (populated from dbo.company). Select All Sites to export every asset.
  3. Optionally filter by Asset Status (In Use, Not In Use, Turned In, Disposed).
  4. Choose Export Format:
    • Tab-Delimited (.txt) — recommended. Safe for values containing commas/quotes. Matches the iDash import parser natively.
    • CSV (.csv) — RFC 4180 compliant. Use for Excel or analysis tools that don't support TSV.
  5. Select which columns to include (all 23 are checked by default). Use Clear All to start fresh.
  6. Click 📊 Preview (50 rows) — validates the query and shows a sample grid with a log.
  7. Click 📤 Export & Download — streams the full file to your browser.
    File name format: iDash_Export_[Site]_[YYYYMMDD-HHmm].[ext]

Import — How to Use

  1. Scroll to the 📥 Import Site Data File panel (or click the sidebar link).
  2. Click Choose File and select the previously exported .txt or .csv file. Format is auto-detected from the file extension.
  3. Select Target Company:
    • Use file's Company column — the importer reads the Company / Site Name column from each row and resolves it to a dbo.company ID. If a row's company name isn't found, that row's company ID defaults to 0.
    • Pick a specific company to override the file value — useful when importing from a different environment or correcting company assignments.
  4. Choose the On Conflict behaviour:
    • Update existing assets (recommended) — if an asset with the same name + company already exists, its fields are updated from the file.
    • Skip existing assets — only inserts rows where no matching asset exists. Existing records are left untouched.
  5. Click 📋 Dry Run (no changes) — scans every row, reports what would be inserted/updated/skipped, but writes nothing to the database. Always do a dry run first.
  6. Review the Import Results pills and log. Confirm the counts are as expected.
  7. Click 📥 Import to Database and confirm the prompt. The live import runs and writes directly to dbo.asset.
⚠ Important: The import operates as atomic set-based database statements. If a fatal database constraint violation occurs, the entire bulk statement will be rolled back. Always run a dry run first, and consider exporting a backup of the target site before a large import.

Why Tab-Delimited?

Asset names, descriptions, and location strings frequently contain commas and quotation marks. Tab-delimited files avoid quoting ambiguity that makes plain CSV unreliable for this data type. Tab-delimited is also trivially parsed in the import engine — values are split on \t with no escape-sequence logic.

The CSV option is available for Excel or analysis tools that can't consume TSV. The importer handles RFC 4180 quoting (double-quote escape) correctly in both directions.

Technical Operation

Export

Queries dbo.v_asset joined to dbo.company. Filter: WHERE companyid = @id (or no filter for all sites). All selected column expressions use ISNULL(..., '') so nulls export as empty strings. DateTime columns are formatted with CONVERT(varchar, col, 120) → yyyy-MM-dd HH:mm:ss.

Location Export & Dedicated Location Import

In addition to assets, clicking Export Locations Only exports all dbo.location rows for the selected site (including name, site, building, floor, room, description, rfidtag, lastinventoried, lastmodifiedby, and company). When a location export file is uploaded to the Import panel, the importer automatically recognizes it as a location file, performs a bulk UPSERT into dbo.location, and links all matching assets.

Import — Staging Table Bulk UPSERT

To avoid database round-trips and index scans associated with row-by-row parameterized loops, the importer uses a high-speed staging table workflow:

  1. It generates a dynamically constructed local temporary table #ai matching the columns in the imported file.
  2. It performs a single SqlBulkCopy operation to write all parsed rows into the temp table in one network round-trip.
  3. Location Auto-Provisioning: Before updating/inserting assets, any unique locations in #ai that do not yet exist in dbo.location for the target site are automatically provisioned with station and company IDs.
  4. It executes a single set-based UPDATE statement joining dbo.asset and #ai on matching name (Asset Tag) and companyid, linking locationid foreign keys directly to dbo.location.id.
  5. It executes a single set-based INSERT statement to write any assets in #ai that do not yet exist in dbo.asset, populating locationid foreign keys.
  6. Fallback Location Linking Pass: Automatically resolves and links any remaining unlinked asset foreign keys to dbo.location.

One-Click Location Repair: If an import was previously completed on a target system without locations, clicking Auto-Provision & Link Locations will immediately scan the existing assets, auto-create missing locations in dbo.location, and link locationid in seconds without re-uploading.

Company Resolution

When using Use file's Company column, the importer resolves company names to IDs via:

  1. Exact name match against dbo.company.name
  2. First-3-character prefix match (VA station number) — e.g. "581 Baltimore" matches any company starting with "581"
  3. Falls back to companyid = 0 if no match found

Security Notes

  • Page requires admin login (iDash session-based auth).
  • Export is read-only — no data is modified on the source server.
  • Import is write-capable — use dry run first and keep a backup.
  • The import engine uses SqlBulkCopy to upload raw data safely to a temporary staging table, executing match, insert, and update operations via structural set-based joins rather than dynamic SQL string concatenation, protecting against SQL injection.

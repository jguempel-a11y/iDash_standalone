Overview

The License Manager provides a single view of all iDash license-consuming registrations — readers, scanners (handheld devices), server registrations, scanner user accounts, and MQTT clients. It allows administrators to delete stale entries to free up license slots, particularly useful during testing when multiple handheld devices are connected and disconnected.

This page mirrors the functionality of the native iDash admin → Scanners page but also includes readers, servers, users, and MQTT clients in one consolidated view.

License Breakdown

iDash licenses are controlled by a license key stored in dbo.applicationsetting.licensekey. The key encodes several limits:

⚠ Important: The Readers limit is shared between fixed readers (e.g., FX9600) and handheld scanners. Each device that connects to iDash registers itself and consumes a slot. With 5 slots, 1 fixed reader + 4 handhelds = fully consumed.

Managed Sections

📡 Registered Readers

Database table: dbo.reader (child: dbo.antenna)

Fixed RFID readers registered in iDash. Each entry corresponds to a physical reader device (e.g., Zebra FX9600). Deleting a reader also removes its antenna records.

  • Displays: Name, Model, IP Address, Location, Last Seen, Status (Active/Stale)
  • Stale = not seen in >24 hours

🖥 Server Registrations

Database table: dbo.serverstatus

Services that register with iDash (AMS, Print Server, etc.). If a server is deleted here, it will re-register automatically on its next heartbeat if still running. Safe to delete stale entries.

📱 Scanners (Handheld Devices)

Database table: dbo.scanner

Handheld RFID scanner devices. These are the same entries shown in the native iDash admin → Scanners page. Each scanner consumes a reader license slot. Deleting stale/unused scanners is the primary way to free up slots for new devices during testing.

  • Displays: Device ID (hardware identifier), Site, Last Seen, Status
  • Stale = not seen in >30 days
  • The Device ID is a unique hardware fingerprint from the mobile device

👤 Scanner Users

Database table: dbo.sysuser

Mobile/handheld scanner user accounts used to log into the iDash mobile app. These are the same users managed via AW User Management.

🔌 MQTT Clients

Database table: dbo.mqttclient

MQTT client registrations for data subscriptions (tag movements, events, alarms, etc.). These are typically site-specific MQTT accounts used by services and integrations.

Common Workflow: Freeing License Slots

When you receive a "License limits exceeded" error while trying to use a new handheld scanner:

  1. Navigate to License Manager
  2. Check the Reader License Slots summary card at the top — it shows used / limit
  3. Scroll to Scanners (Handheld Devices)
  4. Identify stale scanners (shown with yellow "Stale" badge — not seen in 30+ days)
  5. Click Delete on the stale scanner(s) to free up slots
  6. Retry connecting the new handheld — it will register in the freed slot

Safety Notes

  • Server registrations auto-recover — deleting them is always safe if the server is still running
  • Readers do NOT auto-recover — deleting a fixed reader removes it permanently. Re-add via Reader Config
  • Scanners auto-recover when the handheld reconnects — safe to delete stale ones
  • Users are permanent deletes — the user account must be recreated
  • MQTT clients are permanent deletes — services using the deleted credentials will fail until recreated
⚠ Caution: Do not delete active readers or MQTT clients in production. Only delete entries you are certain are stale test devices.

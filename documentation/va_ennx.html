Module Purpose

Generates, previews, downloads, and emails ENNX text files for government system synchronization. Supports per-user, per-site, and date-range filtering to produce either individual technician payloads or a unified daily master file.

Technical Operation

The system renders the UI through va_ennx.aspx with a code-behind at va_ennx.aspx.cs. It queries dbo.asset directly (with a LEFT JOIN on dbo.location for location names) using parameterized ADO.NET commands. The Site and User dropdowns are populated dynamically on page load and on any date or site change, showing only records relevant to the selected time window.

Global Master Export (ALL USERS Bypass)

By default, the ENNX logic enforces strict user ownership mapping (matching LASTMODIFIEDBY) so technicians only generate payloads for assets they physically tagged.

The -- ALL USERS -- option at the top of the User dropdown bypasses this filter and queries across all technicians for the selected date range and site — enabling administrators to build a single unified daily master payload without manually stitching together individual files.

Date Ranges & Dynamic Dropdown Scoping

Date Ranges: Fill out both From Date and To Date to span multiple days. Leave To Date empty for a single-day report.

Dynamic Scoping (updated 2026-04-13): Changing either date field immediately triggers a postback that reloads both the Site and User dropdowns. Only sites and users that have actual scan activity within the specified date range are shown — the previous behavior of showing all activity from the last 30 days regardless of the date fields has been removed.

Site Filtration: Selecting a site further narrows the User dropdown to only technicians who scanned at that station in that period. The ENNX data query also applies the site filter at the database level.

OIT & No-Data Items in Excel Export

When the Include OIT & No-Data in Excel checkbox is checked (default: checked), the Excel export and email attachment include two additional sections after the main ENNX grid data:

Section Header Color What It Contains
⚠ OIT Items Scanned Yellow (#FFF3CD) Assets with CMR/EIL (text8) starting with 78. These belong to a different VA installation and are excluded from the ENNX text output but tracked here for awareness.
✖ No Data Items Red (#F8D7DA) Assets scanned but not found in the database (description = (Not Found in DB) or New Asset Found (Offline Sync)). Created as stubs by TagTeam Scan when scanning barcodes with no matching DB record.

Both sections query dbo.asset using the same date range and site filter as the main ENNX query. The ENNX text preview is not affected — these sections appear only in the Excel file. Uncheck the box to exclude them.

Preview Before Export

Two dedicated preview buttons allow the team to inspect OIT and No-Data items before generating the Excel file or emailing:

  • Show OIT Assets — Queries and displays all OIT items (CMR starting with 78) in a yellow-bordered preview panel. Shows asset name, description, CMR, location, tag date, and user for each item.
  • Show No Data Assets — Queries and displays all No-Data items in a red-bordered preview panel. Shows asset name, description, location, tag date, and user for each item.

Preview panels appear inline on the page when clicked and can be reviewed alongside the main ENNX text preview. The previews use the same date range and site filter as the main report.

Change Log

2026-07-01
  • Critical Fix: dbo.v_asset → dbo.asset — All four SQL queries (sites dropdown, users dropdown, CMR/EIL dropdown, and main ENNX data) were changed from querying the v_asset view to the asset table directly. The v_asset view uses INNER JOINs (on company, location, etc.) that filter out assets missing those foreign-key relationships. This caused assets marked as tagged in TagTeam Scan to not appear in the ENNX report. A LEFT JOIN dbo.location was added to the main query to preserve the location name column.
  • Bug Fix: AddWithValue parameter typing — The Run() helper method was creating properly-typed SqlParameter objects (e.g., SqlDbType.Date) and then discarding them by passing values through AddWithValue, which re-infers types. Changed to clone the original parameters with their explicit types preserved. Also fixed null handling: null values now send DBNull.Value instead of empty string (which caused date conversion errors).
  • Bug Fix: WITH(NOLOCK) removed — The main ENNX data query used WITH(NOLOCK) while the dropdown queries did not. Removed for consistency and to prevent potential issues on complex views.
  • New Feature: OIT & No-Data in Excel — New checkbox "Include OIT & No-Data in Excel" (defaults checked). When enabled, the Excel export and email attachment include two extra sections: OIT items (CMR starts with 78) in a yellow-highlighted table, and No-Data items (assets not found in DB when scanned) in a red-highlighted table. These are Excel-only and do not affect the ENNX text preview or download.
  • New Feature: OIT & No-Data Preview Buttons — Two new buttons (Show OIT Assets and Show No Data Assets) allow the team to preview these items inline on the page before generating the Excel report or emailing. Each opens a styled text preview panel showing asset name, description, CMR (for OIT), location, tag date, and user. Matches the same pattern used in TagTeam Scan.
  • Diagnostic: empty result messaging — When "Build ENNX" returns zero rows, the page now shows a clear diagnostic message with the exact filter values used (date, site, user) to help troubleshoot.
  • Connection string resilience — ConnStr now dynamically resolves the active connection string. Displays a clear error if the connection string is missing entirely.
2026-04-13
  • Site and User dropdowns now filter by the selected date range instead of a fixed 30-day lookback window.
  • TxtEnnxDate and TxtEnnxDateTo now have AutoPostBack="true" — changing either date immediately refreshes both dropdowns.
  • New GetDateRange() helper centralizes date parsing, defaulting to today when fields are blank.
  • New LoadSitesDropdown() method separates site loading from user loading for independent refreshes.
  • CMR/EIL dropdown also now scoped to the selected date range (was also previously hardcoded to −30 days).

📊 ENNX History Page — Updates 08/21/2026

  • 🌟 Redesigned Sticky Header

  • ⚠ Portability Fix
    Removed UserManager.FilterCompanyDropdown() dependency from va_prime_excel_tracking_sheet.aspx which caused a CS0117 compilation error when copied to systems where that method does not exist. Replaced with inline company filtering using GetAllowedCompanyIds().

Tagged vs. Not Tagged — Field Clarification

The Tagged status uses a.text18 = '1' across all ENNX and Asset Master reports. This is not the same as rfidtag. Any report or filter that needs to distinguish tagged assets must use text18.

🔑 iDash Software Licensing & Activation Guide

Architectural reference and step-by-step procedures for deploying, node-locking, and activating iDash on mobile RFID carts and regional VA servers.

1. Understanding the Two Licensing Systems in iDash

iDash manages two distinct categories of licenses. It is important to understand which license controls which layer of the platform:

License Type Target Layer Managed In Enforcement Mechanism
iDash Software License
(This Guide)		 The iDash Portal Web Application itself. Controls feature access, station authorization, multi-user limits, and installation node-locking. va_license_activation.aspx Native RSA-2048 Asymmetric Digital Signatures verified against Windows OS GUID & Ethernet MAC. Zero database dependency for initial gate.
AssetWorx Cart & Device License The underlying AssetWorx RFID Hardware Engine (Fixed readers, handheld scanner users, server registration). va_license_manager.aspx & cart_licenses.aspx Standard Base64 encrypted JSON keys stored in SQL Server table tblLicense.
💡 Dual-Tier Independence
A cart can have a valid AssetWorx database license for RFID readers while still requiring an iDash Software License to authorize the high-speed synchronization hub, reporting tools, and administrative dashboards.

2. Cryptographic Security & Air-Gap Principles

Because VA mobile carts and facility servers frequently operate in isolated subnets with zero internet or external network access, the licensing engine is built with strict air-gapped security:

  • Asymmetric RSA-2048 / SHA-256 Signatures: Licenses are signed using a private RSA cryptographic key kept strictly on the vendor/lead administrator's secure workstation. The corresponding Public Key is embedded inside LicenseManager.cs. It is mathematically impossible to forge a valid license even if someone has full read access to the iDash source code or IIS server.
  • Deterministic Node-Locking (Installation ID): Licenses are tied cryptographically to unique physical hardware identifiers (Primary Ethernet MAC address + Windows MachineGuid). A license issued for Cart 1 cannot be copied or transferred to Cart 2.
  • Anti-Tampering & Clock Rollback Protection: The system continuously tracks a monotonic UTC timestamp in App_Data/idash_clock_state.dat. If an operator attempts to bypass an expiration date by manually rolling back the Windows BIOS or OS clock, iDash detects the discrepancy and suspends access.
  • Dual-Persistence Redundancy: Once applied, the validated license envelope is stored on disk in App_Data/idash_license.json and automatically synchronized to SQL Server (dbo.idash_license). If a cart's web folder is re-deployed, the license is restored automatically from the database.

3. Step-by-Step Implementation: New Mobile RFID Cart (Air-Gapped)

Follow these steps when provisioning a brand-new VA mobile cart (e.g. Beckley Cart 3) that has no internet connection:

1

Deploy iDash Files & Launch Activation Portal

Deploy the standard iDash web client package to C:\inetpub\wwwroot\AssetWorx.WebClient\iDash. Open a web browser on the cart and navigate to:

http://localhost/idash/va_license_activation.aspx

The page will display the current status as ● Not Licensed and present the System Hardware Identity card.

2

Retrieve the Cart's Installation ID

Under the System Hardware Identity section, locate the Installation ID (e.g., IDASH-517-0464-FAFE-80C6-A12B). Click the 📋 Copy ID button to copy it to the clipboard.

# Example Installation ID: IDASH-517-0464-FAFE-80C6-A12B

Send this Installation ID to the software administrator or licensing authority via email, ticket, or encrypted USB.

3

Generate Signed License Key on Admin Workstation

On the secure administrator PC (where the private signing key resides in tools/idash_keys/idash_private_key.xml), open PowerShell in the tools/ directory and execute New-IdashLicense.ps1:

.\New-IdashLicense.ps1 ` -InstallationId "IDASH-517-0464-FAFE-80C6-A12B" ` -Customer "Veterans Health Administration" ` -SiteName "517 Beckley VAMC" ` -StationNumber "517" ` -Perpetual ` -OutputFile "beckley_cart3.idashlic"

This script outputs two formats:

  • A .idashlic file: Ready to transfer to the cart via USB or secure network share.
  • A Base64 Key String: (e.g., IDASH-LIC-v1-eyJhbGci...) ready to copy/paste directly.
4

Apply the License on the Cart

Choose either of the following methods to apply the license to the cart:

Method A: Via the Web Activation Portal (Recommended for Clinicians/Admins):

  • Return to http://localhost/idash/va_license_activation.aspx on the cart.
  • Select the 💾 Offline / Air-Gapped Key tab.
  • Either drag and drop the beckley_cart3.idashlic file into the file upload box, OR paste the IDASH-LIC-v1-... string into the text box.
  • Click 🔑 Apply License Key.

Method B: Automated CLI / Scripted Deployment (For IT Deployment Engineers):

Run the automated silent installer script directly from an administrative PowerShell terminal:

.\tools\Apply-IdashLicense.ps1 -LicenseFile ".\tools\beckley_cart3.idashlic"
5

Verification & Access Confirmation

Once applied, the page immediately updates:

  • Status badge turns to ✓ Active (Perpetual).
  • Facility Name, Station Number (517), and authorized modules are confirmed.
  • The license is cryptographically verified on every request with zero performance overhead (< 2 milliseconds via in-memory caching).
  • Click ⌂ Launch iDash Hub to access all application features.

4. Step-by-Step Implementation: Regional & Enterprise Dashboard Servers

For enterprise regional dashboard installations or central healthcare facility servers running under IIS (across any VISN or private healthcare institution):

A

Enterprise Feature & Seat Provisioning

When generating licenses for central regional or facility servers, specify the multi-user concurrent limit and expiration window if using a yearly renewal contract:

.\New-IdashLicense.ps1 ` -InstallationId "IDASH-ENTERPRISE-SERVER-GUID-xxxx" ` -Customer "Veterans Health Administration" ` -SiteName "Regional Healthcare Asset Hub" ` -StationNumber "REGIONAL" ` -ExpirationDate "2027-09-30" ` -MaxUsers 250 ` -OutputFile "enterprise_hub.idashlic"
B

Online Cloud / Intranet Product Key Activation

If the central server has network access to an enterprise licensing endpoint:

  • Go to the 🌐 Online Product Key tab on va_license_activation.aspx.
  • Enter the facility product key (e.g., IDASH-ENT-2026-ACT1).
  • Click Connect & Activate Online.
  • The server connects to the licensing authority, securely exchanges the hardware fingerprint, downloads the signed token, and caches it locally. Even if the network later goes down, the server continues operating without interruption.

5. Gating-Before-Use: Enforcing Mandatory Pre-Activation Lockout

To ensure that nobody can use any feature of iDash until a license key has been successfully applied, iDash includes an integrated IIS HTTP module:

<!-- In web.config under <system.webServer><modules> --> <add name="IdashLicenseModule" type="IdashLicenseModule" />

When this module is active:

  • Any user attempting to browse to index.aspx, va_sitedata_export.aspx, or any other page is automatically intercepted.
  • The request is immediately redirected to va_license_activation.aspx?reason=unlicensed.
  • Only the activation screen and core branding assets (CSS, images) can be viewed until a cryptographically valid license is submitted.

6. Frequently Asked Questions & Troubleshooting

What happens if a cart's motherboard or network card is replaced?

Because the license is node-locked to the hardware MAC and Windows Machine GUID, swapping a motherboard will trigger a Machine Mismatch warning. Simply open va_license_activation.aspx, copy the new Installation ID, and issue an updated license key using the admin generator script.

What happens if the SQL database is backed up and restored to a different cart?

The licensing engine validates hardware integrity on every startup. If a database from Cart 1 is restored onto Cart 2, the engine detects that the hardware fingerprint does not match the database license, falls back to the local file, or prompts for Cart 2's specific license. This prevents unauthorized database duplication across non-licensed carts.

Where are license keys stored?

Location File / Table Purpose
Disk Storage App_Data/idash_license.json Primary high-speed local cache for air-gapped startup.
Database Backup SQL Server dbo.idash_license Automatic secondary store that survives web directory re-installations.
Private Signing Key tools/idash_keys/idash_private_key.xml STRICTLY VENDOR/ADMIN ONLY. Never deployed to carts or public servers.

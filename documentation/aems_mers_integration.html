🔁 AEMS-MERS & VistA Integration Strategy

This document outlines the ID Integration Inc. approach to bridging the gap between AssetWorx/Dashboard and the VA's primary systems of record: AEMS-MERS and VistA.

Strategic Context: Modern VA logistics require a bi-directional flow of data. Dashboard serves as the "Live Edge" of inventory scanning and RTLS tracking, while AEMS-MERS serves as the "Financial Core" and compliance record.

Interface Architecture

Our approach utilizes a RESTful middleware architecture to facilitate secure, authenticated communication between the Dashboard SQL environment and the VistA MUMPS database. This follows the Enterprise Systems Engineering (ESE) pattern for VA system interactions.

[ AssetWorx / Dashboard ] <--> [ Dashboard Integration Service ] <--> [ VistA Service API ] <--> [ VistA / AEMS-MERS ]

Key Integration Components

  • Dashboard Integration Service (IIS): A dedicated worker process that orchestrates data synchronization, mapping RTLS events to VistA updates.
  • VistA Service API: A RESTful wrapper around VistA Remote Procedure Calls (RPCs), allowing modern JSON/XML communication with the legacy MUMPS environment.
  • Bidirectional Synchronization: Continuous polling for asset updates from VistA and real-time pushing of inventory/location events from Dashboard.

Data Mapping & Logic

To maintain data integrity, we utilize a standardized mapping of fields between the two systems. The EE Number (Equipment Entry Number) serves as the primary unique identifier.

1. Inbound to Dashboard (AEMS → Dashboard)

Asset details are imported into Dashboard to ensure users see up-to-date descriptions, serial numbers, and ownership data.

2. Outbound to AEMS (Dashboard → AEMS)

Critical updates are pushed to AEMS whenever a physical inventory occurs or an asset moves location.

Event TypeAction / RPCResult
Location Move VIAA ENG ASSET MOVE Updates the ROOM NUMBER and DATE ENTERED LOCATION in VistA.
Physical Inventory VIAA ENG ASSET MOVE Updates the PHYSICAL INVENTORY DATE for audit compliance.

Location & Space Mapping

A central challenge in RTLS is mapping physical sensor zones to administrative rooms defined in the VistA Space File (#6928).

Mapping Methodology

We implement a One-to-Many mapping system using the esf-room-number key. This allows Dashboard to track assets at a higher resolution (e.g., specific hallway segments) while still reporting to the correct administrative room in VistA.

// Example: Mapping three RTLS locations to a single VistA Room
RTLS Location: 506-A101-ZoneA  --> VistA: 506 1A101|1
RTLS Location: 506-A101-ZoneB  --> VistA: 506 1A101|2
RTLS Location: 506-A101-ZoneC  --> VistA: 506 1A101|3

// The "|" suffix is stripped during the AEMS push to match VistA Room "1A101"
Data Integrity Guard: If a location move is detected in Dashboard but the target room does not exist in the VistA Space File, the update is logged in the Exception Report and suppressed until corrected by a Space Manager.

Implementation & Deployment

The ID Integration approach to deployment follows a phased "Scan-First" methodology.

Phase 1: Database Baseline

Perform an initial bulk export of AEMS-MERS assets via SQLCMD or BCP extraction. Import this into the AssetWorx SQL database to seed the system.

Phase 2: API Integration

Configure the Dashboard Integration Service with appropriate OIT-provided credentials and firewall ACLs. Verify connectivity to the VistaService REST endpoints.

Phase 3: Active Synchronization

Enable automated inventory date updates. As staff scan assets via Dashboard Tag Team Scan, the system automatically triggers the VIAA ENG ASSET MOVE RPC to satisfy the physical inventory requirement in AEMS-MERS.

Security & Compliance

  • Authentication: All API calls utilize VistALink or OIT-approved Web Service credentials.
  • No Database Direct Writes: We never write directly to the VistA SQL/MUMPS database. All updates MUST go through approved RPCs to ensure business logic and audit trails are preserved.
  • Audit Logging: Every outbound transaction is logged in the Dashboard App_Data/logs folder, capturing the EE Number, target Room, and VistA response code.

📤 ENNX Live Scan

Database Connected Disk / Email / SQL Export Updated 09/09/2026

The ENNX Live Scan module is a real-time, site-scoped asset scanning tool for generating ENNX submission files. Unlike the EIL Live Scan (which reconciles against a predefined CMR parts list), this tool operates in open-capture mode — any asset barcode scanned during a session is accepted, catalogued, and accumulated into a government-ready ENNX payload. It is the primary field tool for general inventory sweeps where the full scope of equipment in a location is not known in advance.

Why WebSerial?

Traditional barcode/RFID scanning in a browser requires a middleware layer (DataWedge, COM-port relay app, or a native mobile app) to translate serial data into keyboard events. WebSerial eliminates that middleware by letting the browser talk directly to the USB serial port. This means:

  • No extra software: No DataWedge profile, no COM-port relay, no native app installation.
  • Any USB serial device: Works with any reader that outputs newline-terminated data over a serial/USB-serial connection.
  • Zero configuration: The browser prompts the user to select their serial port — no driver setup, no port number guessing.
  • Same scan pipeline: Data from the serial port flows through the exact same handleScan() function, so all location detection, EPC filtering, de-dupe logic, and ENNX assembly apply automatically.

How WebSerial Works (Technical Flow)

  1. User clicks "Select/Open Serial Port" inside the collapsible WebSerial panel.
  2. The browser displays its native serial port picker dialog (a security requirement — no port is accessed without explicit user interaction).
  3. Once a port is selected, JavaScript opens it with the parameters below and starts an asynchronous read loop.
  4. Incoming bytes are decoded as UTF-8 and appended to a line buffer. When a newline (\n) is detected, the complete line is trimmed and passed to handleScan().
  5. The scan is processed identically to a keyboard scan — location detection, EPC filtering, de-dupe, and ENNX assembly all apply.
  6. The serial connection stays open until the user clicks "Close Port" or navigates away from the page.

Step-by-Step User Workflow

1
Select Site (Station): Choose the VA facility from the Site dropdown. The station code (e.g., 512) is embedded in every normalized asset line (e.g., 512 EE18193) and in the exported ENNX filename.
2
Optional: Enable EIL Filter: Check "Scan by EIL" and select a CMR from the dropdown. Assets scanned during the session will be verified against the selected EIL via an AJAX call to CheckAssetEIL. Mismatches are logged with a WARN note but not added to the ENNX payload.
3
Scan a Location Barcode: The first scan must be a location. If the barcode starts with SP, it is automatically detected as a location and starts a new block. If not, use the "Force Next = Location" button to treat the next scan as a location.
4
Scan Asset Barcodes: All subsequent scans are treated as assets under the current location. Each asset is normalized (e.g., EE18193 becomes 512 EE18193), de-duplicated (if enabled), and appended to the ENNX preview. Raw EPC hex reads are silently filtered out.
5
Repeat: Scan the next location barcode to start a new block. Continue scanning assets. The scan log shows a timestamped record of every action with color-coded status notes (OK, WARN, ERR).
6
Export the ENNX File: When ready, choose an output method:
  • Download ENNX: Streams the file directly to your browser.
  • Email ENNX: Sends as a UTF-8 attachment via the EmailHelper SMTP service.
  • Save Session (SQL): Commits session data to the EnnxLiveSession table with UTC timestamps.
  • Save ENNX File (Disk): Writes to C:\VA_RFID\ennx_live\saved\ on the server.
ℹ Mobile Ready: This module uses a responsive flexbox layout with full viewport scaling. It operates identically on desktop browsers and Zebra handheld scanners. No separate mobile app or APK is required.

Scan Processing Logic

All scan processing is handled client-side in a single handleScan() function. The same function is used for both keyboard/DataWedge input and WebSerial input.

StepLogic
1. CleanTrim whitespace, normalize to single spaces, uppercase.
2. EPC FilterIf the value is 12+ hex characters with trailing Fs (raw EPC read), silently ignore it.
3. Location CheckIf forceLoc is true, or if "Auto switch" is enabled and the scan starts with SP, treat it as a location. Start a new block.
4. Normalize AssetMatch patterns like 512 EE18193, EE18193, 512EE18193. Prepend the station code if missing. Return null for unrecognized formats.
5. EIL Filter (Optional)If "Scan by EIL" is enabled, make an AJAX call to CheckAssetEIL. Skip assets that don't match the selected EIL.
6. De-dupeIf enabled, check the current block's assetSet hash. Skip duplicates with a WARN log.
7. AddAppend to the current block's assets[] array. Update KPIs and ENNX preview.

Technical Architecture

The scan session state is maintained entirely in client-side JavaScript — a blocks[] array where each block contains a location string and an array of normalized asset lines. On export, the C# code-behind receives the compiled ENNX text and JSON session summary via hidden fields, then performs the selected export action (download, email, SQL save, or disk save).

ENNX File Format

The output is a line-delimited .ennx.txt file with the following structure: 

ENNX
ID
SP101-1
512 EE18193
512 EE29472
SP102-3
512 EE11037
***END***^5

The ^N suffix on the ***END*** line is the total count of location + asset lines (excluding the ENNX, ID, and ***END*** lines themselves).

Access & Security

Users must have the scan_ennx tile key granted in their iDash TileAccess profile to access this module. See User Management for details.

All database queries are fully parameterized via ADO.NET SqlParameter. Barcode input is validated server-side before any SQL is executed. No raw database errors are exposed to the user interface.

The WebSerial feature requires explicit user interaction to grant the browser permission to access a serial port. No serial ports are accessed automatically. The browser's built-in permission prompt is displayed each time a port is selected, and the permission does not persist across sessions.

🗺 System Topology: 4-Tier Zero-Footprint Model

iDash functions strictly as an enterprise web intelligence and presentation layer. It introduces zero workstation binaries, eliminates heavy client push cycles, and communicates with the underlying data store via non-blocking queries and decoupled service buses.

1. User Management, RBAC & Zero-Trust Authentication

iDash employs an independent, zero-trust authentication boundary that protects the application without requiring domain join or Active Directory schema modifications. It also provides bi-directional user account provisioning into the underlying AssetWorx database.

Component / FileArchitecture & Operational Details
User Registry
iDash/App_Data/idash_users.json		 Primary store for all iDash portal users. Contains SHA256 hashed passwords, assigned roles (admin, user, readonly), user display names, last login timestamps, and accepted digital user agreements.
Granular RBAC Fields:
  • SiteAccess: Multi-tenant facility scoping dictionary (e.g. {"517 Beckley": "full"} or {"*": "full"}). Users are strictly partitioned to their assigned facility.
  • TileAccess: Array of permitted operational tiles (e.g. ["rpt_asset_master", "scan_inventory"]). Any unlisted tile is completely hidden and inaccessible.
Digital User Agreement Gate
va_login.aspx • UserManager.cs		 Enforces mandatory VA/federal computer system warning and digital terms sign-off prior to accessing operational tools. The sign-off timestamp is committed to AgreementAcceptedDate in idash_users.json, establishing full legal and audit defensibility.
AssetWorx User Sync Engine
va_user_management.aspx.cs → CreateAwUserInternal()		 When creating or updating accounts in iDash, selecting "Also create AssetWorx account" performs a direct cryptographic insert into dbo.sysuser using .NET Identity V3 SHA256 password hashing (PRF=1, 10,000 iterations). This allows administrators to provision handheld scanner logins and web portal logins from a single interface.
Quick Role Templates
iDash/App_Data/user_templates.json		 Defines role templates (e.g. "VA Standard User", "Tag Team Operator", "System Administrator") allowing one-click assignment of predefined tile sets and facility scopes during user provisioning.

2. Dual-Engine Printing & RFID Encoding Architecture

The iDash printing subsystem integrates native AssetWorx Print Server automation with direct BarTender REST capabilities. This dual-path architecture provides automated failover, label preview, and high-speed batch encoding.

Subsystem LayerTechnical Implementation & Routing Logic
AssetWorx Print Server API
App_Code/AssetWorxApiHelper.cs		 Communicates with the local AssetWorx Core Print Server via authenticated REST endpoints (GetApiBase() → /api/PrintJobs, /api/PrintTemplates).
Auto-Site Resolution: Resolves company ID to matching print templates (e.g. template ID 19 for Beckley 517) and enqueues print jobs directly into the native print engine pipeline.
BarTender Preview Microservice
printing/Run_Preview_Service.ps1
App_Code/BarTenderApiHelper.cs		 A high-performance background preview microservice running on http://localhost:5180. When users click Preview Tag in `va_excel_print.aspx` or `va_location_list.aspx`, the service opens the corresponding BarTender template (.btw), applies sample asset data, renders an ultra-crisp base64 PNG, and serves it directly to the browser modal.
Template & Printer Mappings
iDash/print_mapping_config.json
va_print_mapping.aspx		 Maintains tag-type-to-template relationships (e.g. IQ350 → AW_Std_Small.btw, Large_Metal → AW_Metal_Asset.btw) and binds target network thermal printers (Zebra ZT411, SATO) per facility site.
Interactive Location Printing
va_location_list.aspx → SubmitPrintJobs()		 Enables operators to select any subset of assets from location manifests or age-filter buckets, choose an approved site template, and dispatch multi-tag print batches with instant visual progress badges.

iDash implements consumer-grade client responsiveness while maintaining enterprise state synchronization across sessions.

Allows operators to customize visible fields (Description, Model, Serial #, Manufacturer, RFID Tag, Location, CMR, Tag Type, Status, Days Since, Last Inv) with instant presets (Default, Show All, Compact) and zero page reloads.

In-Memory DOM Only (Session Scoped)		 Used by va_rfid_locator.aspx. Proximity RSSI signal history, found/unfound counters, and Web Audio Geiger tones exist strictly in browser memory and purge on navigation, preserving zero forensic traces on shared mobile devices.

4. Database Concurrency: Non-Blocking Read Isolation

A core engineering priority of iDash is preventing contention on the primary AssetWorx SQL Server transaction log.

Read-Uncommitted Isolation Policy: All heavy analytical and reporting queries executed by iDash explicitly declare:
SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
This guarantees that massive location summaries, CMR age-bucket aggregates, and catalog searches execute with zero shared-read locks, completely preventing table deadlocks with handheld scanner syncs or AssetWorx Core transactions.
SQL Table / ViewAccess Mode & iDash Functional Role
dbo.v_asset Read-Only • Primary reporting view used by `va_asset_master.aspx`, `va_location_list.aspx`, and `va_asset_stats.aspx`. Evaluates lastinventoried, text8 (CMR), text2 (Model), text3 (Serial), and locationname.
dbo.asset Read / Write • Updated during Excel equipment onboarding (`va_excel_print.aspx`), batch database updates (`va_dbupdate.aspx`), and direct barcode edit drawers.
dbo.printjob Read / Write • Standard queue table for print job submissions. Monitored by the background dispatchers and updated with completion status codes.
dbo.sysuser Read / Write • Manages handheld and administrative accounts. Controlled via `va_user_management.aspx`.
dbo.company Read-Only • Master site table mapping company IDs to facility names (e.g. 7 → "613 Martinsburg").

5. Scheduled Automations & Background Services

To avoid ASP.NET worker process idle timeouts, recurring enterprise workloads are decoupled into OS-level background processes and scheduled tasks.

Task / ServiceTrigger & Functional Scope
Daily Report Automator
AutoReportRunner.ps1		 Triggered daily at 7:00 PM via Windows Task Scheduler. Invokes va_report_automator_runner.aspx to compile daily scan summaries, format Excel/text payloads, and dispatch them via SMTP to facility logistics officers. Configuration managed via iDash/config/report_automation.json.
BarTender Preview Daemon
Run_Preview_Service.ps1		 Runs continuously as a background service listening on port 5180. Interfaces with BarTender Print SDK to generate live label renderings without spinning up heavy desktop GUI instances.
Database Autoload Watcher
va_autodbupdate.aspx		 Periodically inspects the /autoload/ drop folder for differential .bak or .sql extracts from remote regional sites, executing automated database merges.

6. File System Topology & Diagnostics

File-based artifacts are strictly partitioned into predictable server directories for straightforward backup, migration, and diagnostic analysis.

Directory PathContent Type & Lifecycle
C:\VA_RFID\ennx_live\saved\ Historical text exports of ENNX inventory submissions generated by users and automated reporting runners.
C:\va_rfid\excel_data\ Default repository for master equipment spreadsheets processed by the Excel Import & Print engine.
C:\Logs\WebClient_log*.txt Diagnostic application logs written by Serilog. Captures API response timings, authentication failures, and SQL exceptions; viewable in real-time via `va_log_viewer.aspx`.
iDash\App_Data\uploads\ Ephemeral storage for browser-uploaded import spreadsheets with automatic session cleanup.

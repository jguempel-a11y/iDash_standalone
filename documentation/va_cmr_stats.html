📋 CMR Progress Report (va_cmr_stats.aspx)

The CMR Progress Report is the primary accountability and turnover tracking tool for the VA's Consolidated Memorandum Receipt (CMR) system. It answers in real time the questions every supply tech, service chief, and administrator needs during a leadership transition: how many assets are in my CMR, how many have been found today, who scanned them, and where are they?

✅ This page is data-driven directly from the AssetWorx database.
Every number, percentage, name, and location you see on this page is pulled live from dbo.v_asset at the moment you load or refresh it. There is no cache, no staging table, and no intermediate report file. What you see is exactly what is in the database right now.

1. What Is a CMR?

A CMR (Consolidated Memorandum Receipt) is a formal VA accountability document that assigns a group of government equipment to a specific service chief, department head, or responsible custodian. The holder is legally accountable for every asset listed. In AssetWorx, the CMR number is stored in the text8 field on each asset record — all assets with the same text8 value belong to the same CMR group.

ⓘ Why Turnover Is a High-Stakes Event
When a CMR holder changes roles, retires, or transfers, every asset on the CMR must be physically located and verified before the outgoing person is cleared. Supply technicians have a limited window — often tied to the size of the CMR — to complete this scan. Without a real-time progress view they are working blind: no idea how many are left, who scanned what, or where they last saw it. This page eliminates that blindness.

2. Filters and Controls

⚠ Technical Note — Date Comparison
Because AssetWorx stores lastinventoried as datetimeoffset (which includes a UTC offset that can vary by device), the filter uses CONVERT(date, lastinventoried) ≥ @ScanFrom with an explicit SqlDbType.Date parameter. This matches only the calendar date portion and correctly handles mixed timezones (e.g., records stored as +00:00 UTC and −07:00 Mountain) without double-counting or missing records.

CMR Search — Single or Multiple

The search box filters which CMR groups are shown in the table and included in the KPI totals. It supports two modes:

✅ All parameters are fully parameterized.
User input is never concatenated directly into SQL. The comma-split list generates individual named parameters (@CmrVal0, @CmrVal1, etc.) which SQL Server binds safely. This completely prevents SQL injection regardless of input.

5. Turnover Workflow — Step by Step

  • Step 1 — Baseline: Before scanning begins, select the correct site, choose All Time, search for the CMR(s) being transferred (comma-separated if multiple), and click Export CMR Summary. This is the full accountability list.
  • Step 2 — Switch to Today: As scanning begins on the day of turnover, switch to Today. The Found count and progress bars update instantly on each page refresh after new scans are submitted.
  • Step 3 — Monitor in real time: The Scanners column shows who is actively working. The Last Location column shows where they were last. Refresh after each ENNX batch submission to see the latest counts.
  • Step 4 — Identify gaps: CMRs showing Not Started or very low % need immediate attention. Cross-reference with the ENNX Report filtered to the same CMR and date for detailed scan logs.
  • Step 5 — Multi-CMR view: If a service chief holds multiple CMRs, type all the CMR numbers comma-separated in the search box. The KPI cards will summarize the combined accountability across all of them.
  • Step 6 — Export and email: Use Export CMR Summary for the per-CMR rollup, or Export Asset Detail for a row-per-asset list with a Yes/No Scanned column. The Email Report button attaches the summary CSV and sends it to configured recipients.
  • Step 7 — Final sign-off: When all CMRs show ✓ Complete, export one final copy as the formal record before the new holder signs.

Core SQL Pattern (Scan Window + Multi-Scanners)

-- @ScanFrom is passed as SqlDbType.Date to avoid datetimeoffset timezone issues
-- CONVERT(date, lastinventoried) strips the time/offset component safely

SELECT
    a.text8                                                     AS CMR,
    COUNT(*)                                                    AS TotalAssets,
    SUM(CASE WHEN CONVERT(date, a.lastinventoried) >= @ScanFrom
             THEN 1 ELSE 0 END)                                 AS ScannedCount,
    MAX(a.lastinventoried)                                      AS LastScanDate,

    -- All distinct users who scanned assets in this CMR in the window
    STUFF((SELECT DISTINCT ', ' + LOWER(LTRIM(RTRIM(v2.lastmodifiedby)))
           FROM dbo.v_asset v2
           WHERE v2.text8 = a.text8
             AND NULLIF(RTRIM(v2.lastmodifiedby), '') IS NOT NULL
             AND CONVERT(date, v2.lastinventoried) >= @ScanFrom
           FOR XML PATH('')), 1, 2, '')                         AS Scanners,

    -- Most recent scan location within the window
    (SELECT TOP 1 v2.locationname
     FROM dbo.v_asset v2
     WHERE v2.text8 = a.text8
       AND CONVERT(date, v2.lastinventoried) >= @ScanFrom
     ORDER BY v2.lastinventoried DESC)                          AS LastLocation

FROM dbo.v_asset a
WHERE NULLIF(RTRIM(a.text8), '') IS NOT NULL
  AND (@CId = 0 OR a.companyid = @CId)
  AND ( /* GetCmrFilter result injected here */
        a.text8 LIKE '%' + @CmrSearch + '%'         -- single value
        -- OR --
        LTRIM(RTRIM(a.text8)) IN (@CmrVal0, ...)    -- comma list
      )
GROUP BY a.text8
ORDER BY ScannedCount * 1.0 / COUNT(*) DESC, ...

CMR Filter Logic (C# GetCmrFilter method)

The search box content is parsed server-side before the SQL command is built. If the text contains a comma, it is split into individual values — each gets its own named parameter (@CmrVal0, @CmrVal1, ...) and the WHERE clause uses IN (...) for exact matching. If no comma is present, a single LIKE '%value%' clause is used for partial matching. If the box is empty, the filter is 1=1 (no restriction). In all cases, user input is bound as a SQL parameter — never concatenated into the query string directly.

Why CONVERT(date, ...) Instead of ≥ DateTime

AssetWorx devices may store lastinventoried with different UTC offset values depending on the device timezone. Comparing lastinventoried ≥ @ScanFrom with a plain DateTime parameter causes SQL Server to implicitly convert DateTime as UTC (+00:00), which can make scans stored with a negative offset appear to fall on the wrong calendar day. Using CONVERT(date, lastinventoried) extracts only the calendar date from the stored value (preserving its local offset context) and comparing that against a SqlDbType.Date parameter eliminates all timezone ambiguity. This matches the pattern proven by the ENNX report which correctly counts scans regardless of device timezone.

📋 CMR Progress Report (va_cmr_stats.aspx)

The CMR Progress Report is an accountability and turnover tracking tool designed around the VA's CMR (Consolidated Memorandum Receipt) system. It answers the core questions a service chief, supply tech, or administrator needs during a leadership transition: how many assets are in my CMR, how many have been found, who scanned them, and where are they?

When an individual takes accountability for a CMR, they are legally responsible for every asset listed on it.

Core SQL Pattern

SELECT
    a.text8 AS CMR,
    COUNT(*) AS TotalAssets,
    SUM(CASE WHEN a.lastinventoried >= @ScanFrom THEN 1 ELSE 0 END) AS ScannedCount,
    MAX(a.lastinventoried) AS LastScanDate,
    (SELECT TOP 1 v2.lastmodifiedby FROM dbo.v_asset v2
     WHERE v2.text8 = a.text8 AND v2.lastinventoried >= @ScanFrom
     ORDER BY v2.lastinventoried DESC) AS LastScanner,
    (SELECT TOP 1 v2.locationname FROM dbo.v_asset v2
     WHERE v2.text8 = a.text8 AND v2.lastinventoried >= @ScanFrom
     ORDER BY v2.lastinventoried DESC) AS LastLocation
FROM dbo.v_asset a
WHERE NULLIF(RTRIM(a.text8), '') IS NOT NULL
GROUP BY a.text8
ORDER BY ScannedCount * 1.0 / COUNT(*) DESC, ...

The @ScanFrom parameter is set to midnight today, 7 days ago, 30 days ago, or 1900-01-01 (All Time) based on the selected scan window tab. Correlated subqueries efficiently pull the most recent scanner and location per CMR without a separate join table.

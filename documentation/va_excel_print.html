1. Overview

va_excel_print.aspx reads C:\va_rfid\excel_data\equipment.xlsx, displays all equipment rows in a selectable grid, and lets the user Import Only or Import & Print selected rows into AssetWorx (dbo.asset).

5. Asset Name Format

Built by BuildAssetName(EquipRow r, string overrideName, string namePrefix):

SITE_PREFIX + " " + NAME_PREFIX + ENTRY_NUMBER

SITE_PREFIX  = company.name  (when Site Override selected)
             = Col 12 value  (when Auto)
NAME_PREFIX  = TxtNamePrefix.Text (e.g. "EE"), may be blank
ENTRY_NUMBER = Col 1 from Excel

Examples:
  Site="613"  Prefix="EE"  Entry="81294"  =>  "613 EE81294"
  Site="613"  Prefix=""    Entry="81294"  =>  "613 81294"
  Auto(Station="613-8") Prefix="EE" Entry="81294"  =>  "613-8 EE81294"

Important: Name is the MERGE key. Changing Site/Prefix/Entry will INSERT a new asset, not update the old one. Always verify via the Preview tab first.

6. RFID Tag Generation

During import, the rfidtag column is generated identically to va_dbupdate.sql:

  • baseTag = SITE_PREFIX + NAME_PREFIX + ENTRY_NUMBER
  • The script pads baseTag with the letter F so that the resulting length is a multiple of 4.
  • Example: "613" + "EE" + "81294" = "613EE81294" (Length 10). It will be padded with FF to become "613EE81294FF".

7. MERGE / Upsert Logic

Every row uses a SQL MERGE keyed on name + companyid (matches unique index index_asset_name_companyid on dbo.asset):

MERGE dbo.asset AS tgt
USING (SELECT @name AS n, @companyid AS cid) AS src
    ON tgt.name = src.n AND ISNULL(tgt.companyid, -1) = ISNULL(src.cid, ISNULL(tgt.companyid, -1))
WHEN MATCHED    -- asset exists with this name+company -> UPDATE other fields
    UPDATE SET description=@desc, text1..text12=..., text3=@serial, lastmodified=GETDATE()
               -- name and companyid are NOT changed (they are the key)
WHEN NOT MATCHED  -- new asset -> INSERT
    INSERT (name, ..., companyid, created, lastmodified) VALUES (...)
OUTPUT inserted.id;
⚠ Why not Serial# as the key? Serial numbers from VISTA/AEMS are sometimes missing, duplicated, or not yet assigned. The asset name is unique per company per the DB unique index and is the most reliable upsert key. Serial# (text3) is still written on every UPDATE.

8. Preview Names Tab

Two tabs in the equipment card:

  • Equipment Data - 19-column full grid with a highlighted "Name" column showing computed name.
  • Preview Names - 5-column focused view: Computed Name, Entry#, Station, Serial#, Status.

Both update in real time (no postback) when Site Override or Name Prefix changes via updatePreviewNames() JS function. The function reads data-entry and data-station attributes on each TR and rebuilds the name using the embedded companyNames JS object (emitted server-side from _companyIdToName dict).

9. Print Flow

  1. Selected rows are upserted (same MERGE as Import Only).
  2. AssetWorxApiHelper.SubmitPrintJob(assetId, templateId, companyId) called per row.
  3. AssetWorx API publishes MQTT print job to site print server.
  4. BarTender prints the label.

Print errors are collected separately; a print failure does not roll back the import. See Print Administration.

10. Performance & Limits

Because the web server processes the entire batch synchronously in a single request, there are strict batch size limits to prevent IIS connection timeouts:

  • Import Only: Safe up to ~500 rows.
  • Import & Print: Safe up to ~100 rows (the bottleneck is dispatching individual API/MQTT print jobs per row).

To prevent users from clicking repeatedly during long operations and flooding the server, a glassmorphism loading overlay with a CSS spinner is injected into the DOM the moment the user clicks OK on the confirmation prompt.

11. Access Control

Access granted if tile list contains any of: excel_print, admin_print, admin_users. Checked via UserManager.CanAccessTile(). Unauthorized redirected to index.aspx?err=access.

VA Site Inventory (Real-Time Location Sweep)

Active Production Interface: va_inventory.aspx / va_inventory.aspx.cs

ACTIVE PRODUCTION (v2.0)
Archival Notice: The earlier postback-driven version has been retired and archived as va_inventory_legacy.aspx. This document describes the modern client-side real-time sweeping engine, designed specifically for rapid RFID sweeps (30–50 tags/sec) on Zebra TC53 / RFD40 handhelds and enterprise web clients.

Database Interaction: Read / Write (via High-Performance AJAX WebMethods to AssetWorx SQL database)

Primary Workflow: Technicians walk into a room, scan the room barcode (e.g. SP008-BD. 8A), pull the RFID trigger to sweep the physical space, visually confirm confirmed vs misplaced equipment, and commit the reconciled inventory back to the database in one tap.

Configuring Screen & Column Visibility

To maximize usable screen real estate on mobile handhelds (such as the Zebra TC53 / TC530e at 412px viewport width) and prevent accidental taps during active room sweeps, the column chooser was intentionally removed from the scanning page. Column display is configured centrally via System Configuration.

How to Select or Deselect Columns:

  1. Open System Configuration: Navigate to the iDash Hub and click System Configuration (or navigate directly to va_site_config.aspx).
  2. Access Scanning Columns Section: Click 📱 Scanning Columns in the left sidebar, or scroll directly to the Mobile Scanning Page Column Visibility section.
  3. Toggle Column Checkboxes: In the configuration table, check or uncheck any of the 28 columns. Essential identity columns (Status and Asset Tag) are locked as required, while all optional metadata fields can be customized.
  4. Save Configuration: Click the green Save Column Configuration button at the bottom of the section. The server persists your layout to App_Data/scan_columns_config.json.
  5. Automatic Handheld Synchronization: The next time technicians load va_inventory.aspx, the page calls GetColumnConfig and injects precise CSS column visibility rules. Hidden columns are suppressed completely without horizontal bloat.

Room Sweep & Reconciliation Workflow

1Scan or Enter Room Location Barcode:
Scan the room barcode (starts with SP) or type the room name (e.g. SP008-BD. 8A) and press Enter or tap Load Room. The system fetches all assets assigned to that room in AssetWorx.

2Physically Sweep the Room:
Hold down the RFID trigger on the Zebra handheld. Focus is automatically maintained on the scanning trigger box. Incoming tags match instantly in memory. Total reads increment live, and found assets turn bright green.

3Review Reconciliation Categories:
Use the filter tabs to review sweep status:

  • All: Complete room manifest plus any misplaced tags found.
  • Found: Expected room assets that were physically detected in this room.
  • Not Found: Assets assigned to this room that have not yet been detected.
  • Move Here?: Assets registered in the database to a different room, but detected here.
  • Unknown: Tags detected that are not in the database (e.g. shipping labels or non-VA items).

4Commit Inventory:
Tap the green ✔ Commit Scans button.

  • If only expected assets were found: The system prompts for confirmation and immediately commits them.
  • If out-of-place assets (Move Here?) were detected: A choice modal appears:
    • Commit Expected Only: Updates last inventoried date on expected assets; leaves misplaced assets assigned to their original rooms.
    • Commit All & Move Misplaced Here: Updates expected assets AND officially transfers all misplaced items to the current room in SQL.
After commit, tap Next Room to clear the workspace and sweep the next location.

Found Item Pinning & Ordering Rules

To provide instant visual feedback without scrolling through long manifests of hundreds of items:

  1. Immediate Insertion at Row 1: As soon as an asset is scanned, its DOM row moves to the very first position in the table (tbody.insertBefore(row, tbody.firstElementChild)) with an emerald highlight pulse animation (.row-just-found).
  2. Found Priority Over Misplaced Items: Non-found items (such as newly scanned Move Here? or Unknown tags) are inserted after all Green Found rows, ensuring confirmed assets are never displaced or buried.
  3. Persistent Top Sorting: Column sorting (by tag, serial number, CMR, reads, etc.) maintains Green Found items at the top of the grid regardless of sort direction.

Handheld Ergonomics & Horizontal Swiping

  • Smooth Touch Swiping: On narrow handheld displays (Zebra TC53 at 412px width), the grid container (.grid-wrap) supports native horizontal touch scrolling (touch-action: pan-x pan-y; -webkit-overflow-scrolling: touch;). Technicians can smoothly slide across all enabled columns.
  • 🌓 Light / Dark Mode Toggle: An adaptive theme button in the top bar toggles between dark mode and a high-contrast daylight mode with bold text tokens for high-glare environments.
  • Auto-Focus Scanner Input: Trigger focus is automatically retained or re-acquired after button taps, modal dismissals, and tab switches so the technician never has to tap the input field.
  • Technician Fast Login: Supports Enter-key keyboard submission and authenticates against both iDash portal accounts and SQL scanner users (dbo.sysuser).

📡 Remote Database Update

Run database imports from any workstation on the network — no RDP, no file shares, no same-server requirement.

Overview

The Remote DB Update tool allows you to import VA data files into the iDash database from any computer on your network. It consists of two components:

ComponentLocationPurpose
remote_db_update.ps1 Any workstation (copy from Downloads) PowerShell script you run on your local machine. Reads the data file and sends it to the server.
api/va_remote_import.ashx IIS server (already deployed) Server-side API endpoint that receives the file, streams it to SQL Server, and runs the merge.
✅ Network-Safe: This tool uses SqlBulkCopy to stream data over the SQL connection — it does not use BULK INSERT. IIS and SQL Server can be on different machines without any issues.

Why This Exists

The original va_dbupdate.aspx uses SQL Server's BULK INSERT command, which reads files from a path local to the SQL Server. When IIS and SQL Server are on different machines, BULK INSERT fails because SQL Server can't see the data file sitting on the IIS box.

End User Guide

Prerequisites

  • Windows workstation with PowerShell 5.1+ (built-in on Windows 10/11 and Server 2016+)
  • Network access to the iDash server (can reach it via browser)
  • A tab-delimited .txt data file (standard VA 15-column format)
  • Copy of remote_db_update.ps1 (download from iDash Downloads → Scripts)

Step-by-Step Instructions

  1. Download the script.
    Go to iDash → Downloads → Scripts and save remote_db_update.ps1 to a folder on your workstation (e.g., C:\Tools\).
  2. Open PowerShell.
    Right-click the Start menu → Windows PowerShell (or Terminal). Navigate to the folder containing the script.
  3. Run the script.
    Provide the path to your data file and the iDash server URL: 
    .\remote_db_update.ps1 -DataFile "C:\Data\ALLV5SITEdata.txt" -ServerUrl "http://your-server/iDash"
  4. Review the summary and press Enter.
    The script will show you the file size, row count, and estimated processing time. Press Enter to start, or Ctrl+C to cancel.
  5. Wait for results.
    The script uploads the file and displays a summary when complete: 
      ╔══════════════════════════════════════════════════╗
  ║  IMPORT COMPLETED SUCCESSFULLY                  ║
  ╚══════════════════════════════════════════════════╝

    Rows parsed          : 45,231
    Locations inserted   : 12
    Assets inserted      : 1,847
    Assets updated       : 0
    Assets skipped       : 23
    Errors               : 0
    Total assets now     : 89,456

Common Command Examples

# Basic import (auto-detect station numbers from file)
.\remote_db_update.ps1 -DataFile "C:\Data\export.txt" -ServerUrl "http://10.0.1.50/iDash"

# Force all rows to station 640
.\remote_db_update.ps1 -DataFile ".\data.txt" -ServerUrl "http://idash-srv/iDash" -ForceSite "640"

# With API key authentication
.\remote_db_update.ps1 -DataFile "\\fileserver\exports\data.txt" -ServerUrl "http://myserver/iDash" -ApiKey "secret123"

# From a network share
.\remote_db_update.ps1 -DataFile "\\nas01\va_data\weekly_extract.txt" -ServerUrl "http://idash/iDash"

Developer & IT Reference

Architecture

How the Pipeline Works

  1. 1 Client-side: PowerShell reads the .txt file from the local filesystem and sends it as a multipart/form-data HTTP POST to the API endpoint.
  2. 2 Server-side (IIS): The va_remote_import.ashx handler receives the upload, parses the tab-delimited content into a DataTable in memory.
  3. 3 Server-side (SQL): The handler uses SqlBulkCopy to stream the DataTable rows over the SQL connection into dbo.AssetFileRaw. This works regardless of whether SQL Server is on the same machine.
  4. 4 Merge: The standard merge SQL runs (same logic as va_data_import.aspx) — maps raw data to assettemp, computes EPC tags, resolves companies, inserts locations, inserts/updates assets.
  5. 5 Response: JSON results are returned to the PowerShell client and displayed.

Authentication (Optional)

By default, the endpoint has no API key requirement (suitable for internal VA networks). To enable key-based authentication:

  1. Add to web.config → <appSettings>: 
    <add key="RemoteImportKey" value="your-secret-key-here" />
  2. Pass -ApiKey "your-secret-key-here" when running the PowerShell script.
ℹ Note: The API key is sent in the X-Api-Key HTTP header. If no RemoteImportKey is configured in web.config, the endpoint accepts all requests without authentication.

Troubleshooting

"Script is not digitally signed"

Windows blocks unsigned scripts by default. Fix:

Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

Or run directly:

powershell -ExecutionPolicy Bypass -File .\remote_db_update.ps1 -DataFile ".\data.txt" -ServerUrl "http://server/iDash"

"Unable to connect to the remote server"

  • Verify the server URL is correct and reachable: Test-NetConnection your-server -Port 80
  • Make sure you're using http:// not https:// unless SSL is configured
  • Check Windows Firewall on the IIS server allows inbound port 80

"401 Invalid or missing API key"

  • A RemoteImportKey is configured in web.config but you didn't pass -ApiKey
  • The key you passed doesn't match the one in web.config

"File must have a header row and at least one data row"

  • The file is empty or has only a header
  • The file is not UTF-8 encoded — try re-saving as UTF-8 in Notepad

Import runs but 0 assets inserted

  • All assets already exist in the database (matched by name + companyid or rfidtag)
  • The merge SQL only inserts new assets — it does not update existing ones. Use va_dbupdate.aspx with the enrichment script for updates.

Large files timing out

  • The server-side timeout is 30 minutes; the PowerShell timeout is also 30 minutes
  • For files over 100K rows, ensure the IIS maxRequestLength in web.config is large enough (default is 100 MB)
  • Check the IIS server's requestLimits maxAllowedContentLength in <system.webServer>

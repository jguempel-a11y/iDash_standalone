📡 Fixed Reader Configuration

Manage fixed RFID reader registrations, antenna mappings, and online/offline status — all from a single dashboard.

Overview

The Fixed Reader Configuration page is the central management tool for all fixed RFID readers deployed across VA sites. It connects to the iDash REST API to provide a real-time view of every registered reader and allows you to:

  • View all readers with live online/offline status
  • Add, edit, and delete reader registrations
  • Configure per-antenna port mappings and TX power levels
  • Discover unregistered readers on the network
  • Filter readers by site and search by name, location, IP, or model

Dashboard KPIs

The top of the page displays four key metrics that update each time the reader list refreshes:

KPIDescription
Total ReadersCount of all registered readers (filtered by the selected site).
OnlineReaders whose lastSeen timestamp is within the last 11 minutes.
OfflineReaders that have NOT reported within the last 11 minutes.
ModelsCount of distinct reader models (CSL, Zebra, Impinj, etc.) across the filtered set.
Online/Offline logic: A reader is considered Online if its lastSeen timestamp is within 11 minutes of the current UTC time. Anything older is marked Offline.

Use the search bar above the table to filter by reader name, location, IP address, or model. Use the Site dropdown in the header to filter by VA site.

Adding a Reader

Click the + Add Reader button in the page header to open the registration modal. Required and optional fields:

Reader Name * A descriptive name for the reader (e.g., "ED Hallway Reader 1"). Required.
IP Address * The network IP address of the reader hardware (e.g., 10.0.1.50). Required.
Reader Model Select the manufacturer: CSL (Convergent Systems), Zebra, Impinj, or Other.
Physical ID / Serial The hardware serial number printed on the reader. Optional but recommended for inventory tracking.
Site The VA site (company) this reader belongs to. Loaded directly from dbo.company via the api=companies endpoint — always shows all available sites regardless of header filter.
Location The iDash location to associate with this reader. Dynamically filtered — only shows locations belonging to the site selected above. Changing the Site automatically reloads the location list.
MQTT Control Topic Optional MQTT topic for remote reader control commands. Leave blank if not using MQTT.
Batch Mode Toggle ON for readers that accumulate reads and send them periodically rather than in real-time.

Update Location on Read

When enabled (the default), any asset scanned by this reader will have its location automatically updated to the reader's assigned location. Disable this for readers used only for inventory verification where you do not want asset locations to change.

Antenna Configuration

Each reader can have multiple antennas, each with its own port number, location override, and transmit power setting. The antenna section appears at the bottom of the Add/Edit modal.

FieldDescriptionRange
PortThe physical antenna port number on the reader hardware.1 – 16
LocationOptional location override for this specific antenna. Useful when one reader covers multiple rooms.Any location
PowerTransmit power in dBm. Higher = longer range but more interference.0 – 33

Click + Add to add antenna rows, and click the ✕ icon to remove one. Antenna configurations are saved separately after the reader record is saved.

Antenna save order: When creating a new reader, save the reader first (which creates the record), then edit it to configure antennas. Antenna mappings require an existing reader ID.

Editing a Reader

Click the ✎ Edit button on any reader row to re-open the modal pre-filled with that reader's current settings. The modal title changes to show the reader name. All fields can be modified, and the existing antenna configuration is loaded automatically.

Deleting a Reader

Click the 🗑 Delete button on any reader row. You will be prompted to confirm before the reader is permanently removed. This action calls the iDash API's delete endpoint and cannot be undone.

Discovering Unregistered Readers

The Unregistered / Discovered Readers panel (below the main table) lets you scan the network for readers that are broadcasting but not yet registered in iDash. Click ↻ Scan to query the API for unregistered CSL and Zebra readers.

When unregistered readers are found, each row displays the reader's name, IP, model, and physical ID along with a ✓ Register button that pre-fills the Add Reader modal with those values.

Tip: Use the Scan feature after deploying new reader hardware. It saves time by auto-populating the registration form with discovered reader details.

How It Works (Technical)

Architecture

The page communicates with the iDash REST API using OAuth2 client credentials. All reader CRUD operations go through the API — the page itself does not write directly to the database. Location and company data for the modal dropdowns are fetched directly from SQL Server via dedicated API endpoints.

API Endpoints Used

ActionMethodEndpoint
List readersGET/api/readers/
Create readerPOST/api/readers/
Update readerPUT/api/readers/
Delete readerDELETE/api/readers/?ids={id}&madeBy=iDash
Get antennasGET/api/antennas/Reader/{readerId}
Save antennasPOST/api/antennas/Reader/{readerId}
Discover unregisteredGET/api/readers/Unregistered?readerModel={model}

Internal API Endpoints (iDash page-level)

The ASPX page itself exposes lightweight JSON endpoints for the modal dropdowns, routed via ?api= query string:

ActionEndpointSource
Load locations (filtered by site)?api=locations&siteid={id}dbo.location
Load companies (all sites)?api=companiesdbo.company

Authentication

The code-behind obtains an OAuth2 bearer token using the client_credentials grant type. Tokens are cached in memory and automatically refreshed 60 seconds before expiry. The following web.config app settings are required:

SettingPurpose
iDash_ApiBaseBase URL of the iDash API (e.g., https://aw-server/iDash)
iDash_TokenUrlOAuth2 token endpoint URL
iDash_ClientIdOAuth2 client ID
iDash_ClientSecretOAuth2 client secret

Site Filtering & Permissions

The Site dropdown is populated from the dbo.company table and filtered based on the logged-in user's role and site access permissions:

  • Admin users see all sites plus an "All Sites" option.
  • Non-admin users see only the sites listed in their SiteAccess profile. If they have access to more than one site, the "All Sites" option also appears.

Troubleshooting

All readers show as Offline

Check that the iDash API is reachable and that the OAuth2 credentials in web.config are correct. If the API returns data but lastSeen timestamps are stale, verify that the reader middleware (MQTT broker or polling service) is running and updating reader heartbeats.

"iDash API not configured" error

The iDash_ApiBase or iDash_TokenUrl app settings are missing or blank in web.config. Add or correct them and recycle the app pool.

No locations in the dropdown

Locations are loaded directly from dbo.location filtered by the selected company ID. If the dropdown is empty, confirm that locations exist in the database for that site. You may need to run a data import first.

Antennas not saving on new reader

Antenna configurations require an existing reader ID. When adding a new reader, save the reader first to create the record, then edit it to configure antennas.

Delete fails

The API delete call includes madeBy=iDash as an audit parameter. If the API returns an error, check that the OAuth2 client has delete permissions on the readers endpoint.

VA Site Maps — Tagging Command Center

Complete documentation for the site maps dashboard, including how it works, what the status indicators mean, and how to use every feature. Updated July 2026.

What This Page Does

The Site Maps page is the central hub for tracking RFID tagging progress across VA medical centers. It displays architectural floor plan maps for each building at a site, overlays real-time tagging statistics from the iDash database, and lets you drill into room-level asset data.

Why does this exist? Before this tool, tracking tagging progress required manually cross-referencing exported Excel reports with physical floor plans. This dashboard automates that process, showing which buildings and rooms have been fully tagged, partially tagged, or not yet started. The reporting team and field technicians can see at a glance where to focus their efforts.

How It Works — The Architecture

The page works in three layers:

  1. Map Files: Physical floor plan images (PNG/PDF) stored in iDash/site_maps/VISN##/### SiteName/. File names start with the building number (e.g., 500-1st Floor Arch.pdf).
  2. Database: Asset tagging data from dbo.v_asset in the iDash database. Key fields: text18 (tagged flag = '1'), text6 (location code like SP4C141-500 where 500 = building), text20 (notes).
  3. Building Stats API: The page calls buildingstats API which groups assets by building number (extracted from text6) and returns tagged/remaining counts per building.

Data Flow

When you select a site from the dropdown:

  1. Three API calls fire simultaneously: sitestats, locationstats, buildingstats
  2. KPI chips update (Tagged / Remaining / % Complete)
  3. Map cards render with building-specific status dots and progress bars
  4. Directory sidebar shows folders matching the selected site's station number (e.g., 613)

Status Dot Legend

How building numbers are matched: The system extracts the building number from map filenames (e.g., 500 from 500-1st Floor Arch.pdf) and matches it against the text6 location field in the database (e.g., SP4C141-500). The last segment after the final dash is the building number.

Map Status Toggle (All / Done / Pending)

This filters map cards by their manual completion status (set via the "Mark Complete" button in the detail panel):

  • All — Show all map cards
  • Done — Only maps you've marked as "Complete" (saved in browser localStorage)
  • Pending — Maps not yet marked as complete
Important: This toggle is about map-level completion tracking — it does NOT filter by RFID tag status. It's for the tagging team to track which floor plans they've finished reviewing.

Shows folder structure under site_maps/. Click a folder to filter map cards to just that directory. The badge shows how many maps are in each folder.

Inline Notes

The asset table has a Notes column at the far right. Each cell shows the current note from dbo.asset.text20 or a clickable "+ note" placeholder if empty.

Adding/Editing Notes

  1. Click the Notes cell for any asset
  2. A centered modal dialog opens with the current note and the asset name in the title bar
  3. Type your note and click Save (or press Ctrl+Enter)
  4. The note saves to the database immediately via AJAX
Database field: Notes are saved to dbo.asset.text20 with lastmodified updated. to the current UTC timestamp. This field syncs through the normal Field Sync process.

Map Version Control

When a map file is uploaded through the UI, the previous version is automatically backed up before overwriting.

How It Works

  • Previous versions are saved to a .versions/ subdirectory next to the original file
  • Backup naming format: 500-1st Floor Arch_v1_20260712_153000.pdf
  • A version_history.json file tracks who uploaded what and when
  • Click the 🕑 History button in the detail panel to view the version log
Automatic: You don't need to do anything special — version tracking happens automatically when you upload a new map through the UI. Existing maps before this feature won't have history entries, but will start tracking on their next update.

ENNX Report Import

The "Import ENNX Report" button in the sidebar opens a drag-and-drop panel for importing ENNX reader output files. The system parses the file and cross-references lines against the database by RFID tag or asset name.

Supported Formats

  • .ennx.txt files from EPC readers
  • Any text file with one identifier per line (RFID EPC hex values or asset names)
  • Lines starting with # or // are ignored

Column Chooser

The asset table includes a Column Chooser button (⚙ icon) that lets you show or hide specific columns. Click it to open a dropdown with checkboxes for every column.

  • Selections persist for your browser session
  • Hidden columns are excluded from the table display but included in exports
  • Default columns shown: Name, Description, Location, RFID Tag, Tagged, Notes

Troubleshooting

Maps show "No Data" (grey dots)

This means the building number extracted from the filename doesn't match any text6 suffixes in the database. Check that the filename starts with the correct building number and that assets have their location field populated.

KPIs show 0 / 0 / 0

The selected site has no assets in the database. Run Field Sync to import data from the field server backup.

Note save fails

The dbo.asset table must allow updates. Check SQL permissions for the IIS app pool identity. The query uses UPDATE dbo.asset SET text20 = @Note WHERE name = @Name.

Version history is empty

Version tracking only starts when maps are uploaded through the web UI. Maps that existed before this feature won't have history entries. The first upload will create the tracking file.

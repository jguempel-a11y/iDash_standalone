🔗 iDash REST API

The iDash API is a .NET Web API hosted in the same IIS application pool as the iDash web portal. It provides CRUD operations for assets, readers, antennas, print jobs, and user accounts.

Base URL: http://localhost/api
Auth: OAuth 2.0 Client Credentials (per-site clientapp entries in DB)
Token Endpoint: POST /api/oauth/token
Content-Type: application/json

Authentication

POST /api/oauth/token
Obtain an OAuth 2.0 bearer token using client credentials. Each site has its own clientapp entry (e.g., idash_540, idash_517) so the token carries the correct cmpid claim.
Request Body (form-urlencoded):
ParameterValue
grant_typeclient_credentials
client_ide.g. idash_512
client_secretFrom dbo.clientapp.secret
Response:
{ "access_token": "eyJ...", "token_type": "bearer", "expires_in": 86400 }
Used in: IdashApiHelper.cs

Print Jobs

POST /api/printjob/print
Create a print job, generate RFID tag, insert dbo.printjob row, and notify the native Print Server via MQTT on port 8883.
✔ Active Native Pipeline: iDash uses this endpoint as the primary printing mechanism via IdashApiHelper.SubmitPrintJob(), providing 100% independent server-side label printing without external scripts. Automatic database fallback is included if the API is offline.
Request Body (JSON):
{ "id": -1, "recordID": 12345, "templateID": 7, "tableName": "Asset", "useWithService": "" }
Response: Print job ID (integer) on success, or error message string.
Used in: IdashApiHelper.cs (Asset Master, Excel Print, Tag Team Scan, Print Admin)
Primary Print Engine
GET /api/PrintJobs/New
Returns uncompleted print jobs (completed=0). Used by administrative tools to monitor pending queues.
Used by: Print Queue Admin & Diagnostics

Readers

GET /api/readers/
List all registered fixed readers. Returns reader name, model, IP, location, company, last seen, and status.
Used in: va_reader_config.aspx, va_fixed_reader.aspx
GET /api/readers/{id}
Get a specific reader by database ID.
Used in: va_reader_config.aspx
GET /api/readers/Unregistered
List readers that have connected to the MQTT broker but are not yet registered in dbo.reader. Used during initial reader setup to auto-discover new hardware.
Used in: va_reader_config.aspx (auto-discover feature)

Antennas

GET /api/antennas/Count
Get the total count of registered antennas across all readers.
Used in: va_fixed_reader.aspx
GET /api/antennas/Reader/{readerId}
Get all antennas for a specific reader. Returns port number, location mapping, and configuration.
Used in: va_reader_config.aspx

Health

GET /api/health
Basic health check. Returns 200 OK if the API is running.
Used in: va_reader_config.aspx, va_system_diagnostics.aspx

Assets

GET /api/asset/{id}
Get a single asset record by ID. Returns full asset fields including name, description, EIL, tag data, location.
Used in: va_system_diagnostics.aspx (batch test simulation)

📡 Zebra IoT Connector REST API

Local REST API running on each Zebra FX9600 fixed reader. Provides hardware management, configuration, firmware updates, and tag-reading control. Accessed via the reader's IP address.

Official Docs: Zebra IoT Connector API Reference | MQTT Command Schemas

Base URL: https://{reader-ip}/api/v1 (e.g. https://192.168.4.47/api/v1)
Auth: JWT — obtained via Basic Auth on /cloud/localRestLogin
TLS: Self-signed certificate (accept in browser or use ServerCertificateValidationCallback)
Default Credentials: admin / change (factory default)

Authentication

GET /cloud/localRestLogin
Authenticate with HTTP Basic Auth. Returns a JWT token used for all subsequent calls. Token should be sent as Authorization: Bearer {jwt}.
Headers:
Authorization: Basic {base64(username:password)} Content-Type: application/json
Response:
{ "message": "Login successful", "token": "eyJ..." }
Used in: va_reader_config.aspx (Hardware Intelligence panel)

Firmware & Config

PUT /cloud/os
Push firmware update from an HTTP URL. The reader downloads and installs the firmware file, then reboots.
PUT Body:

Used in: va_reader_config.aspx (Firmware Push feature)
PUT /cloud/revertbackOS
Rollback firmware to the previous version stored on the secondary partition. Extremely valuable for recovering from bad firmware updates without physical access.
PUT /cloud/reboot
Reboot the reader. Returns immediately; reader takes ~60 seconds to come back online.
Used in: va_reader_config.aspx
GETPUT /cloud/config
Backup or restore the complete reader configuration as a JSON blob. GET returns the current config; PUT restores a previously saved config.
Used in: va_reader_config.aspx (Backup & Restore)

Pull reader logs. Log types: syslog, radioPacketLog, RgErrorLog, RgWarningLog, RcLog.

📱 Zebra Handheld & Mobile Scanning Architecture

Direct hardware-level integration for handheld RFID sweeps and barcode scans across VA medical facilities. Designed specifically for Zebra TC53 / TC530e Touch Computers coupled with RFD40 Standard / Premium Plus or RFD90 Ultra-Rugged UHF RFID Sleds (via 8-pin eConnex mount), as well as Zebra MC3300x mobile computers.

Target Platforms: Zebra TC530e, TC53, TC26, MC3300x + RFD40/RFD90 UHF RFID Sleds
Ingestion Modes: Zebra DataWedge (Keystroke & Intent Output), Zebra Enterprise Browser (EB) JS API
Sweep Performance: 30–50 tags/sec continuous trigger hold with 0ms UI lag (Synchronous in-memory matching)
EPC Normalization: VA EE Formats (^(\d{3})EE([A-Z0-9]+)$) with automatic FF checksum stripping

Zebra DataWedge Ingestion Pipeline

KEYSTROKE / INTENT DataWedge Profile: "idash_portal"
Zebra DataWedge intercepts hardware trigger events from the barcode imager or RFD40 RFID sled, buffers the scanned payload, and delivers it to the active browser input field or broadcast intent receiver.
✔ Zero-Flicker Hardware Buffer: Configured with 5ms inter-character delay and Enter/CR (\n) suffix. The input field in va_inventory.aspx captures continuous tag bursts while user holds the trigger, passing tokens directly to the in-memory lookup table.
DataWedge Profile Configuration:
SettingRequired ValuePurpose
Profile Nameidash_portalAssociated with Chrome / Zebra Enterprise Browser package
Barcode InputEnabled (Code 39, Code 128, DataMatrix, QR)Scans room barcodes (SP...) & asset serials
RFID InputEnabled (RFD40/RFD90 eConnex)Continuous EPC streaming on trigger hold
Keystroke OutputEnabled (Action: Send Enter / \n)Delivers tag stream to focused DOM input
Intent OutputAction: com.idash.idash.SCANBackground headless capture (optional)
Used in: va_inventory.aspx, va_zebra_browser_test.aspx

Zebra Enterprise Browser (EB) JavaScript APIs

JS API EB.Barcode / EB.RFID
Native hardware control within Zebra Enterprise Browser runtime. Bypasses keystroke emulation for direct programmatic control over illumination, beeper volume, and sled antenna transmit power.
EB JavaScript Invocation Example:
// Enable Barcode Scanner with hardware callback EB.Barcode.enable({ allDecoders: true, picklistMode: 'hardware' }, function(scanResult) { if (scanResult && scanResult.data) { processTag(scanResult.data); } }); // Configure RFD40 UHF Sled Transmit Power (1000 - 3000 cdm = 10 - 30 dBm) if (window.EB && EB.RFID) { EB.RFID.setAntennaPower(2700); // 27 dBm standard room sweep }
Used in: va_zebra_browser_test.aspx, va_zebra_browser_test_2.aspx

In-Memory Tag Normalization & Auto-Location Switching

RULE ENGINE Synchronous Tag & Location Matcher
Client-side token parser executes in sub-millisecond memory time. Automatically distinguishes location barcodes from asset tags, normalizes EPC hex into human-readable VA asset names, and detects misplaced equipment.
Parsing Rules:
PatternClassificationAction Taken
SP* (e.g. SP008-BD. 8A)Location / Room BarcodeInstantly updates room selection & fetches room manifest via LoadLocationAssets
^(\d{3})EE([A-Z0-9]+)$VA EPC Tag (Compact)Normalizes to {Site} EE{Core}, strips trailing FF checksum byte
E280116060...Raw SGTIN-96 / Gen2 EPCMaps to database asset record via a.rfidtag index
Alphanumeric / SerialManufacturer Serial NumberMatches against a.text3 or a.text8
Used in: va_inventory.aspx, va_zebra_browser_test.aspx

🐇 RabbitMQ Management API

HTTP API provided by the RabbitMQ management plugin. Used by iDash to monitor broker health, connection counts, and queue depths. Proxied through va_site_config.aspx to avoid CORS issues.

Base URL: http://localhost:15672/api
Auth: HTTP Basic Auth (guest:guest default)
iDash Proxy: va_site_config.aspx?api=rmq&path={endpoint}
GET /api/overview
Broker overview: Erlang version, RabbitMQ version, message rates, queue totals, connection counts.
Used in: va_site_config.aspx (RabbitMQ Broker Status panel)
GET /api/connections
List all active MQTT/AMQP connections. Shows client ID, connected since, channel count, state.
Used in: va_site_config.aspx
GET /api/queues
List all queues with message counts, consumer counts, and message rates.

🛠 iDash Internal APIs

AJAX endpoints built into iDash pages. These are query-string-based APIs on .aspx pages that return JSON. No external dependencies — they query the database directly.

Base URL: http://localhost/iDash
Auth: iDash session cookie (no separate auth needed)
Format: {page}.aspx?api={command}&{params}

Asset Master

GET /iDash/va_asset_master.aspx?api=detail&id={assetId}
Get full detail for a single asset including all fields, tag data, and metadata.
POST /iDash/va_asset_master.aspx?api=update&id={assetId}
Update asset fields (inline edit from the detail drawer).
GET /iDash/va_asset_master.aspx?api=locationhistory&id={assetId}
Get location history timeline for an asset.

Site Config

GET /iDash/va_site_config.aspx?api=rmq&path={endpoint}
Server-side proxy to RabbitMQ Management API. Avoids CORS by routing through the ASP.NET backend.
GET /iDash/va_site_config.aspx?api=svc&cmd=status
Get status of all managed services: RabbitMQ, Print Server, IIS (W3SVC), Antenna Service.
GET /iDash/va_site_config.aspx?api=svc&cmd=restartAll
Restart all services in order: RabbitMQ → IIS → Print Server.

License Manager

GET /iDash/va_license_manager.aspx?action=api&cmd=getAll
Get all license-consuming registrations: readers, servers, users, scanners, MQTT clients.

Base URL: http://localhost/iDash/va_inventory.aspx/{Method}
Alternative: http://localhost/iDash/va_zebra_browser_test.aspx/{Method}
Auth: Session Cookie (IsAdminAuthenticated = true & IdashSiteAccess claim)
Content-Type: application/json; charset=utf-8
POST /iDash/va_inventory.aspx/GetSessionState
Verify mobile operator session, identify assigned VA facility, and resolve user permissions.
Request Body: {}

Retrieve distinct room and location codes for the active VA facility.

🔌 MQTT Topics

Publish/subscribe topics used for real-time tag data and system notifications. Two separate brokers are in use.

RabbitMQ Broker (port 1883)

Broker: 127.0.0.1:1883 (non-TLS)
External Clients: FX9600 reader (192.168.4.47), iDash AntennaLocationService
PUB reader/#
Tag read events published by fixed readers. JSON payload contains EPC, antenna port, RSSI, timestamp. The AntennaLocationService subscribes to this topic and updates dbo.asset.locationid based on antenna-to-location mappings.
Example Payload:
{ "data": { "idHex": "E280116060000209AB...", "reads": [{ "antennaPort": 2, "peakRssi": -45, "timestamp": "2026-09-01T15:30:00Z" }] } }

API Embedded Broker (port 8883)

Broker: 127.0.0.1:8883 (TLS)
Clients: Print Server (MasterPrint credentials)
Note: iDash no longer uses this broker for printing (Sept 2026)

🛡 Security, Authorization & Federal Compliance Standards

Every API endpoint, mobile scanner integration, and background service in iDash is designed to satisfy federal information security mandates (NIST SP 800-53 Rev. 5), Veterans Affairs directives, and Section 508 accessibility guidelines.

NIST AC-3 Authorization Consistency & Fail-Closed Session Enforcement

All directly invokable .ashx HTTP handlers (LiveScanHandler.ashx, v_asset.ashx) and AJAX WebMethods implement IRequiresSessionState. Unauthenticated requests are rejected immediately with HTTP 401 Unauthorized. The remote import handler (va_remote_import.ashx) enforces a strict fail-closed policy requiring an explicit X-Api-Key header matching web.config.

NIST SC-4 Multi-Tenant Facility Isolation (Site Boundary Protection)

SQL queries dynamically inject site boundary checks via UserManager.GetAllowedCompanyIds(). Mobile scanner operators are restricted strictly to their assigned VA medical center or station (e.g. Station 517, 540, 613). Cross-facility data queries or cross-site asset commits are blocked at the database abstraction layer.

NIST AU-2 / AU-12 Full Operator Audit Trails & Timestamping

Every inventory sweep commit permanently updates lastinventoried = SYSDATETIMEOFFSET(), lastmodifiedby = @username, and lastmodifieddate = SYSDATETIMEOFFSET() in dbo.asset. Operator logins and access attempts are recorded in dbo.login_audit with client IP, timestamp, role, and authentication outcome.

Section 508 Accessibility & Mobile Scanner Ergonomics

Scanning pages use a 4-color status identification model (Green = Found, Orange = Missing, Purple = Misplaced, Slate = Unregistered) supplemented by distinct typography, icons, and auditory tone synthesizers. Viewports are responsive and optimized for Zebra 720x1440 handheld displays with swipeable cards and touch targets exceeding 48x48px.

🔧 Import Workbench

The Import Workbench (va_dbupdate_workbench.aspx) is a standalone tool that lets you test, configure, and validate VA data imports before anything touches the database. It supports configurable field separators, dynamic column header mapping, and a full dry-run preview workflow.

✅ Zero Risk Testing
Every test run wraps the entire SQL execution in a database transaction and immediately rolls it back. The database is left exactly as it was. You see the full import stats and affected records without committing a single byte.

🤔 Why Does This Exist?

The VA is transitioning from tab-delimited data exports to pipe-delimited (|) exports. This seems like a small change — just swap one character, right? — but it's actually a landmine that silently corrupts your entire database if you get it wrong.

What Goes Wrong Without This Tool

The SQL import script (va_dbupdate.sql) uses BULK INSERT with a hardcoded FIELDTERMINATOR = '\t'. If the VA sends you a pipe-delimited file and you run the standard script without changing this:

  • Every column shifts. SQL Server reads the entire row as one giant column because it never finds a tab character.
  • Data goes into the wrong fields. The manufacturer ends up in the serial number field. The location goes into the CMR field. The equipment category overwrites the station number.
  • You don't find out until someone notices that 40,000 asset records now have garbage data in half their fields.
  • Recovery is painful. You'd need to restore from a database backup or run a targeted cleanup script on tens of thousands of records.

The same problem applies to header changes. If the VA renames a column (e.g., MFGR. EQUIPMENT NAME becomes EQUIPMENT DESCRIPTION), the CREATE TABLE dbo.AssetFileRaw definition in the SQL script won't match the file, and the INSERT INTO dbo.assettemp mapping will reference columns that don't exist.

⚠ This is exactly the kind of silent failure that ruins your weekend.
The BULK INSERT succeeds. SQL Server doesn't throw an error. The data looks like it imported. But every field is wrong. You won't know until someone pulls up an asset and sees "SOMATICS" where the location should be.

How the Workbench Prevents This

  1. You pick your separator before anything runs. Tab, pipe, comma, or any custom character.
  2. You see the parsed data in a grid with the actual column headers. If columns are misaligned, you see it immediately.
  3. You map the headers if they don't match the standard VA column names. Auto-mapping handles exact matches.
  4. You test run against the real database with a transaction rollback. You see exactly how many records would be inserted, updated, and skipped.
  5. You commit only when you're confident the data is correct.

📚 Step-by-Step Walkthrough

Step 1: Configure & Parse

  1. Open va_dbupdate_workbench.aspx from the iDash hub (🔧 Import Workbench tile).
  2. Select your separator:
    • Tab — Standard VA CDW format (the default).
    • Pipe (|) — The new VA format being rolled out.
    • Comma — Standard CSV files.
    • Custom — Any single character you type in the box.
  3. Select a data file from the dropdown (lists .xlsx, .txt, .csv files from the server). Or click "upload manually" to upload from your device.
  4. Select a SQL script from the dropdown (usually va_dbupdate.sql or va_dbupdate_upsert_enrich.sql).
  5. Click 🔍 Parse & Preview.
✅ What to look for: The preview grid shows the first 25 rows of your data with column headers at the top. Verify that the data in each column makes sense. If you see garbled data or everything in one column, you picked the wrong separator. Go back and change it, then re-parse.

Step 2: Map Headers

  1. After parsing, the Header Mapping section appears with a two-column grid.
  2. Left column: Shows each header found in your file (read-only).
  3. Right column: A dropdown with all 16 AssetFileRaw database columns plus a "— Skip —" option.
  4. Columns that exactly match (case-insensitive) are auto-mapped and highlighted green.
  5. Columns that didn't match are shown in amber. Use the dropdown to manually assign the correct mapping.
  6. Use — Skip — for columns you don't want to import (they'll be loaded into dummy columns and ignored).
  7. Click ✔ Apply Mapping & Generate SQL.
⚠ Important: The order matters. BULK INSERT reads columns positionally — column 1 in the file goes into column 1 in the table. The workbench handles this automatically by creating the AssetFileRaw table with columns in the same order as your file. You just need to tell it which database column each file column maps to.

Step 3: Review Generated SQL & Test Run

  1. The Generated SQL panel shows the modified SQL script with:
    • FIELDTERMINATOR set to your chosen separator
    • CREATE TABLE dbo.AssetFileRaw rewritten with columns matching your mapping
    • A comment header noting the modification date and settings
  2. Scroll through the SQL to verify it looks correct.
  3. Click ⚠ Test Run (Dry Run) to execute the SQL inside a transaction.
  4. The test run:
    • Executes every batch of the SQL script against the live database
    • Collects import statistics (locations inserted, assets inserted/updated/skipped, errors)
    • Collects the preview log (first 25 affected records, if the script supports #PreviewLog)
    • Immediately rolls back the entire transaction — nothing is permanently written
  5. Review the results. If everything looks correct, proceed to Step 4.

Step 4: Commit (or Save Profile for Later)

  1. Click ✅ Commit Import to run the same SQL for real (with a confirmation prompt).
  2. Click 💾 Save Configuration Profile to save your separator + mapping as a JSON file so you can reload it instantly next time.
  3. Click Download Summary to get a text file with the import results.

💾 Saved Configuration Profiles

Profiles save your separator choice and header mapping so you don't have to reconfigure them every time the VA sends files in the same format.

How to Save a Profile

  1. Complete Steps 1–3 (configure separator, parse file, map headers, generate SQL).
  2. Click 💾 Save Configuration Profile on the Step 3 panel.
  3. The profile is saved as a JSON file in the workbench_profiles/ directory on the server.

How to Load a Profile

  1. Select a profile from the Load Profile dropdown at the top of Step 1.
  2. Click Load. The separator radio button and header mapping are restored.
  3. Select your data file and SQL script, then click Parse & Preview. The auto-mapping will use your saved column assignments.
ℹ Profile Location
Profiles are stored in workbench_profiles/ under the iDash root directory. They are plain JSON files. You can copy them between servers or delete them by removing the file.

⚙️ What Actually Happens Under the Hood

1. File Parsing

  • If the file is .xlsx, it's read via ClosedXML (MIT License) and converted to delimited text using your chosen separator. Scientific notation in numeric cells is preserved as plain integers.
  • If the file is .txt or .csv, it's read as-is with BOM auto-detection and re-encoded as clean UTF-8 without BOM.
  • The first row is treated as column headers. All subsequent rows are data.

2. SQL Rewriting

Two targeted regex replacements are made to the selected SQL script:

WhatBeforeAfter
FIELDTERMINATOR FIELDTERMINATOR = '\t' FIELDTERMINATOR = '|' (or whatever you chose)
CREATE TABLE dbo.AssetFileRaw 16 hardcoded column definitions Columns rewritten in file order, using your mapped names. Unmapped columns get dummy names (_skip_N) so BULK INSERT still has the right column count.

The rest of the SQL script is unchanged. The INSERT INTO dbo.assettemp mapping, the normalization logic, the deduplication, the location sync — all of it runs exactly as written. Only the landing zone (AssetFileRaw) and the separator are adjusted.

3. Transaction Isolation

  • Test Run: The entire SQL execution is wrapped in BEGIN TRAN ... ROLLBACK. Every INSERT, UPDATE, and DELETE is undone.
  • Commit: Same transaction wrapper, but COMMIT instead of ROLLBACK.
  • Both modes capture #ImportStats and #PreviewLog before the transaction ends.

4. Profile Persistence

Profiles are saved as plain JSON files in workbench_profiles/. No database tables, no registry entries, no hidden state. Copy the file to another server and it works immediately.

🛠 Troubleshooting FAQ

"My columns look shifted — data is in the wrong fields"

Cause: Wrong separator selected.
Fix: Check the actual file. Open it in Notepad and look for the delimiter character between columns. If you see | between values, select Pipe. If values are separated by invisible characters, it's probably Tab. Re-parse after changing the separator.

"I see blank/NULL in columns that should have data"

Cause: Header mapping mismatch. The file column wasn't mapped to the correct database column, or was set to "— Skip —".
Fix: Go back to the Header Mapping section and verify each file column is mapped to the right AssetFileRaw column. Re-apply the mapping.

"The test shows zero inserts when I expected thousands"

Cause: The data already exists in the database. Both va_dbupdate.sql and va_dbupdate_upsert_enrich.sql skip assets that already exist (by name + company ID or by RFID tag).
Fix: This is expected behavior on a re-import. If you're importing to a fresh database, check that the company mapping resolved correctly (station number → company ID).

"BULK INSERT failed with a syntax or conversion error"

Common causes:
  • Wrong row terminator: The SQL script uses ROWTERMINATOR = '0x0a' (Unix LF). If the file has Windows CRLF line endings, change it to '0x0d0a' in the SQL script.
  • Encoding mismatch: The script uses CODEPAGE = '65001' (UTF-8). If the file is ANSI-encoded, remove the CODEPAGE parameter.
  • Extra columns: The file has more columns than the AssetFileRaw table. Make sure every file column is either mapped or set to "— Skip —".

"I saved a profile but the dropdown is empty"

Fix: Click Refresh File Lists. The profile dropdown only scans the workbench_profiles/ directory on page load and manual refresh.

"Can I use this with the enrichment script?"

Yes. The workbench works with any .sql script — va_dbupdate.sql, va_dbupdate_upsert_enrich.sql, va_cmr_recovery.sql, or any custom script you write. As long as the script contains FIELDTERMINATOR and CREATE TABLE dbo.AssetFileRaw, the workbench can rewrite both.

✅ Independence Guarantee
The workbench is completely independent from the standard import page and the automated pipeline. Nothing you do on the workbench page affects either of those systems. They continue to work exactly as they always have, using their own hardcoded tab separator and column definitions.

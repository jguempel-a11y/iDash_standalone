Module Purpose

Provides administrators a historical view of all ENNX scan sessions grouped by Site → User → Date. Each row represents a unique scan session for a specific user on a specific day at a specific site. Clicking Preview on any row generates the full ENNX text file for that session and displays the asset grid, allowing download or email directly from history.

Filter Controls

ControlBehavior
Site dropdownFilters the session list to a specific VA station. Only sites that have actual inventory activity (lastinventoried IS NOT NULL, lastmodifiedby IS NOT NULL) appear. Changing the site also refreshes the User dropdown.
Filter by User dropdownNarrows the session list to a single technician. Populates dynamically from the current data (respects the Hide Empty Users checkbox).
From / To date rangeRestricts sessions to those within the specified date window. Both fields trigger an immediate postback on change.
Hide rows with no userExcludes sessions where lastmodifiedby is NULL or blank. Checked by default.

Session Grid — Site → User → Date Hierarchy

As of 2026-04-13, the session grid displays four columns: Site, User, Date, and Assets. Rows are sorted alphabetically by site, then by user, then newest-date-first within each user. This allows leadership to immediately identify which technicians scanned at which locations on any given day.

Clicking Preview opens the ENNX text file and asset detail grid for that exact Site + User + Date combination. The preview header reads: Site — User — Date (N assets).

Preview & Export Actions

  • Download ENNX
    Downloads the ENNX text file for the currently previewed session.
  • Email ENNX
    Sends the ENNX text of the previewed session to all configured recipients.
  • Export ENNX to CSV
    Exports the asset detail grid of the previewed session as a CSV file.
  • Batch Email Everything
    Emails all displayed sessions in bulk to configured recipients.

Technical Operation

All logic is self-contained in ennxhistory.aspx as inline server code (no separate code-behind). The core data source is dbo.v_asset joined to dbo.location and dbo.company. The GetSqlData() method returns all matching rows and the in-memory LINQ grouping in LoadSessions() builds the Site → User → Date summary. Site filtering hits the DB directly via companyid = @SiteId parameter.

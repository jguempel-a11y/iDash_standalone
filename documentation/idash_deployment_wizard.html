💡 Why This Wizard Was Created & Why It Is Needed

Deploying enterprise asset tracking systems across Veterans Affairs (VA) medical centers, VISN networks, and regional field teams has historically been a high-friction, error-prone endeavor. Traditional installations required manual database administration: executing ad-hoc SQL scripts in SQL Server Management Studio (SSMS), checking table schemas by hand, verifying IIS application pool permissions, configuring connection strings, and manually populating facility stations.

A single missing table index, unmapped database view, or restrictive folder permission could cause runtime failures during live technician scanning sweeps in the field.

The iDash Deployment & System Wizard (deploy_idash.aspx) solves this by transforming the entire installation, schema provisioning, multi-site configuration, and system hardening into an autonomous, single-screen, guided pipeline. It delivers guaranteed 100% clean standalone operation, verifies every host dependency before traffic is accepted, and issues an immutable, verifiable certificate of production readiness.

📅 Operational Scenarios: When to Use the Wizard

🚀 Initial Server Commissioning

When provisioning a brand new Windows Server VM, bare-metal server, or mobile inventory cart. Probes IIS, provisions the database catalog, and sets up initial facility stations.

⚙ Software Upgrades & Migrations

After upgrading the iDash codebase. Step 2 automatically synchronizes schema tables and reporting views without dropping tables or risking historical inventory data.

🏢 Adding New Facilities / Stations

When onboarding a new VA Medical Center or divisional substation (e.g. Station 528 Upstate New York). Instantly configures tenant data isolation, API keys, and MQTT topics.

🔄 Disaster Recovery Verification

After restoring a SQL backup or recovering from a hardware event. Step 5 runs non-destructive CRUD write probes and verifies read/write integrity in seconds.

🔒 Security Credential Rotation

Securely update the primary idashadmin administrative password using modern PBKDF2 with SHA-256 salted HMAC cryptographic hashing.

📋 Audit & Compliance Certification

Execute the automated 5-point validation suite to generate an on-screen verified readiness certificate stamped with the server hostname, UTC timestamp, and sub-millisecond latencies.

1⚙ The 5-Step Automated Pipeline

1

Step 1: Host Environment & Prerequisites Check

✓ Non-Destructive Probes
Executes automated, real-time diagnostic probes against the host Windows operating system and IIS hosting environment:

💻 Host Operating System & Machine Identity

Verifies 64-bit Windows OS build, server hostname, and processor architecture.

⚙ .NET Framework & CLR Runtime

Validates that the 64-bit ASP.NET 4.8 CLR runtime (v4.0.30319) is active and running under an isolated application pool.

📁 File System Write Permissions

Confirms the worker process (IIS_IUSRS) has full read/write access to App_Data/, logs/, and config directories.

🗃 SQL Server Connectivity & Engine

Tests the ADO.NET connection string, verifies SQL Server version (e.g. SQL Server 2022), and measures connection latency.

💾 Storage Volume Free Space

Ensures sufficient disk capacity is available on the hosting volume (minimum 10 GB recommended for log and database backups).

2

Step 2: Database Initialization & Schema Engine

⚙ Pure Standalone Schema
Audits the SQL database catalog against the pure standalone iDash baseline and provides automated, non-destructive migrations:
  • 26 Pure Core Tables: Verifies core tables exist, including asset, location, company, fixedreader, printjob, printtemplate, printerrouting, EnnxLiveSession, and sysuser.
  • 7 Modern Reporting Views: Automatically compiles high-speed views (dbo.v_asset, dbo.v_asset_extended) with optimized left-joins for instant reporting across hundreds of thousands of equipment records.
  • Zero Legacy Dependencies: Ensures clean standalone operation with no orphaned tables or outdated columns.
  • Safe Non-Destructive Migrations: Clicking Deploy / Refresh Schema automatically provisions any missing tables, columns, or indexes without dropping existing data or interrupting operations.
3

Step 3: Facility & Multi-Site Provisioning

🏢 Station Data Isolation
Manages VA Medical Centers, Station numbers, isolated client application keys (dbo.clientapp), and MQTT topic hierarchies:
  • Facility Inventory Roster: Lists all registered facilities (e.g., Station 512 Baltimore, 517 Beckley, 540 Clarksburg, 581 Huntington, 613 Martinsburg, 649 Prescott) with real-time asset counts per station.
  • API Client Key Generation: Automatically provisions an isolated clientapp credential token for each station to restrict handheld scanner access.
  • MQTT Topic Scoping: Assigns facility-specific MQTT pub/sub namespaces (e.g. mqtt_512_baltimore) so fixed portal readers only stream detections to their authorized station.
  • Instant Provisioning Form: Allows administrators to add a new VA Station # and Facility Name in one click with full database referential integrity.
4

Step 4: Administrator Account & Security Hardening

👤 RBAC & Cryptographic Storage
Configures and hardens the primary system administrator account (idashadmin):
  • PBKDF2 SHA-256 Hash Storage: Passwords are encrypted using 10,000 iterations of PBKDF2 with unique cryptographic salt and SHA-256 HMAC — ensuring government-grade credential security.
  • System Alert Notifications: Sets the primary administrative email recipient for automated error alerts, scan session summaries, and scheduled inventory reports.
  • Operator Profile: Configures administrator first and last name for audit logging on database changes.
5

Step 5: End-to-End System Validation Suite & Certification

🎉 100% Production Certified
Executes five automated integration probes simulating actual field usage to prove end-to-end operational readiness:
Diagnostic Probe Typical Latency Verification Purpose
Database Read & Row Enumeration < 100ms Queries full asset catalog (e.g. 584,053 items) to verify non-blocking read concurrency.
Database Write Probe (CRUD Transaction) < 15ms Inserts and immediately removes a synthetic probe record to verify transactional commit authority.
Asset Master View Resolution (dbo.v_asset) < 10ms Resolves top 100 joined records to confirm foreign keys and view indices are healthy.
RFID Scan API Endpoint (scan_api.aspx) < 1200ms Simulates an incoming HTTP REST scan packet from Zebra handhelds to verify API ingest.
MQTT Broker Service (Port 1883) < 5ms Opens a TCP socket to localhost:1883 to verify the fixed reader streaming daemon is active.

2🛠 Technical Architecture & REST Actions

The wizard executes stateless, lightweight AJAX actions handled directly by deploy_idash.aspx.cs:

Action Parameter HTTP Method Backend Method Functional Payload
?action=check_env GET CheckEnvironment() Returns OS, CLR, disk space, folder write permissions, and SQL latency.
?action=check_db_status GET CheckDatabaseStatus() Audits table/view counts, live asset tallies, and schema health.
?action=deploy_schema POST DeploySchema() Executes non-destructive table migrations, view creation, and index tuning.
?action=get_facilities GET GetFacilities() Returns array of registered stations, asset counts, client keys, and MQTT topics.
?action=provision_facility POST ProvisionFacility(...) Provisions a new VA station number, facility name, and isolated client key.
?action=update_admin POST UpdateAdmin(...) Updates admin password via PBKDF2 hash and updates notification email.
?action=run_tests GET RunDiagnosticTests() Executes the 5 integration test probes and generates certification metadata.

🔍 Data Research Portal

Database Connected WebMethod JSON API

The Data Research Portal (va_data_research.aspx) is a high-capacity, dual-mode asset investigation tool for administrators and field leads. It provides both a flat-file spreadsheet viewer (for inspecting uploaded Excel/CSV data) and a live SQL search engine (for querying the iDash database in real time). It is the go-to tool for debugging missing attributes, tracking down specific assets, cross-referencing inventory data, and performing ad-hoc data quality investigations.

Flat File Viewer — How It Works

Click the file picker to select any .xlsx, .xls, or .csv file from your local device. On upload, the server reads the file using the NPOI library (for Excel formats) or a custom CSV parser, converts it to a DataTable, and renders the result as a fully interactive HTML grid.

  • All column names are automatically extracted from the first row of the file.
  • The column chooser panel lets you show/hide any column to focus on specific fields.
  • The per-column search filter bar allows instant client-side filtering without reloading from the server.
  • Rows are rendered with alternating styles and hover highlights for readability.
⚠ Note: Flat file uploads are read-only. The tool displays the data for inspection only — it does not write any uploaded file data to the SQL database. Use the Database Update or SQL Upload tools for import operations.

Live SQL Search — How It Works

On page load, the tool auto-loads the 200 most recently modified asset records. Entering a search term and clicking Load / Search (or pressing Enter) triggers the SearchSqlAssets [WebMethod], which runs a parameterized SQL query against dbo.asset.

Search Query Logic

The search term is matched against multiple fields simultaneously using LIKE pattern matching:

SELECT TOP (@top) *
FROM dbo.asset
WHERE description LIKE @like
   OR name         LIKE @like
   OR rfidtag      LIKE @like
   [AND companyid = @site]  -- optional site filter
ORDER BY lastmodified DESC

This means a single search term will match against:

  • description — the human-readable asset description
  • name — the EE barcode number
  • rfidtag — the RFID EPC hex string

Site Filtering

If a site is selected from the Site dropdown before searching, an additional AND companyid = @site clause is injected, restricting results to only assets belonging to that facility. This is critical for multi-site environments where the same barcode prefix may exist at different stations.

Column Chooser

The rendered grid includes all columns from the asset table by default, but a configurable set of default visible columns is pre-defined in the code-behind: 

id, name, description, lastobservedlocation, lastobservedtime,
listvalue1, text6, text8, text16, text19,
lastmodified, lastmodifiedby, lastinventoried, companyid, locationname

Users can toggle any column on or off using the Column Chooser panel, and the selection persists within the session. A built-in column search box filters the chooser list for tables with many fields.

DataTables-Style Server API

The flat file viewer also exposes a secondary [WebMethod] endpoint (GetDataTableData) that accepts DataTables-compatible parameters: start, length, sortCol, sortDir, and a searchCols array for per-column filtering. This enables large datasets to be paged and filtered server-side without loading the full file into the browser.

Access & Security

This module is restricted to users with the data_research tile key in their iDash TileAccess profile. It is typically granted to administrators and field leads only. See User Management for details.

All SQL queries are fully parameterized using SqlParameter — user search input is never interpolated directly into any SQL string. The [WebMethod] endpoints are accessible only within the same IIS application and do not expose unauthenticated external API access.

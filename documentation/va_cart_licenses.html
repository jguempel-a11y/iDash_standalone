⚠ Essential Cart Deployment & Troubleshooting Guide

🔍 Issue 1: Blank Screen / White Page After Login (HTTP 500)

When installing or cloning a new cart, logging into iDash might authenticate successfully but return a totally blank white screen.

Cause: In C:\inetpub\wwwroot\iDash\appsettings.json, the AuthServerUrl is configured with the originating computer's hostname instead of localhost:

// WRONG (Causes timeout/IDX20803 failure): "AuthServerUrl": "http://BECKLEYCART1" // CORRECT (Required for standalone carts): "AuthServerUrl": "http://localhost"

Always verify appsettings.json has "AuthServerUrl": "http://localhost", then run iisreset.

🔐 Issue 2: Invisible Unicode U+202A in Windows MAC Address Copy

When copying a MAC address from the Windows Network Adapter Details dialog, Windows injects an invisible Unicode left-to-right character (\u202A) immediately preceding the MAC address.

When the vendor signs the license key with this string, pasting the key into a text editor that normalizes unicode will invalidate the cryptographic RSA signature check!

Solution: Always copy the base64 keys directly from this page or from the Cart License Reference Tool, which preserves the exact binary payload expected by the validation service.

🔧 Issue 3: Validating the Installed Key in SQL Server

To check what key is currently registered in the database on any cart, open PowerShell as Administrator and run:

$conn = New-Object System.Data.SqlClient.SqlConnection("Server=localhost\sqlexpress;Database=iDash;Integrated Security=True") $conn.Open() $cmd = $conn.CreateCommand() $cmd.CommandText = "SELECT licensekey FROM dbo.applicationsetting" $key = $cmd.ExecuteScalar() $conn.Close() $json = [System.Text.Encoding]::UTF8.GetString([Convert]::FromBase64String($key)) Write-Host "Active License Payload:" -ForegroundColor Cyan Write-Host $json

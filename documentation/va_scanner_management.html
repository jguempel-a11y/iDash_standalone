📡 Scanner & Device Registration Management

Understanding, auditing, and managing RFID scanner registrations in the iDash dbo.scanner table. Includes compliance tracking, safe cleanup procedures, and impact analysis.

What is this? iDash automatically registers RFID handheld scanners (Android app) when they connect and sync. Each device gets a unique deviceid fingerprint. The compliance page in iDash counts these registrations to ensure you stay within your license limits.

1 Table Schema: dbo.scanner

Column Type Nullable Description
id int NO Primary key (identity)
companyname varchar(100) NO Site/company name at time of registration (e.g. "613 Martinsburg")
deviceid varchar(100) YES Unique device fingerprint (hardware-generated hex string)
inactive bit YES Soft-delete flag — 1 = deactivated, 0 = active
description varchar(500) YES Optional description or label for the device
lastseen datetimeoffset YES Timestamp of the last sync from this scanner

2 Dependency & Impact Analysis

Safe to delete. The scanner table has no foreign key references from any other table. Deleting rows will not cascade or break any relationships.

What happens when you delete scanner records:

Area Impact
Foreign keys ✓ None — no other table references scanner
Asset data ✓ No impact — assets are in dbo.asset, completely independent
Scan sessions ✓ No impact — scan data is stored in dbo.audit and history tables
User accounts ✓ No impact — dbo.sysuser is independent
Scanner functionality ✓ Scanners auto-re-register on next sync — no manual re-setup needed
Compliance count ⚠ Resets to 0 until scanners reconnect (temporary)
Last seen history ⚠ Lost — you won't know when a device last synced until it syncs again

Related tables (NOT affected by scanner deletion):

  • dbo.asset — has vtaggpsdeviceid but this is a GPS device ID, unrelated to scanner registrations
  • dbo.session — tracks login sessions by ticket ID, not scanner devices
  • dbo.clientapp — API client credentials for app authentication, separate from scanner registration

3 Diagnostic Queries

3.1 — List all registered scanners

SELECT
    id,
    companyname   AS [Site],
    deviceid      AS [Device Fingerprint],
    inactive      AS [Inactive],
    description   AS [Label],
    lastseen      AS [Last Sync]
FROM dbo.scanner
ORDER BY lastseen DESC;

3.2 — Count active scanners per site

SELECT
    companyname   AS [Site],
    COUNT(*)      AS [Total Devices],
    SUM(CASE WHEN inactive = 0 OR inactive IS NULL THEN 1 ELSE 0 END) AS [Active],
    SUM(CASE WHEN inactive = 1 THEN 1 ELSE 0 END) AS [Inactive],
    MAX(lastseen) AS [Most Recent Sync]
FROM dbo.scanner
GROUP BY companyname
ORDER BY companyname;

3.3 — Find stale scanners (not seen in 90+ days)

SELECT
    id, companyname, deviceid, lastseen,
    DATEDIFF(DAY, lastseen, GETDATE()) AS [Days Since Sync]
FROM dbo.scanner
WHERE lastseen < DATEADD(DAY, -90, GETDATE())
   OR lastseen IS NULL
ORDER BY lastseen;

3.4 — Verify no FK dependencies exist

-- Returns empty if safe to delete
SELECT fk.name AS FK_Name, tp.name AS ParentTable
FROM sys.foreign_keys fk
INNER JOIN sys.tables tp ON fk.parent_object_id = tp.object_id
INNER JOIN sys.tables tr ON fk.referenced_object_id = tr.object_id
WHERE tr.name = 'scanner' OR tp.name = 'scanner';

4 Cleanup Scripts

Always back up first. Run SELECT * FROM dbo.scanner and save the results before deleting, so you have a record of what was registered.

4.1 — Delete all scanner registrations (full reset)

-- Full reset: removes all device registrations
-- Scanners will auto-re-register on next sync
DELETE FROM dbo.scanner;

-- Verify
SELECT COUNT(*) AS [Remaining] FROM dbo.scanner;

4.2 — Delete scanners for a specific site

-- Remove only scanners registered to a specific site
DELETE FROM dbo.scanner
WHERE companyname = '613 Martinsburg';  -- change to your site

4.3 — Delete stale scanners only (90+ days)

-- Remove only scanners that haven't synced in 90+ days
DELETE FROM dbo.scanner
WHERE lastseen < DATEADD(DAY, -90, GETDATE())
   OR lastseen IS NULL;

4.4 — Soft-deactivate instead of delete

-- Mark as inactive without removing from the table
-- Useful if you want to keep the record but exclude from count
UPDATE dbo.scanner
SET inactive = 1
WHERE id = 3;  -- change to target scanner ID

4.5 — Delete a specific scanner by device ID

-- Remove one specific scanner
DELETE FROM dbo.scanner
WHERE deviceid = '73ad1b8535d2fb54';  -- change to target device ID

5 How Scanner Registration Works

  1. User opens the iDash Handheld Android app on an RFID scanner
  2. App authenticates via the iDash API using the clientapp credentials
  3. On first sync, iDash generates a unique deviceid from the device hardware
  4. A row is inserted into dbo.scanner with the company name and current timestamp
  5. On subsequent syncs, the lastseen timestamp is updated
  6. The compliance page reads COUNT(*) WHERE inactive = 0 to show active device count
Auto-recovery: If you delete all scanner records, the count will drop to zero. As soon as each scanner syncs again, it will automatically re-register itself. No manual intervention is needed on the scanner side.

6 Compliance Notes

  • The scanner compliance page in iDash shows how many active devices are registered vs. your license limit
  • Deleting stale/unused scanner records is a valid way to bring the count back into compliance
  • If a scanner hasn't synced in 90+ days, it's likely no longer in active use and safe to remove
  • The inactive flag provides a soft-delete alternative — the device stays in the table but doesn't count toward the license

Security & Audit Trail

  • All updates use parameterized SQL — no SQL injection risk.
  • Strict field whitelist (Dictionary<string, int> column → max varchar) — non-whitelisted POST keys silently ignored.
  • String values truncated to max column length (e.g. 500 chars for text, 50 for status).
  • Every save sets lastmodified = SYSDATETIMEOFFSET() and lastmodifiedby to the logged-in user.
  • UserManager.BuildSiteFilter appended to UPDATE WHERE — users can only edit assets in their assigned sites.
📌 Hybrid design: iDash handles 20+ frequently updated fields. Full lifecycle ops (location assignment via locationid, parent/child, RFID enrollment, V-Tag config) remain in iDash. Use “Open in iDash” for anything not editable here.

Offline Sync & Data Quality Updated 08/21

Understanding "New Asset Found (Offline Sync)" stubs and the VistA enrichment pipeline.

What Is a Stub Record?

When a TagTeam scanner scans in offline mode and later syncs, if no matching asset is found in dbo.asset, a stub record is auto-created so the scan is never lost:

FieldStub ValueSource
name613 EE12345Scanner (barcode)
descriptionNew Asset Found (Offline Sync)System placeholder
text6 (location)Where it was scannedScanner
text13 (tech)Employee ID who scannedScanner
lastinventoriedExact scan timestampScanner
rfidtag, text8 (CMR), text1 (Manufacturer)NULL / emptyNot available until VistA import
✅ These are not errors. Stubs represent real physical assets scanned before VistA had their record. Once entered into VistA and imported, the enrichment pass in vista_import_production.sql automatically fills in description, RFID tag, CMR, manufacturer, model, serial — while preserving the original lastinventoried timestamp.

Barcode Validation (New 08/21)

Valid format: {3-digit station} + space + EE + digits only — e.g. 613 EE12345. Invalid barcodes are rejected with INVALID FORMAT before any DB record is created.

Rejected patterns: trailing letters (613 EE8051J), letter in number (613 EE80G52), wrong prefix (613 ES41881), single E (613 E72190), location scanned as asset (SP102-519), concatenated barcodes, non-digit station code.

Duplicate Prevention — Upsert Logic (New 08/21)

  • TagTeam Sync: Checks WHERE name = @Name across all companyids. If found, updates scan metadata instead of inserting a new stub.
  • VistA Import: NOT EXISTS guard uses name alone (globally unique due to station code prefix).

Applies to: vista_import_production.sql, vista_import_preview.sql, and the Import Workbench. Raw SQL dumps must be verified manually.

  • ~21 scanner error stubs with invalid barcode formats — deleted
  • ~28 duplicate stubs (673xxx range) with enriched VistA counterparts (934xxx range) — merged, stubs deleted

Server-Side Architecture Notes

  • Pagination: DataTables server-side mode. SearchAssets [WebMethod] accepts draw/start/length/search/sort + custom filters. Queries v_asset with OFFSET...FETCH NEXT. KPI runs in a parallel count query in the same call.
  • Detail API: Page_Load intercepts ?api= before normal ASP.NET lifecycle and routes to HandleDetailApi().
  • Date handling: JavaScriptSerializer emits /Date(timestamp)/. Frontend regex /\/Date\((-?\d+)\)\// handles positive and negative timestamps.
  • Column reordering: On drop, ALL_COLS is spliced, DataTables destroyed and reinitialized, all custom renderers preserved.

📡 Batch Mode Scanning (Offline Inventory Guide)

In iDash Standalone, Batch Mode Scanning is the Offline Site Inventory operation. It allows technicians to conduct comprehensive room inventories in areas with zero Wi-Fi or cellular connectivity (such as basements, shielded wards, and remote clinics).

ⓘ How Standalone Offline Mode Works:
iDash is built as a progressive web architecture backed by a client-side Service Worker. You load your room manifest while at your cart or connected to the network. Once loaded, you can walk anywhere disconnected — the scanner matches tags instantly in local memory and queues all results. When you reconnect, one tap on Commit Scans synchronizes your records directly with the iDash master database.
💻 Phase 1: Preload at the Cart / Connected Station
1 Sign In to iDash on the TC53
At the scanning cart or while connected to Wi-Fi/MiFi, open the iDash Inventory application (/va_inventory.aspx). Sign in with your assigned site operator account. This binds your session to your facility site code.

Technician Sign In — authenticates operator and locks site assignment.

Ready state — scanner is armed and awaiting room barcode scan.

2 Scan or Select Room Location Tag
Scan the room's 2D/1D barcode tag using the bottom trigger (barcode imager) or select the location from the dropdown and tap Load Room.
The system instantly loads all expected assets into device memory.

Manifest loaded — all expected room assets are held in memory for offline scanning.

💡 Offline Assurance: Once the room is loaded (e.g., SPBC104-BD. 1 — 1,771 Assigned to Room), you can safely walk into any Wi-Fi dead zone. The full inventory database for this room is cached locally.
📱 Phase 2: Offline Sweeping & Real-Time Matching
3 Pull the RFID Trigger (Top Trigger) to Sweep
Walk through the room squeezing the top trigger on the RFID sled. As RFID tags enter range, the device beeps and updates the live counters in real time — completely offline.

Live RFID sweep — green badges indicate expected assets found; blue badges indicate items assigned elsewhere.

4 Status Color Coding Reference
iDash organizes every tag detected during an offline sweep using clear, instant color codes:
Status Badge Meaning Action Required
✔ Found Expected in this location and physically verified. None — inventory verified.
○ Not Found Expected in this room, but tag has not yet been detected. Continue sweeping or flag for follow-up.
↻ Move Here? Valid facility asset found here, but assigned to a different room. Decide whether to reassign to this room on commit.
? Unknown RFID tag detected that does not match your facility's database (alien/vendor tag). Ignored automatically on commit.
💾 Phase 3: Resolution & Database Commit
5 Handle Misplaced Items (Commit Modal)
When you tap Commit Scans, if any misplaced (blue) items were found in the room, iDash presents an autonomous resolution dialog:

Commit resolution dialog — choose whether to move misplaced assets to this room.

  • ✔ Commit Expected Only: Leaves misplaced assets assigned to their prior locations, verifying only the expected room assets.
  • ↻ Commit All & Move Misplaced to this Room: Automatically reassigns the misplaced equipment to the currently scanned room in the database.
6 Sync Results Back to Master Database
When you return to your cart or re-enter network range, tap the commit confirmation. The client pushes the session to the standalone iDash SQL database:

Commit complete — all verified records are merged into the iDash database.

✅ Ready for Next Room: Tap Clear / New Scan or scan the next door barcode tag to begin your next room inventory immediately.

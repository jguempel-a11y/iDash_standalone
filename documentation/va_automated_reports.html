How It Works

Two subsystems share one email engine.
SubsystemWhat It DoesWhen It Fires
Alert TriggersReal-time email/SMS for system events (DB failure, print crash, folder missing, audit triggered)Immediately when the condition occurs inside the relevant page handler
Automated Daily ReportsScheduled batch email with ENNX .txt extract + Excel grid — one email per site with scans todayDaily at configured time via Windows Task Scheduler hitting va_report_automator_runner.aspx
ℹ Shared engine: Both subsystems call EmailHelper.SendEmail(). SMTP settings, From Name, and From Email apply to all iDash outgoing email — ENNX exports, Tag Audit, diagnostics, inventory reports, and daily reports. No per-feature email identity exists.
⚠

Section 1 — Master Switch

Globally enables or disables the daily runner. Does not suppress in-page alert triggers.

Controls the SmsAlertsEnabled key in web.config.

  • OFF: va_report_automator_runner.aspx exits immediately — no emails sent.
  • ON: runner checks recipients, finds active sites, sends per-site reports.
  • Alert triggers fire from their own page code-behind regardless of this switch — they check their individual Alert_* keys.
👥

Section 2 — Global Recipients

Default destination for all alerts and reports without custom routing.

Enter one address per line. Saved to ~/config/email_recipients.json (not web.config) so changes never trigger an IIS app pool recycle.

✅ Session-safe: Changes write to a JSON file. EmailHelper reads JSON first, falls back to legacy web.config EmailRecipients key, and auto-migrates to JSON on first use. No user sessions are disrupted.
FormatUse Case

Section 6 — Per-Site Email Routing & Station Alerts

Individual station recipients, enable/disable alert toggles, and centralized SMTP relay.

Designed for multi-facility VISN deployments where multiple stations (e.g. Baltimore, Beckley, Clarksburg, Huntington, Martinsburg) share one iDash instance or central database, but require independent report recipients and notification control.

Key Features

  • Database Auto-Discovery: Sites are queried live from the database company table (dbo.company columns: id, name — e.g. 512 Baltimore, 517 Beckley, 540 Clarksburg, 581 Huntington, 613 Martinsburg). Any new site added to the company table is automatically discovered on page load without manual code changes.
  • Station Enable / Disable Alert Switch: Each station card has an independent toggle switch. If toggled OFF, daily ENNX reports and automated emails for that site are completely suppressed and skipped by the runner engine, even if scan sessions occurred that day.
  • Dedicated Station Recipients: Enter semicolon- or comma-separated email addresses for each station's supervisors or logistics leads. When populated, that station's daily report is dispatched only to its designated team.
  • Global Fallback: If a station's recipient field is left blank, the runner automatically falls back to the Global System Recipients (Section 2).
  • Centralized SMTP Authentication: All outbound emails authenticate through one central M365 or Exchange account (configured in Section 4). This eliminates SendAsDenied (5.2.252) permission errors that occur when attempting to send from differing station addresses.
  • Session-Safe JSON Storage: Per-site configurations and toggle states are saved to ~/config/site_email_config.json, avoiding IIS application pool recycles.
ℹ JSON Structure in ~/config/site_email_config.json: 
[
  {
    "CompanyId": 2,

Section 7 — Windows Task Scheduler Setup

How to wire up the daily runner to fire automatically each evening.
Open Task Scheduler (taskschd.msc) on the iDash server.
Click Create Basic Task. Name it e.g. iDash Daily ENNX Report.
Set trigger: Daily, start time 7:00 PM (or after last TagTeam scan session).
Set action: Start a program — curl.exe with argument: http://localhost/iDash/va_report_automator_runner.aspx
Or use PowerShell: Invoke-WebRequest -Uri "http://localhost/iDash/va_report_automator_runner.aspx" -UseBasicParsing
Run as: SYSTEM or a service account with IIS read permissions. Check "Run whether user is logged on or not."
Test: right-click task → Run. View the plain-text response for per-site results.
🔒 Security: The runner URL has no login check — restrict to localhost/internal IP via IIS IP Restrictions or a web.config allow rule. Do not expose it to the internet.

Section 8 — Runner Engine Details

How va_report_automator_runner.aspx builds, resolves, and sends reports.

Per-Site Execution Pipeline

  1. Discover Active Sites: Scans the database for assets scanned on the specified run date (defaults to today; testable via ?date=YYYY-MM-DD). Groups assets by Station Number (text7).
  2. Check Site Enable Toggle: Queries SiteEmailConfigHelper.GetSiteEnabled(site). If toggled OFF, logs [DISABLED] Alerts & emails disabled for site {site}; skipped. and continues to the next site without sending.
  3. Render Subject: Reads the template from ~/config/report_automation.json (SubjectTitle) and substitutes {Site} and {Date}.
  4. Generate Local Backup: Saves the full ENNX text payload to C:\VA_RFID\ennx_live\saved\auto\auto_ennx_{site}_{date}.txt before transmitting email.
  5. Resolve Site Recipients: Checks SiteEmailConfigHelper.GetRecipientsForSite(site). If configured, uses the site-specific list; if empty, falls back seamlessly to EmailHelper.GetRecipients().
  6. Dispatch Email: Calls EmailHelper.SendEmailTo(recipients, subject, body, attachments) using the central SMTP account.

ENNX File Format

The .txt attachment follows the standard ENNX format:

ENNX
ID
{Location Group A}
{Asset Name 1}
{Asset Name 2}
{Location Group B}
{Asset Name 3}
***END***^{total line count}
  • Location resolved: LocationTagged → Locationname → Previous_Location (first non-empty, "MISSING" treated as empty)
  • Footer count includes: ENNX header + ID prefix + each location header + each asset name
  • ID prefix configurable via IdPrefix in ~/config/report_automation.json (default: ID)

🛠 Email & Routing Helpers Reference

Backend helpers located in App_Code/ that power all outbound communication.

EmailHelper (App_Code/EmailHelper.cs)

MethodPurpose
SendEmailTo(toAddresses, subject, body, atts)Sends email to an explicit list of destination addresses using the centralized SMTP relay credentials.
SendEmail(subject, body, atts)Sends to the global system recipient list. Reads all SMTP settings from web.config at call time.
SendDirectEmail(...)One-off to a single address with a 15-second timeout. Used by Support Request.
GetRecipients()Reads global recipients from email_recipients.json (with fallback to legacy web.config key).

GetFromEmailAddress()Returns SMTP_FromEmail from web.config.
GetDefaultSubject()Returns Default_EmailSubject from web.config (empty by default).

SiteEmailConfigHelper (App_Code/SiteEmailConfigHelper.cs)

MethodPurpose

SaveConfig(entries)Serializes updated site list back to site_email_config.json.

GetSiteEnabled(stationKey)Returns true if the site is enabled (defaults to true if unconfigured).

🕘 Location & Scan History

Database Connected Read-Only Rev. 2026-07-25

The Location & Scan History tool (va_previous_location.aspx) is a forensic location audit tool that lets field leads and administrators trace the complete movement history of any asset across a VA facility. It surfaces every recorded location event for an asset — combining real-time scan history from dbo.v_locationhistory with the asset's current and previous location fields from dbo.v_asset — so you can answer the question: "Where has this asset been, and when?"

Is This Page Still Relevant?

✓ Yes — this is a standalone, purpose-built tool with unique functionality.
It has not been merged into another page. It is distinct from the Asset Explorer (va_asset_api.aspx), which shows a single asset's current field values, and from the Data Research Portal (va_data_research.aspx), which does bulk field browsing. How to Use

Search Controls

ControlWhat to EnterSQL Parameter Mapped To
Search Box Asset barcode (e.g., 512 EE12345), partial barcode, serial number, or EIL group @q — matched with LIKE '%@q%' against a.name; exact match against a.text3 (serial) and a.text8 (EIL)
Site Dropdown Select a VA facility from the list, or leave as All Sites @site — appends AND a.companyid = @site when a specific site is selected

To Date End of date range (inclusive — automatically extends to end of day) @toDate — filters < DATEADD(day, 1, @toDate)
ℹ Tip — Leaving Search Empty: If you leave the search box blank and click Search, it returns the 2,000 most recent location events across all assets at the selected site and date range. This is useful for auditing recent movement activity in a given period without knowing a specific asset number.

Grid Interactions

  • Column Header Sort: Click any column header's ▲▼ arrows to sort ascending or descending. Toggle again to reverse. Numeric columns sort numerically; date columns sort chronologically.
  • Per-Column Filter Row: Each column has an inline filter text box below the header. Type to instantly narrow results without re-querying the server.
  • Column Chooser: Click the Columns button to open a checkbox panel. Toggle any column off to hide it from the grid. Useful on narrow screens or for focused investigation.
  • Record Counter: The Total Records pill updates live to reflect both the raw server result count and the post-filter visible count.

Maximum Results

The query is capped at TOP 2,000 rows ordered by scan date descending. If your search returns exactly 2,000 records, narrow by date range or a more specific asset identifier.

Current Loc (text6) a.text6 The current recorded location barcode (SP code) of the asset as of the last scan. This is the field updated by Tag Team Scan and similar workflows.
📌 Understanding the Three Location Fields
Each asset record simultaneously carries three location-related values. This is intentional — they represent different data sources:

• text6 — Scanner-assigned location: updated when a field tech scans the asset in a specific room via Tag Team Scan or Site Inventory
• lastobservedlocation — Fixed reader-assigned location: updated automatically by infrastructure readers; can disagree with text6 if the asset has moved since last manual scan
• text11 — Previous manual scan location: the value text6 held before it was last updated; enables single-step "undo" investigation

Technical Architecture

Rendering Model

This page uses a client-rendered JSON API pattern — no ASP.NET postbacks. On page load, the C# code-behind populates the Site dropdown via server-side data binding (LoadCompanies()). All subsequent searches are driven by the JavaScript doSearch() function, which calls the same page URL with ?api=search query parameters and receives a JSON response.

SQL Query

The core query joins the asset table to the location history view and applies up to three optional filter clauses:

SELECT TOP 2000
    a.name              AS barCode,          -- EE barcode / asset #
    a.description       AS descr,            -- equipment name
    a.text8             AS eil,              -- EIL group
    a.text3             AS serial,           -- serial number
    ISNULL(h.locationname, a.text6) AS scanLoc,   -- where scanned (history or current)
    ISNULL(h.timeseen, a.lastinventoried) AS scanDate,  -- when scanned
    a.text11            AS prevLoc,          -- previous location field
    a.lastobservedlocation AS lastObsLoc,    -- fixed reader observation
    a.text6             AS curLoc            -- current manual scan location
FROM dbo.v_asset a WITH(NOLOCK)
LEFT JOIN dbo.v_locationhistory h WITH(NOLOCK) ON a.id = h.assetid
WHERE (
    @q = ''
    OR a.name  LIKE '%' + @q + '%'   -- asset barcode / partial match
    OR a.text3 = @q                   -- exact serial match
    OR a.text8 = @q                   -- exact EIL match
)
-- Optional: AND a.companyid = @site           (when site != 0)
-- Optional: AND ISNULL(h.timeseen, ...) >= @fromDate
-- Optional: AND ISNULL(h.timeseen, ...) <  DATEADD(day, 1, @toDate)
ORDER BY ISNULL(h.timeseen, a.lastinventoried) DESC
⚠ NOLOCK Hint
Both table references use WITH(NOLOCK) (read uncommitted isolation). This allows the query to run without blocking active scan sessions and prevents scans from blocking history reads. The trade-off is that very recently written rows may occasionally appear or disappear during a scan burst. For audit purposes this is acceptable — results are consistent within a few seconds of any scan event.

Common Use Cases

ScenarioHow to Use
Asset was lost / can't be found Enter the EE barcode, leave dates blank. The most recent entries show the last known scanned locations in reverse chronological order. Compare "Location Scanned" vs. "Last Observed Loc" to detect if a fixed reader has recently seen it somewhere different than its last manual scan.
Audit where an asset was during a date range Enter the barcode and set a From / To date range. All movement events in that window will appear. Use the Scan Date column sort to trace the path chronologically.
EIL group movement audit Enter the EIL number (e.g., 04-06900) in the search box. Every asset in that EIL group's location history will appear. Filter the Location Scanned column to find items that moved between buildings.
Serial number lookup Enter the exact serial number. The query performs an exact match (a.text3 = @q). Useful when you have a serial but not the EE barcode.
Recent site-wide movement report Select a specific site from the dropdown, leave the search blank, set a date range (e.g., last 7 days). Returns up to 2,000 most recent movement events across all assets at that facility.

Access & Security

Access is controlled by the iDash tile-key model. Users must have the location_history tile key in their TileAccess profile. Typically granted to field leads, inventory supervisors, and administrators. See User Management for details.

All query parameters are passed via SqlParameter — no string interpolation is ever used for user input. The LIKE pattern is built server-side using '%' + @q + '%' parameterized form. No raw SQL errors are surfaced to the browser; all exceptions are caught and returned as { success: false, error: "..." }.

⚠ Read-Only: This tool performs no writes. All queries are SELECT only. It cannot modify location records, asset fields, or history entries. To correct a location, use Tag Team Scan or the iDash desktop application.

🖨 Printing Asset Labels

Integrations:
Database Connected Print Jobs New 07/24

Overview

The Asset Master page (va_asset_master.aspx) includes a built-in print feature that lets you submit RFID label print jobs for one or more assets. You select assets by entering EE numbers — the site prefix (e.g. 613 EE) is automatically detected from the selected site. Print jobs are routed through the iDash core API, which publishes to the Print Server via MQTT for automatic printing via BarTender.

🛠 Admin Setup: For template, printer, and multi-site configuration, see Print Administration.

How to Print Labels — Step by Step

Step 1: Navigate to Asset Master

From the iDash hub, click Asset Master, or navigate directly to:

https://<your-server>/iDash/va_asset_master.aspx

Step 2: Select a Site

Use the Site dropdown at the top of the page. The print feature needs to know which site you're printing for in order to determine the correct asset name prefix.

Step 3: Open the Print Modal

Click the 🖨 Print button in the header bar (left of the CSV/Excel export buttons). The print modal will open with:

  • Site Prefix — auto-detected (e.g. 613 EE for Martinsburg, 512 EE for Baltimore)
  • Asset Numbers — input field for entering the numeric portion
  • Print Template — dropdown of available label templates

Step 4: Enter Asset Numbers

Type the asset numbers (just the numbers — the prefix is added automatically). You can use any of these formats:

Format You Type Assets Generated
Single 312 613 EE312
Range 1-25 613 EE1 through 613 EE25 (25 labels)
Comma-separated 5, 12, 42 613 EE5, 613 EE12, 613 EE42
Mixed 1-5, 8, 12-15 10 labels: EE1–EE5, EE8, EE12–EE15
💡 Tip: You can press Enter in the numbers field instead of clicking "Load Preview".

Step 5: Preview

Click Load Preview. The system will look up all matching assets and display them in a table. This table uses the same columns as your main Asset Master grid — so if you've toggled or reordered columns, those settings carry over to the preview.

If some numbers don't match any asset, a yellow warning banner will list them (e.g. "Not found: 613 EE999").

Step 6: Select Template & Print

  1. Choose the label template from the Print Template dropdown.
  2. Click 🖨 Send to Printer.
  3. Confirm the dialog ("Send X asset(s) to the printer?").
  4. A green success banner confirms how many jobs were created.

The print jobs are now queued. The Print Server picks them up via MQTT within seconds and routes them to the configured printer via BarTender. Check the Print Admin Status tab to monitor job progress.

🛠 Server Configuration

For printing to work, the following components must be configured on the server. This section covers API credentials and file locations that a system administrator needs to set up.

Configuration Files

File Location What to Configure
web.config C:\inetpub\wwwroot\iDash\web.config API credentials (Client ID & Secret), API base URL, token URL
appsettings.json C:\inetpub\wwwroot\iDash\appsettings.json iDash API server settings: WebClientId, WebClientSecret, AuthenticationServer
printer_routing.json C:\idash_prints\printer_routing.json Maps BarTender template filenames to Windows printer names
.btw templates C:\idash_prints\*.btw BarTender label layouts referenced by the template table

API Credentials — iDash Side (web.config)

The iDash portal authenticates to the iDash API using OAuth 2.0 client credentials. These are stored in web.config under <appSettings>:

Key Purpose Example
UseRestApi Master switch to enable API integration true
iDash_ApiBase Base URL of the iDash REST API http://localhost/api
iDash_TokenUrl OAuth token endpoint http://localhost/connect/token
iDash_ClientId OAuth Client ID (must match iDash server config) v512
iDash_ClientSecret OAuth Client Secret (must match iDash server config) <generated-secret>
⚠ Important: The iDash_ClientId and iDash_ClientSecret must match the values configured in the iDash API application. These are used for machine-to-machine authentication — the iDash server authenticates to the iDash API using the OAuth client_credentials grant type. If these don't match, all API-driven features will fail.

API Credentials — iDash server Side

On the iDash API server, the corresponding credentials are configured in two places:

1. Database: applicationsetting table

The applicationsetting table (single-row) has two columns that define the web client credentials that the API server accepts:

Column Purpose Default
webclientid The client ID the API expects for introspection/auth idash.web
webclientsecret The client secret the API expects 901564A5-E7FE-42CB-B10D-61EF6A8F3654

To update via SQL:

UPDATE dbo.applicationsetting
SET webclientid = 'your_client_id',
    webclientsecret = 'your_client_secret';

2. Config File: appsettings.json

The iDash Web API application reads its config from appsettings.json (or overrides from the DB). The relevant keys under ConfigSettings are:

  • "WebClientId" — must match the webclientid in the database
  • "WebClientSecret" — must match the webclientsecret in the database
  • "AuthenticationServer" — the OAuth authority URL (e.g. http://localhost)

If values are not set in the config file, the API defaults to idash.web / 901564A5-E7FE-42CB-B10D-61EF6A8F3654.

Credential Flow Diagram

  iDash web.config                     iDash API
  ┌─────────────────────┐              ┌─────────────────────────────┐
  │ iDash_ClientId  │─── must ────▶│ webclientid (DB)            │
  │ iDash_ClientSec │    match     │ webclientsecret (DB)        │
  │ iDash_TokenUrl  │─── calls ───▶│ /connect/token endpoint     │
  │ iDash_ApiBase   │─── calls ───▶│ /api/* endpoints            │
  └─────────────────────┘              └─────────────────────────────┘

  OAuth Flow:
  1. iDash sends POST to TokenUrl with client_credentials grant
  2. iDash validates against webclientid/webclientsecret
  3. Returns Bearer token (cached until expiry)
  4. iDash includes Bearer token in all API requests

Database Tables for Printing

Table Purpose
dbo.template Maps template IDs to BarTender .btw filenames. The name column populates the template dropdown.
dbo.printjob Print job queue. Each row = one label to print. completed=0 means pending. The spooler sets it to 1 on success, -1 on failure.
dbo.asset Asset records — the id is stored as printjob.recordid so the spooler knows which asset data to inject into the label.
dbo.applicationsetting Global singleton settings table. Contains webclientid and webclientsecret for API authentication.

Print Spooler Prerequisites

For labels to actually print after being submitted from iDash:

  1. BarTender must be installed on the print server.
  2. Run_Bypass_Spooler.ps1 must be running (polls the printjob table every 3 seconds).
  3. printer_routing.json must map the template's .btw filename to the correct Windows printer name.
  4. .btw template files must exist in C:\idash_prints\ matching the template.filename values in the database.

For detailed print server setup, see 🖨 Print Server Setup & Troubleshooting.

Troubleshooting

Symptom Cause Fix
"No prefix configured" Selected site has no assets with EE in their name Select a site that has EE-named assets, or check the company name starts with a station number
"No templates found" The template table is empty or the query failed Insert at least one row into dbo.template with name and filename
Jobs created but labels don't print Spooler not running or printer not mapped Check Run_Bypass_Spooler.ps1 is active and printer_routing.json has the template mapped
API features failing (401/403) Client ID/Secret mismatch between web.config and iDash server Verify iDash_ClientId and iDash_ClientSecret match the values in the applicationsetting table

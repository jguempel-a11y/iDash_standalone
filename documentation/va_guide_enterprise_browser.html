Zebra Enterprise Browser & Config.xml Setup Guide

Field engineering standard operating procedure (SOP) for configuring Zebra TC53, TC58, and MC3300 mobile handhelds to run iDash in a locked-down, high-performance kiosk environment using Zebra Enterprise Browser v5.6+ and Config.xml.

Production Ready Enterprise Browser v5.6+ TC53 / TC58 / RFD40 / RFD90

1. Why Use Zebra Enterprise Browser?

While standard consumer mobile browsers (such as Google Chrome) can access iDash web pages, Zebra Enterprise Browser (EB) is the purpose-built industrial web runtime designed for rugged enterprise deployments. Running iDash inside Enterprise Browser provides significant operational advantages:

Feature / Requirement Standard Chrome Browser Zebra Enterprise Browser (with Config.xml)
Dedicated Kiosk Lockdown No — users can access browser address bars, open new tabs, and exit the application. Full Kiosk Mode — disables Android Status Bar, Home key, and Recent Apps button. Technicians cannot exit to the OS.
Full-Screen Immersive UI Address bar and navigation buttons occupy ~15% of vertical screen space. 100% Edge-to-Edge Display with zero browser chrome or address bars, maximizing table visibility.
Hardware Trigger RFID / Barcode Requires manual tap into inputs; virtual keyboard may pop up and obscure the screen. Direct DataWedge Hook (usedwforscanning = 1) with automatic SIP suppression on trigger pull.
Startup & Auto-Routing Manual typing of server URL or browser bookmark navigation. Auto-Launches Direct to iDash via <StartPage> immediately upon opening the app.
Hardware Acceleration & Caching May throttle background WebSockets, timers, or WebSerial threads. Optimized Android WebKit with persistent memory and high-rate scanning loops (30–50 tags/sec).

2. Step 1: Installing Zebra Enterprise Browser on the Handheld

Before deploying the configuration file, Zebra Enterprise Browser must be installed on the mobile computer.

1
Install from Google Play Store (Easiest Method):
Open the Google Play Store on the Zebra TC53/TC58, search for Zebra Enterprise Browser (Package: com.zebra.mdna.enterprisebrowser), and tap Install.
2
Alternative: Enterprise MDM / StageNow APK Push:
If the handhelds are on a restricted hospital or enterprise intranet without Google Play access, push the Enterprise Browser APK (e.g., EnterpriseBrowser_v5.6.0.10.apk) to the device via StageNow AppMgr, SOTI MobiControl, or Microsoft Intune.
3
First-Time App Launch:
Launch Enterprise Browser once on the device and accept all requested Android permissions (Storage, Camera, and Phone). This creates the necessary app directories on the device's internal storage.
⚠ Critical Prerequisite for DataWedge Integration:
Always install Zebra Enterprise Browser before importing the iDash DataWedge profile. When DataWedge loads its profile database, it verifies that com.zebra.mdna.enterprisebrowser exists on the operating system to successfully bind the hardware RFID trigger to the browser.

3. Step 2: The Production Config.xml Architecture

Enterprise Browser's behavior is entirely controlled by a single XML configuration file named Config.xml. The production-ready file for iDash Standalone is published in the downloads directory:

📥 Download iDash Production Config.xml

Key Configuration Settings for iDash

Below is an annotated breakdown of the critical parameters in the iDash Config.xml:

<?xml version = "1.0"?> <!-- EnterpriseBrowser_v5.6.0.10 Configuration for iDash Standalone --> <Configuration> <EB_VERSION value="5.6.0.10"/> <HideSystemBar value="1"/> <!-- 1 = Hides top Android status bar --> <!-- Custom Kiosk Lockdown: Prevents technicians from closing or switching apps --> <CustomKioskMode> <setHomeKeyDisable value="1"/> <!-- Disables Android Home button --> <setStatusBarDisable value="1"/> <!-- Prevents pulling down notifications --> <setBackKeyDisable value="0"/> <!-- 0 = Allows internal web back navigation --> <setRecentAppDisable value="1"/> <!-- Disables App Switcher / Recent Apps --> </CustomKioskMode> <!-- Screen and Orientation Settings --> <Screen> <FullScreen value="1"/> <!-- True full-screen borderless display --> <PageZoom value="1.0"/> <!-- 1:1 default scaling --> <EnableZoom value="1"/> <!-- Allows pinch-zoom on facility SVG maps --> <AutoRotate value="0"/> <!-- 0 = Locks portrait orientation for scanner --> </Screen> <Applications> <Application> <!-- Scanner Integration Mode: 1 = Use DataWedge profile keystrokes (Recommended for iDash web forms) 0 = Direct EB.Barcode / EB.RFID JavaScript API calls --> <usedwforscanning value="1"/> <!-- Startup URL: Set this to your iDash Standalone server address --> <General> <Name value="iDash"/> <StartPage value="https://lingcod.tail585c9b.ts.net:8443/index.aspx" name="iDash"/> </General> <!-- Soft Input Panel (Keyboard) Behavior --> <SIP> <ResizeOnSIP value="1"/> <!-- Shrinks web view when keyboard opens --> </SIP> <KeyboardConfiguration> <KeyboardVisibility value="onDemand"/> <!-- Keyboard only shows when user taps input --> </KeyboardConfiguration> <!-- Persistent Sessions & Security --> <Navigation> <NavTimeout value="45000"/> <Cookies value="1"/> <DeleteCookiesOnLaunch value="0"/> <!-- Preserves login session across shifts --> <DeleteCookiesOnExit value="0"/> </Navigation> </Application> </Applications> </Configuration>
💡 Customizing the StartPage:
If a handheld is permanently assigned to a specific task (such as the RFID Asset Locator or Room Inventory), you can change the <StartPage> value in Config.xml directly to that tool:
  • Main Hub (Default): https://<server>:8443/index.aspx
  • Dedicated Asset Locator: https://<server>:8443/va_rfid_locator.aspx
  • Dedicated Site Inventory: https://<server>:8443/va_inventory.aspx
  • Dedicated Tag Team Scan: https://<server>:8443/va_tagteam_scan.aspx

4. Step 3: Deploying Config.xml to the Zebra Handheld

For Enterprise Browser to read your configuration, Config.xml must be copied to the application's configuration directory on the handheld.

Target Directory Path on the Device

Depending on the Android operating system version on your Zebra device, use the appropriate path:

OS Version / Device Type Exact Directory Path for Config.xml
Android 11, 13, 14 (Scoped Storage)
TC53, TC53e, TC58, TC78		 /sdcard/Android/data/com.zebra.mdna.enterprisebrowser/Config.xml
Legacy Android / Enterprise Partition
Android 8, 9, 10 or StageNow FileMgr		 /enterprise/device/enterprisebrowser/Config.xml

Deployment Method A: Direct Download via iDash Portal (Fastest in the Field)

1
On the Zebra handheld, open Chrome and navigate to the iDash Downloads page: https://<server>:8443/va_downloads.aspx.
2
Sign in and navigate to the Software folder. Tap Config.xml to download it to the device's /Download folder.
3
Open the device's Files app (or Total Commander / Solid Explorer).
4
Copy Config.xml from /sdcard/Download/ and paste it into:
/sdcard/Android/data/com.zebra.mdna.enterprisebrowser/ (overwriting the default file).

Deployment Method B: USB ADB Command Line (Fastest for IT Admin / Staging Bench)

If you have the Zebra handheld docked in a USB communication cradle connected to a workstation:

1
Enable USB Debugging on the handheld under Settings → Developer Options.
2
Open PowerShell on the staging PC and push the downloaded file in one command:
adb push Config.xml /sdcard/Android/data/com.zebra.mdna.enterprisebrowser/Config.xml
3
Restart Enterprise Browser on the handheld:
adb shell am force-stop com.zebra.mdna.enterprisebrowser adb shell am start -n com.zebra.mdna.enterprisebrowser/com.rhomobile.rhodes.RhodesActivity

Deployment Method C: Zebra StageNow Barcode Deployment (Mass Rollout)

For deploying across a large fleet of scanners (10 to 500+ devices):

  • In the StageNow Workstation Tool, create an Xpert Mode profile targeting MX 10.x+.
  • Add a FileMgr step:
    • File Action: Transfer/Copy
    • Source Protocol: HTTPS
    • Source URL: https://<your-idash-server>:8443/downloads/Software/Config.xml
    • Target Path: /sdcard/Android/data/com.zebra.mdna.enterprisebrowser/Config.xml
  • Generate the 2D PDF417 staging barcode. Technicians simply open the StageNow app on each handheld and scan the barcode to complete configuration in 5 seconds.

5. Step 4: Testing & Verification

Once Config.xml is in place, verify the deployment on the device:

1
Launch Enterprise Browser: Tap the Enterprise Browser app icon on the handheld.
2
Verify Kiosk Display: Confirm that: • The app immediately launches directly to the iDash Hub (or specified tool).
• No browser address bar, back/forward buttons, or tabs are visible.
• The top Android notification bar is hidden or inaccessible.
• Tapping the Home key does not exit the app (if Kiosk lock is enabled).
3
Verify Scanner Trigger: Navigate to va_rfid_locator.aspx or va_inventory.aspx. Squeeze the RFID trigger on the sled. Verify that tags stream immediately into the scanner input field without requiring the virtual keyboard.
4
Run Hardware Test Harness: Navigate to va_zebra_browser_test.aspx to execute automated diagnostics on Enterprise Browser JavaScript APIs (EB.Barcode, EB.RFID, battery status, and memory limits).

6. Troubleshooting & Field FAQs

Q: Handheld shows "Page Not Found" or a white screen on startup?

Verify network connectivity. If using Tailscale, ensure the Tailscale client is running and connected on the handheld. Check that the URL specified in <StartPage> includes the correct port (e.g. :8443 for SSL) and matches the current server address.

Q: The virtual keyboard pops up and covers the asset table when I scan?

In Config.xml, ensure the <KeyboardConfiguration> section has <KeyboardVisibility value="onDemand"/> and <ResizeOnSIP value="1"/>. This ensures the keyboard only opens when a technician explicitly taps an editable text field, not during background RFID trigger streams.

Q: How does IT exit Kiosk mode for device maintenance?

If CustomKioskMode has disabled the Home and Back keys:
1. Plug the device into a PC with ADB enabled and run: adb shell am force-stop com.zebra.mdna.enterprisebrowser.
2. Alternatively, configure an administrative password in the <Kiosk> section of Config.xml to allow PIN-based kiosk exit.

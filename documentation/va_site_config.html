1. System Overview

Application NameiDash (VA Asset Intelligence Hub)
PublisherID Integration Inc.
RuntimeASP.NET Web Forms — .NET Framework 4.8
Hosting ModelIIS 10+ Application Pool (Integrated Pipeline)
DatabaseMicrosoft SQL Server Express (local instance)
Installation PathC:\inetpub\wwwroot\iDash\
Runs AsIIS App Pool identity (typically ApplicationPoolIdentity)
CompilationSource-deployed (no pre-compiled assemblies — ASP.NET JIT compiles .aspx.cs and App_Code/ at runtime)
External CallsDirect SQL (localhost only) • SMTP outbound (email notifications)

iDash is a web-based asset management dashboard deployed to VA VISN servers alongside the iDash inventory system. It provides barcode scanning, ENNX government reporting, data import/enrichment, automated alerts, and label printing capabilities. All database and API communication is local to the server — no external cloud services are contacted for core functionality.

🔒 SQL Execution Security: Import scripts (va_dbupdate.sql, va_dbupdate_upsert_enrich.sql) are loaded as raw SQL text and executed via SqlCommand using the configured SQL authentication credentials. The company setup SQL on va_site_config.aspx uses parameterized @station and @companyName parameters to prevent SQL injection. Scripts use IF NOT EXISTS guards and MERGE statements to prevent data loss. No xp_cmdshell, OPENROWSET, or dynamic SQL with user input is used.

🌐 Configurable Listening Ports & Automated Rollout: Administrators can change the active listening port (e.g. 80, 443, 8181) directly from the Server Protocol & Listening Port section on va_site_config.aspx. Saving automatically synchronizes web.config, the automated report runner (AutoReportRunner.ps1), remote database update scripts (remote_db_update.ps1), report automation configuration (report_automation.json), and BarTender print server authentication (printserver_appsettings.json). Administrators can download or execute the generated apply_server_port.ps1 PowerShell script with elevation to automatically bind the target port in IIS and configure the Windows Firewall rule.
🔒 Firewall Summary: The only outbound connection is SMTP (port 587) for email delivery. All database and API traffic is localhost-only. Inbound web access requires only the configured IIS listening port (typically 443 for HTTPS, 80 for HTTP, or 8181 for root-level deployment).

11. Security Model

Authentication

  • Application-level login: UserManager.cs manages session-based authentication. Users log in through the hub page with credentials stored locally in App_Data/.
  • Role-based access: Each page checks CanSee("permission_key") at load. Pages are grouped into permission tiers (admin, reports, scanning, etc.).
  • Password fields: Sensitive fields (SQL password, SMTP password) are cleared on page load — values are never displayed back to the user.

Data Protection

  • SQL Injection Prevention: All database operations use parameterized SqlParameter objects. No string concatenation of user input into SQL.
  • XSS Prevention: Output encoding via HttpUtility.HtmlEncode() on all user-supplied values rendered to the page.
  • File Upload: Uploaded data files are saved to temp/ with generated names. Only .xlsx, .txt, .csv, and .sql extensions are processed.
  • web.config Protection: IIS blocks direct HTTP access to web.config by default. The site config page writes to it server-side only via authenticated admin action.

12. Data Flow Architecture

End-to-end data flow for the three primary operations:

A. Asset Data Import

1
Admin uploads VA data file (.xlsx/.txt) via va_dbupdate.aspx
2
File saved to temp/ → parsed by ClosedXML (Excel, MIT License) or StreamReader (text) into staging DataTable
3
SQL script loaded from site root → executed against dbo.asset via SqlCommand
4
Results displayed in grid — insert/update/skip counts shown

B. Barcode Scanning (TagTeam Scan)

1
Technician scans barcode → AJAX call to api/v_asset.ashx for asset lookup
2
Asset data returned as JSON → displayed in scan grid
3
Asset written to dbo.asset immediately via SaveScanToDb() with lastinventoried = SYSDATETIMEOFFSET()
4
Optional: auto-print label via BarTender spooler

C. ENNX Report Generation

1
User selects date range, site, user filters on va_ennx.aspx
2
Parameterized SQL query against dbo.asset LEFT JOIN dbo.location
3
Results rendered in grid + ENNX text format preview
4
Download as .txt (ENNX format) or .xls (Excel HTML) or email via SMTP

Portable BCP Export Script – Deployment Documentation

This page documents the portable BCP export script used to generate the LsvDataForIdash.txt file for iDash. It includes the script, instructions for moving it to a new machine, built‘in validation steps, and troubleshooting tips for common errors.

1. Security & Operational Overview

This script is designed for review by Information Security Officers (ISO). It performs a read-only extraction of asset inventory data.

Operational Steps

  • Initialization: Sets configuration variables for Server, Database, and Output path.
  • Connectivity Check: Verifies network connectivity to the SQL Server using a benign query (SELECT TOP 1 GETDATE()).
  • Access Check: Verifies write permissions to the destination folder by briefly creating and deleting a 0-byte test file.
  • Data Export: Uses the Microsoft BCP (Bulk Copy Program) utility to query specific tables and save the result to a text file.

Security & Permissions

  • Authentication: Uses Windows Authentication (-E flag). No usernames or passwords are stored in the script.
  • Database Scope: Requires SELECT (Read) permissions only. No data is modified, inserted, or deleted in the database.
  • Network Ports: Requires outbound traffic on TCP 1433 (SQL Server) and SMB (File Share) to the output location.
  • File System: Writes a single text file to the defined OUTPUT path. Does not access system files.

2. Portable BCP Script (BCP_Export_LSV.cmd)

Save this as BCP_Export_LSV.cmd on any machine. Only update the variables at the top.

@echo off
setlocal enabledelayedexpansion

REM ============================================================
REM  PORTABLE BCP EXPORT SCRIPT FOR IDASH
REM  Only update the variables in this section when moving
REM ============================================================

REM --- SQL Server to connect to ---
set SQLSERVER=VHACDWDWHSQL33.VHA.MED.VA.GOV

REM --- Database name ---
set DATABASE=LSV

REM --- Output file location (UNC or local path) ---
set OUTPUT=\\vhavanapprfidp\idashsqlcmd\VISN20_RFIDSQL\LsvDataForIdash.txt

REM --- Station IDs (Comma separated) ---
set STATIONS=512,540,517,581,613,688

REM ============================================================
REM  DO NOT EDIT BELOW THIS LINE
REM ============================================================

echo Running BCP export...
echo Server: %SQLSERVER%
echo Database: %DATABASE%
echo Output: %OUTPUT%
echo Stations: %STATIONS%
echo.

REM --- Test SQL connectivity ---
echo Testing SQL connectivity...
sqlcmd -S %SQLSERVER% -d %DATABASE% -E -Q "SELECT TOP 1 GETDATE()" >nul 2>&1
IF ERRORLEVEL 1 (
    echo ERROR: Unable to connect to SQL Server %SQLSERVER%.
    echo Make sure you are on the correct network and have SQL permissions.
    pause
    exit /b 1
)
echo SQL connectivity OK.
echo.

REM --- Test write access to output folder ---
echo Testing write access to output folder...
echo Test > "%OUTPUT%.test" 2>nul
IF ERRORLEVEL 1 (
    echo ERROR: Cannot write to output path: %OUTPUT%
    echo Check permissions or update the OUTPUT variable.
    pause
    exit /b 1
)
del "%OUTPUT%.test"
echo Output path OK.
echo.

REM --- Run BCP export ---
bcp "SET NOCOUNT ON 
SELECT DISTINCT 
    a.EntryNumber as EE, 
    a.Manufacturer, 
    a.MfgrEquipmentName as Description, 
    a.Model, 
    a.Serial, 
    a.EquipmentCategory as Category, 
    a.UseStatus as Status, 
    b.ServiceSection as Service, 
    a.Location, 
    a.PhysicalInventoryDate, 
    a.PreviousLocation, 
    a.SecondPreviousLocation, 
    a.ThirdPreviousLocation, 
    a.Sta3n As Site, 
    a.CSNName as CSN, 
    a.CMR as EIL, 
    a.purchaseorder as PO 
FROM BISL_R1VX.R_Eng_EquipmentInventory AS a 
LEFT JOIN Dim.ServiceSection AS b 
    ON a.ServiceIEN = b.ServiceSectionIEN 
    AND a.Sta3n = b.Sta3n 
WHERE a.Sta3n IN (%STATIONS%) 
  AND a.TypeOfEntry = 'NON-EXPENDABLE EQPT' 
  AND vistaeditdate > (GETDATE() - 3)"
queryout "%OUTPUT%" -S %SQLSERVER% -d %DATABASE% -E -T -c

IF ERRORLEVEL 1 (
    echo ERROR: BCP export failed.
    pause
    exit /b 1
)

echo Export completed successfully.
pause

2. Output Data Description

The script generates a tab-delimited text file (LsvDataForIdash.txt) containing Non-Expendable Equipment modified within the last 3 days for the specified stations.

Columns included:

  • EE (Entry Number)
  • Manufacturer
  • Description (MfgrEquipmentName)
  • Model
  • Serial
  • Category (EquipmentCategory)
  • Status (UseStatus)
  • Service (ServiceSection)
  • Location
  • PhysicalInventoryDate
  • PreviousLocation
  • SecondPreviousLocation
  • ThirdPreviousLocation
  • Site (Sta3n)
  • CSN (CSNName)
  • EIL (CMR)
  • PO (PurchaseOrder)

Only update these three variables:

set OUTPUT=\\vhavanapprfidp\idashsqlcmd\VISN20_RFIDSQL\LsvDataForIdash.txt

SQLSERVER

  • Must be reachable from the new machine
  • Must allow Windows authentication

DATABASE

  • Usually stays LSV

OUTPUT

  • Must be writable
  • Can be UNC or local path

5. Troubleshooting Tips

If the script fails, check the console output for specific error messages.

Common Error Messages

Error Message Likely Cause Things to Try
ERROR: Unable to connect to SQL Server... Network issue, Firewall, or wrong Server Name.
  • Ping the server name to verify network visibility.
  • Check if SQL Browser service is running on the server.
  • Verify port 1433 is open and not blocked by firewall.
  • Ensure your Windows account has login permissions on the SQL box.
ERROR: Cannot write to output path... Permissions or invalid path.
  • Check if the shared folder path exists.
  • Verify your user account has Write/Modify permissions to the share.
  • Try changing OUTPUT to a local temporary folder (e.g., C:\Temp\test.txt) to rule out network permission issues.
ERROR: BCP export failed. SQL query error or Database issue.
  • Check if the 'LSV' database exists on the target server.
  • Verify the user has SELECT permissions on the required tables (R_Eng_EquipmentInventory).
  • Check for ODBC driver compatibility (install latest SQL Native Client).
'bcp' is not recognized...
or
'sqlcmd' is not recognized...		 SQL Command Line Tools not installed. Install Microsoft Command Line Utilities 15 for SQL Server (MsSqlCmdLnUtils) on the machine running the script.

9. Server-Side Data Load Script (va_ntwksvr.sql)

This SQL script imports the LsvDataForIdash.txt (generated by the BCP script above) into the iDash database. It handles deduplication, normalization, and updating existing assets.

One-Time Setup

Save this as va_ntwksvr.sql on the SQL Server (or a machine with SSMS connected to it).

/* 10) INSERT NEW LOCATIONS */
BEGIN TRY
  BEGIN TRAN;
  ;WITH src AS (
      SELECT LTRIM(RTRIM(lt.name)) AS base_name, lt.site, lt.companyid
      FROM dbo.locationtemp AS lt
  ),
  shaped AS (
      SELECT
          name_final = 'SP' + base_name,
          site,
          companyid,
          rn = ROW_NUMBER() OVER (
                  PARTITION BY 'SP' + base_name, companyid
                  ORDER BY (SELECT 0)
              )
      FROM src
  )
  INSERT INTO dbo.location (name, site, companyid)
  SELECT s.name_final, s.site, s.companyid
  FROM shaped AS s
  WHERE s.rn = 1
    AND NOT EXISTS (
        SELECT 1
        FROM dbo.location WITH (UPDLOCK, HOLDLOCK)
        WHERE name = s.name_final AND companyid = s.companyid
    );
  UPDATE #ImportStats SET LocInserted = @@ROWCOUNT;
  COMMIT;
END TRY
BEGIN CATCH
  IF XACT_STATE() <> 0 ROLLBACK;
  UPDATE #ImportStats SET Errors = Errors + 1;
  THROW;
END CATCH;
GO

BEGIN
    UPDATE a
    SET a.[description] = LTRIM(RTRIM(REPLACE(REPLACE(REPLACE(a.[description], '"',''), N' ',''), N' ','')))
    FROM dbo.asset AS a
    JOIN #new_assets AS na
      ON na.rfidtag = a.rfidtag
    WHERE a.[description] IS NOT NULL
      AND (a.[description] LIKE '%"%' OR a.[description] LIKE N'% %' OR a.[description] LIKE N'% %');
END

-- Enforce SP prefix on legacy data (text6, text11, lastobservedlocation)
UPDATE a
SET a.text6 =
    CASE
        WHEN a.text6 IS NULL OR LTRIM(RTRIM(a.text6)) = '' THEN 'SPZZUNKNOWN'
        WHEN LEFT(LTRIM(a.text6),2) = 'SP' THEN 'SP' + LTRIM(SUBSTRING(LTRIM(a.text6),3,500))
        ELSE 'SP' + LTRIM(a.text6)
    END,
    a.text11 =
    CASE
        WHEN a.text11 IS NULL OR LTRIM(RTRIM(a.text11)) = '' THEN 'SPZZUNKNOWN'
        WHEN LEFT(LTRIM(a.text11),2) = 'SP' THEN 'SP' + LTRIM(SUBSTRING(LTRIM(a.text11),3,500))
        ELSE 'SP' + LTRIM(a.text11)
    END,
    a.lastobservedlocation =
    CASE
        WHEN a.lastobservedlocation IS NULL OR LTRIM(RTRIM(a.lastobservedlocation)) = '' THEN 'SPZZUNKNOWN'
        WHEN LEFT(LTRIM(a.lastobservedlocation),2) = 'SP' THEN 'SP' + LTRIM(SUBSTRING(LTRIM(a.lastobservedlocation),3,500))
        ELSE 'SP' + LTRIM(a.lastobservedlocation)
    END
FROM dbo.asset a
WHERE a.text6 IS NULL OR LEFT(LTRIM(a.text6),2) <> 'SP'
   OR a.text11 IS NULL OR LEFT(LTRIM(a.text11),2) <> 'SP'
   OR a.lastobservedlocation IS NULL OR LEFT(LTRIM(a.lastobservedlocation),2) <> 'SP';
GO

/* 14) LINK LOCATION IDS */
IF OBJECT_ID('tempdb..#new_assets') IS NOT NULL
BEGIN
    UPDATE a
    SET a.locationid = l.id
    FROM dbo.asset a
    JOIN #new_assets na ON na.rfidtag = a.rfidtag
    JOIN dbo.location l
      ON l.name =
          'SP' + LTRIM(
                  CASE
                    WHEN LEFT(LTRIM(a.text6),2) = 'SP' THEN SUBSTRING(LTRIM(a.text6),3,500)
                    ELSE a.text6
                  END
                )
      AND l.companyid = a.companyid
    WHERE a.locationid IS NULL;
END
GO

Operational Overview

  • Import: Bulk loads the text file into a staging table (AssetFileRaw).
  • Normalize: Formats dates, ensures "SP" prefixes on locations, and generates RFID tags/primary keys in assettemp.
  • Location Sync: Inserts any new locations found in the import file into the location table.
  • Asset Sync: Inserts new assets into the asset table only if they don't already exist. It does NOT overwrite existing assets to preserve history.

Troubleshooting

  • "Bulk insert cannot find file": The SQL Server service account must have permission to read the file path. Adjust the path to a local folder on the SQL Server (e.g., C:\Temp) if network shares fail.
  • "String truncation": Check if any column in the text file exceeds 500 characters.
  • "Violation of PRIMARY KEY": The script handles duplicates, but if the source file implies a new asset with an existing ID, it will be skipped.

6. Notes

This script is designed to be portable and easy to maintain. Update the variables at the top and the script will validate the environment before running.

🔐 License Fix: Network Adapter Change

How to resolve LICENSE KEY ERROR. EXPECTING MAC ADDRESS after a NIC swap, adapter replacement, or VM migration.

This is a common issue. Every time a server's network adapter is replaced, disabled, or swapped, the iDash license validation fails because the license is bound to the old adapter's MAC address. This guide documents the fix.

1 Understanding the Problem

iDash licenses are tied to a specific MAC address (hardware network adapter identifier). When you see this error in the logs:

LICENSE KEY ERROR. EXPECTING MAC ADDRESS 00E04C360E15 WHICH IS NOT FOUND ON THIS SERVER.

It means:

  • The license stored in dbo.applicationsetting.licensekey was generated for MAC 00E04C360E15
  • That MAC address no longer exists on the server (adapter was replaced/disabled)
  • A new license keyed to the current MAC is required

Where the License Lives

LocationDetails
dbo.applicationsetting.licensekeyBase64-encoded JSON containing the license key string and cryptographic signature

License Key Structure (Decoded)

{
  "LicenseKey": "VA Baltimore 80E4BADAC5E1|5|1|5|80E4BADAC5E1",
  "Signature": "Ko9+NAea2VXq...iEw="
}

The LicenseKey field format is: Label MAC|sites|?|assets|MAC. The MAC appears at both the start and end of the key string.

2 Step-by-Step Fix

Prerequisites: SQL Server Management Studio (SSMS) access to the iDash database, access to the iDash web interface, and the new license key (base64 string) from ID Integration Inc..

Step 1: Identify the Current MAC Address

On the affected server, open PowerShell and run:

Get-NetAdapter | Where-Object Status -eq 'Up' | Select-Object Name, MacAddress, Status

Note the MAC address (e.g., 80-E4-BA-DA-C5-E1). Remove dashes and uppercase it: 80E4BADAC5E1. This is the MAC that the new license must be keyed to.

Step 2: Request a New License

Contact ID Integration Inc. (or your license provider) with:

  • The new MAC address
  • The site name / VISN
  • The required asset count and site count

They will provide a new base64-encoded license string.

Step 3: Clear the Old License (SQL)

Connect to the iDash database in SSMS and run:

-- Verify current (broken) license
SELECT licensekey FROM dbo.applicationsetting;

-- Clear it
UPDATE dbo.applicationsetting SET licensekey = '';
Script available: The full diagnostic + fix script is available at:
iDash → Downloads → Scripts → va_license_fix.sql
Or directly: va_license_fix.sql

Step 4: Apply the New License

Use the iDash web interface (recommended):

  1. Open the iDash admin / settings page
  2. Paste the new base64 license key into the license field
  3. Save / Apply
If the iDash interface rejects the key, the licensekey column may be too short. Run this first: 
ALTER TABLE dbo.applicationsetting ALTER COLUMN licensekey varchar(2000);
Newer licenses with site labels (e.g., "VA Baltimore") produce longer base64 strings that may exceed a varchar(255) column.

Step 5: Restart Services

iisreset
# Also restart the iDash Print Server service if applicable
Restart-Service "iDash Print Server" -ErrorAction SilentlyContinue

Step 6: Verify

  • Check the web application logs (C:\Logs\) — the MAC error should be gone
  • Run iDash → System Diagnostics — the "Database & License" test should pass
  • Try a batch update from a mobile device to confirm license limits are no longer exceeded

3 Decoding a License Key

License keys are base64-encoded JSON. To inspect one, use PowerShell:

# Decode a license key
$key = "ew0KICAiTGljZW5z..."  # paste full base64 string
$mod = $key.Length % 4
if ($mod -gt 0) { $key += ('=' * (4 - $mod)) }  # fix padding if needed
[System.Text.Encoding]::UTF8.GetString([System.Convert]::FromBase64String($key))

This will output something like:

{
  "LicenseKey": "VA Baltimore 80E4BADAC5E1|5|1|5|80E4BADAC5E1",
  "Signature": "Ko9+NAea2VXq..."
}

The MAC address appears in the LicenseKey value. Compare it with the server's actual MAC to confirm the key matches.

4 Troubleshooting

ProblemCauseFix
License accepted but batch updates still fail with "License limits exceeded" iDash API caches the license in memory Run iisreset to clear the cache
New license key rejected / won't save Column licensekey is too short (varchar 255) ALTER TABLE dbo.applicationsetting ALTER COLUMN licensekey varchar(2000);
Key appears truncated after pasting Clipboard truncation or missing base64 padding Save the key to a .txt file first, then paste from there. Add = padding if needed.
MAC changed again after fix Another adapter swap, Windows Update, or VM migration Repeat the process. Consider using a USB Ethernet adapter with a fixed MAC.
Multiple MACs on server — which one? Server has multiple NICs Use the MAC of the primary active adapter. Run Get-NetAdapter | Where Status -eq Up
Error repeats every 5 minutes in logs iDash re-checks the license on a timer Expected behavior until the license is fixed. Will stop after applying valid key + iisreset.

5 Prevention

  • Document the MAC address for each site in your site records
  • Request a spare license if the site frequently changes adapters
  • Use a dedicated NIC (USB Ethernet adapter) with a known, fixed MAC for licensing
  • Set a static MAC in the NIC's advanced driver settings if possible
  • Before replacing a NIC, note the current MAC and request the new license proactively

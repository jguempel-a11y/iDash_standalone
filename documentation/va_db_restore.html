🔥 Database Restore Tool

Rev. 2026-08-10 SQL Server Admin Only

The Database Restore page (va_db_restore.aspx) provides a one-click interface for replacing the iDash database with a .bak backup file. It handles the full restore lifecycle: killing active connections, restoring the backup, fixing orphaned SQL users, running schema migrations, and normalizing data (companies, companyid mappings, SP location prefixes, and listvalue1 dropdown options).

⚠ DANGER ZONE: This tool completely overwrites the iDash database. All existing data is replaced with the backup contents. This action cannot be undone.

Prerequisites

  • SQL Server Express (or full edition) with the iDash database
  • The idashadmin SQL login with sysadmin, bulkadmin, and db_owner roles
  • A .bak backup file accessible from the server's file system
⚠ Critical: The idashadmin login must have sysadmin for the post-restore orphaned user fix and data normalization to work. Without it, the restore will complete but companies, user mappings, and asset data will not be configured.

One-time setup (SQL Express): Open a command prompt on the server and run: 
sqlcmd -S .\sqlexpress -E -Q "ALTER SERVER ROLE [sysadmin] ADD MEMBER [idashadmin]"
This uses your Windows login (which has sysadmin from the SQL Express installation) to grant sysadmin to the idashadmin account. Only needs to be run once per system.

Restore Process

When you click RESTORE DATABASE, the following steps execute automatically:

1

Kill Active Connections

Sets the database to SINGLE_USER WITH ROLLBACK IMMEDIATE to drop all active connections. This ensures no locks prevent the restore.

2

Restore Database

Executes RESTORE DATABASE [iDash] FROM DISK = '...' WITH REPLACE using the selected .bak file. The WITH REPLACE flag allows overwriting the existing database.

3

Set Multi-User

Returns the database to MULTI_USER mode so applications can reconnect.

4

Fix Orphaned User

When a .bak file comes from a different server (e.g., a tagging cart), the idashadmin database user has a SID that doesn't match this server's login. The restore page attempts three methods to fix this:

MethodTechniqueRequirement
AALTER AUTHORIZATION ON DATABASE::[iDash] TO [idashadmin]sysadmin server role
BWindows auth connection → ALTER USER ... WITH LOGINIIS app pool identity with SQL access
Csp_change_users_login 'Auto_Fix'sysadmin server role

Method A is the most reliable and is the one that works on SQL Express tagging systems when idashadmin has sysadmin.

5

Verify Server Roles

Ensures idashadmin is a member of the bulkadmin server role (required for BCP/bulk data import operations).

6

Schema Migration & Data Normalization

Once the orphaned user is fixed and the connection can USE [iDash], the restore page runs two sets of patches:

6a. Schema Migration

Adds missing columns to dbo.sysuser if they don't exist:

  • hideadminpopups (BIT, default 0)
  • inventorylimiteduser (BIT, default 0)
  • restricteditmobile (BIT, default 0)

6b. Data Normalization

Ensures the restored database has the application-level data that iDash expects:

PatchDescription
Create CompaniesInserts VISN 5 companies if missing: 512 Baltimore, 517 Beckley, 540 Clarksburg, 581 Huntington, 613 Martinsburg, 688 Washington DC
Fix companyidMaps asset.companyid to the correct company based on station number (text7) where companyid is 0, NULL, or orphaned
SP Location PrefixesEnsures text6, text11, and lastobservedlocation have the required SP prefix for iDash location matching
Seed listvalue1Creates USE STATUS dropdown options: IN USE, LOST OR STOLEN, LOANED OUT, TURNED IN, OUT OF SERVICE
💡 Why is this needed? Backup files from tagging carts or other servers may have empty company tables, mismatched companyid values, or missing dropdown options. Without this normalization, the User Management page shows an empty Company dropdown, and assets have no site assignment.

Troubleshooting

"Skipping schema migration and normalization — orphaned user not fixed"

Cause: idashadmin does not have sysadmin.

Fix: Run this once from a command prompt on the server:

sqlcmd -S .\sqlexpress -E -Q "ALTER SERVER ROLE [sysadmin] ADD MEMBER [idashadmin]"

Then re-run the restore.

"Method A (ALTER AUTHORIZATION) failed: does not exist or you do not have permission"

Cause: Same as above — idashadmin needs sysadmin.

User Management shows empty Company dropdown after restore

Cause: The normalization step didn't run (orphaned user wasn't fixed), so the dbo.company table is empty or has data from the source server that doesn't match.

Fix: Grant sysadmin and re-run restore, or run the VISTA data import which also creates companies.

Restore succeeds but can't login to iDash

Cause: The backup came from a server with different sysuser records. The idashadmin user in the application's user table may have a different password hash.

Fix: Use the User Management page to reset the password, or sign in with superadmin/demo via the iDash desktop client to reset credentials.

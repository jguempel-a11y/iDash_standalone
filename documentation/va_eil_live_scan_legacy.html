📋 EIL Live Scan & Reconciliation

Database Connected Disk / Email / SQL Export Updated 09/09/2026

The EIL Live Scan module is a structured accountability reconciliation tool. It loads a targeted Equipment Item List (EIL) filtered by VA station and CMR number into an interactive scanning grid. Technicians physically walk through the facility, scan equipment barcodes against the live checklist, and the system simultaneously builds a fully formatted ENNX export payload ready for government system submission.

Supported Input Methods

EIL Live Scan accepts scan input via two methods. Both feed into the same handleScan() function, so all EIL reconciliation, EPC filtering, de-dupe, and ENNX assembly logic applies identically regardless of how the barcode data enters the page.

MethodHow It WorksRequirements
Keyboard / DataWedge Scans are typed or injected into the scan input field by a keyboard-wedge device (e.g., Zebra TC53 / RFD40 with DataWedge). ENTER key triggers processing. The page auto-focuses the scan input to capture DataWedge keystroke output. Any browser. DataWedge configured with ENTER suffix.
WebSerial (USB) A USB RFID reader or serial device is connected directly to the browser via the WebSerial API. Data is buffered and split on newline characters. Each complete line is passed to the same handleScan() function used by keyboard input. Chrome or Edge. HTTPS (or localhost). Expand the "WebSerial" section and click "Select/Open Serial Port".

Why WebSerial?

Traditional barcode/RFID scanning in a browser requires a middleware layer (DataWedge, COM-port relay app, or a native mobile app) to translate serial data into keyboard events. WebSerial eliminates that middleware by letting the browser talk directly to the USB serial port. This means:

  • No extra software: No DataWedge profile, no COM-port relay, no native app installation.
  • Any USB serial device: Works with any reader that outputs newline-terminated data over a serial/USB-serial connection.
  • Zero configuration: The browser prompts the user to select their serial port — no driver setup, no port number guessing.
  • Same scan pipeline: Data from the serial port flows through the exact same handleScan() function, so all EIL reconciliation, EPC filtering, de-dupe logic, and ENNX assembly apply automatically.

How WebSerial Works (Technical Flow)

  1. User clicks "Select/Open Serial Port" inside the collapsible WebSerial panel.
  2. The browser displays its native serial port picker dialog (a security requirement — no port is accessed without explicit user interaction).
  3. Once a port is selected, JavaScript opens it with the parameters below and starts an asynchronous read loop.
  4. Incoming bytes are decoded as UTF-8 and appended to a line buffer. When a newline (\n) is detected, the complete line is trimmed and passed to handleScan().
  5. The scan is processed identically to a keyboard scan — EIL reconciliation, EPC filtering, de-dupe, and ENNX assembly all apply.
  6. The serial connection stays open until the user clicks "Close Port" or navigates away from the page.

Step-by-Step User Workflow

1
Select Site (Station): Choose the VA facility from the Site dropdown. The station code (first 3 digits of the site name, e.g., 512) filters all subsequent queries to that station's records.
2
Select EIL / CMR: After selecting the site, the EIL dropdown auto-populates with all distinct CMR numbers (text8 field) for that station. Select the CMR you are reconciling — this defines the expected set of equipment for the audit.
3
Review the EIL Checklist Grid: The page renders a live grid of all assets tied to the selected CMR, showing each asset's barcode, description, current location, and reconciliation status (Found / Not Yet Scanned).
4
Scan Equipment Barcodes: Focus the scan input field and use your barcode scanner. As each barcode is matched against the EIL grid, its row immediately updates to Found and the item is appended to the ENNX payload in memory.
5
Export the ENNX Report: When scanning is complete, choose your export method:
  • Save to Session (SQL): Inserts the ENNX payload and metadata into ennx_session for audit trail.
  • Save to Disk: Writes .ennx.txt to C:\VA_RFID\ennx_live\saved\ on the server.
  • Download: Triggers a browser download of the .ennx.txt file.
  • Email: Sends the ENNX file as an attachment via the AssetWorx EmailHelper service.
⚠ Note: Barcodes scanned that do not exist in the selected CMR are still captured in the ENNX payload and flagged as extra items. This supports discovery of misplaced or unregistered assets during an audit.

Technical Architecture

On page load, LoadCompanies() populates the site dropdown from dbo.company. When a site is selected, LoadEIL() runs a SELECT DISTINCT a.text8 query joined to dbo.company via companyid, restricting to the chosen station code. Scan state is held in the hidden field HidEnnx — a JSON-encoded accumulator that grows with each successful scan. On export, this value is decoded server-side and written to the chosen destination.

Access & Security

Access is controlled via the iDash tile-key model. Users must have the scan_eil tile key granted in their TileAccess profile. See User Management for details.

All SQL queries use parameterized ADO.NET SqlParameter commands to prevent injection. Exceptions are caught and surfaced via ShowMsg() with sanitized messages only — raw SQL errors are never exposed to the browser.

The WebSerial feature requires explicit user interaction to grant the browser permission to access a serial port. No serial ports are accessed automatically. The permission does not persist across sessions.

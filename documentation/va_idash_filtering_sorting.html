iDash — Column Sorting, Filtering & Export

Applies to All Reporting Pages Added 08/22/2026

Overview

As of August 2026, column sorting, per-column filtering, and Excel export are standardized across all three main iDash reporting pages. The behavior is identical on each page — once you learn it on one page, it works the same everywhere.

📋 Pages using this pattern:
va_asset_master.aspxAsset Master — server-side paginated grid with full DataTables column sort and inline filter row.
va_location_list.aspxLocation List — location summary grid (native JS) and asset detail grids (lightweight initDetailFilter).
va_asset_stats.aspxAsset Statistics — the “Assets by Location — Top 50” table and the location asset drill-down panel.

▲ Column Sorting

Every sortable column header contains a sort indicator (▲▼ by default). Clicking a column header sorts the table by that column.

BehaviourDetail
First clickNumeric / date columns → Descending first (largest / newest at top)
Text columns (e.g. Location, Asset Name) → Ascending first (A–Z)
Second click (same column)Reverses the sort direction.
Visual indicatorActive sort column highlights in accent color. Indicator changes from ▲▼ (inactive) to a solid ▲ (ascending) or ▼ (descending).
Interaction with filtersSort always applies to the current filtered result set — not the full dataset.
PersistenceSort state is maintained across paging but does not persist across page reloads (intentional).

🔍 Per-Column Filtering

Each table has a second header row containing a compact text input under each column. Type anything in any box to instantly narrow the rows shown.

📌 How the filter inputs work:
  • AND logic — a row must match every non-empty filter box to be visible.
  • Substring match — typing 123 in the CMR column shows rows whose CMR contains “123”.
  • Case-insensitive — SPGD and spgd find the same rows.
  • Instant — filtering triggers on every keypress; no Enter required.
  • Resets to page 1 — when filters change, the pager returns to the first page.
  • Composes with sort — the active sort order is re-applied to the filtered result set automatically.
  • Clear a filter — delete the text; all rows reappear immediately.

💾 Export Excel & Data Extraction

Every reporting page includes an “💾 Export Excel” button in the page header. While summary pages stream standard CSV files, Asset Master delivers native OpenXML .xlsx spreadsheets powered by ClosedXML (MIT License) with full column sync and dual-mode selection capability.

📌 Context-aware export on va_location_list.aspx:
Location clickedExports only assets for that location. File: Assets_{LocationName}.csv.
Age-bucket filter activeExports the filtered age-bucket list. File: Assets_Age_Filter.csv.
No panel openExports the location summary grid. File: Location_Summary.csv.

Data comes from the server-side Session cache — no second database query is issued.

🏭 Site Selection Persistence

All three pages share a common site selection memory using localStorage key iDash_selectedSite. Changing the Site dropdown on any page saves the value; navigating to any other page restores it automatically. Works for both admin and regular users and survives page refreshes.

⚠ DataTables is NOT used on Location List or Asset Stats.
Only Asset Master uses DataTables (server-side). Location List and Asset Stats use lightweight native JS (initSummaryFilter, initDetailFilter, _applyLocFiltersAndSort) to avoid conflicts with ASP.NET WebForms __doPostBack events and minimize library footprint.

Performance Notes

  • Location List: EnableViewState="false" on all GridViews; data cached in Session["GridXyzDT"] and rebound on postback — eliminates 50–150KB ViewState per request.
  • Location List SQL: All queries run under READ UNCOMMITTED to avoid blocking RFID write locks.
  • Asset Master: Server-side OFFSET...FETCH NEXT pagination — only the current page crosses the wire.
  • Asset Stats location table: Data embedded as a JSON literal (LOC_STATS_DATA); all client-side filtering is zero-latency after load.

VA BCP AW Push — AssetWorx to VA SQL Export

📤 Push (AW → VA SQL)

This tool is the reverse of the VA On Network Queries page. Instead of pulling data from a CDW/VistA server into AssetWorx, this tool generates BCP out commands to extract data from the local AssetWorx SQL database, plus a SQLCMD insert script to push that extracted file into a remote VA SQL server (e.g. an AEMS-MERS or reporting endpoint). All fields are editable and are persisted in your browser.

ℹ️ How this works
1. BCP OUT — runs bcp … queryout against your local AssetWorx SQL instance to dump asset records into a tab-delimited flat file on a shared path.
2. SQLCMD PUSH — creates a staging table on the remote VA server and bulk-inserts the flat file, then maps/updates rows to the target table.
Run both scripts in order from a Windows command prompt on a machine that has network access to both the AssetWorx SQL server and the destination VA SQL server.

How to Use This Page

📝 What is this tool?

This page generates ready-to-run command-line scripts that extract AssetWorx asset data and push it to a remote VA SQL Server endpoint. No manual SQL writing required — just fill in the fields and copy the scripts.

🔄 Direction of data flow

BCP PULL (va_bcp_query.html) reads from CDW/VistA → into AssetWorx.
BCP PUSH (this page) reads from AssetWorx → pushes to a remote VA SQL server.

💾 Save my settings

Click Save Current Values as Default at the bottom to persist all field values in your browser. They will reload automatically next time.

Step-by-Step Workflow

1
Fill in the Source fields (Section 1) with your AssetWorx SQL server name, database, and authentication. Adjust the column list and company ID filter to match what the destination server expects.
2
Set the Output Path to a shared UNC path or local path that both the source machine (running BCP) and the destination SQL Server can access. Both scripts must reference the same path.
3
Copy and run the BCP OUT script from a Windows command prompt. This creates a tab-delimited flat file at the output path containing your AssetWorx asset records.
4
Fill in the Destination fields (Section 2) with the remote VA SQL server name, database, credentials, destination table, and the path to the flat file.
5
Copy and run the SQLCMD PUSH script. This creates a staging table on the remote server, bulk-inserts the flat file, then merges records into your destination table using rfidtag as the unique key.
6
Verify the row count on the destination server: SELECT COUNT(*) FROM [destination_table]. Compare against your AssetWorx company filter.

Frequently Asked Questions

Q: What is the difference between this page and va_bcp_query.html?
va_bcp_query.html generates a BCP command that pulls data out of a remote CDW/VistA server into AssetWorx (the input pipeline). This page generates a BCP command that pushes data out of AssetWorx to a remote VA SQL server (the output/reporting pipeline).
Q: Which columns should I include?
Include only the columns that the destination table is designed to receive. If sending to an AEMS-MERS endpoint, align your column list with that schema. The defaults cover the most commonly transferred AssetWorx fields.
Q: Can I filter to only recently changed records?
Yes — use the Additional WHERE Clause field, e.g.: a.lastmodified > DATEADD(day, -1, GETDATE()) for a daily delta push.
Q: What happens if a record already exists in the destination?
The SQLCMD and T-SQL scripts use a MERGE statement keyed on rfidtag. Existing rows are updated; new rows are inserted. No duplicates are created.
⚠️ Security reminder: These scripts contain database credentials in plaintext. Do not save or share generated scripts via email or untrusted channels. Use Windows Auth (-T) wherever possible for the AssetWorx source to avoid embedding passwords.

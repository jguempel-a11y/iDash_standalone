⚠ Deprecation Notice: Legacy Carrier SMS Gateways

Early experimental prototypes attempted to route administrative alerts to mobile phones via public cellular SMTP-to-SMS email gateways (e.g. 5551234567@vtext.com, @mms.att.net). In enterprise healthcare and VA environments, this mechanism is entirely unfeasible, non-compliant, and deprecated.

❌ Why Cellular SMS Gateways Failed

  • A2P 10DLC Carrier Blocking: Major US mobile operators (Verizon, AT&T, T-Mobile) have decommissioned or aggressively rate-limited unauthenticated email-to-SMS gateways to comply with FCC anti-spam mandates. Unauthenticated server alerts are dropped without delivery confirmation or bounce notices.
  • VA OIT Firewall & Gateway Filtering: VA enterprise mail relays (IronPort, Cisco ESA, Exchange Online) prohibit relaying automated alerts to public carrier domains, flagging them as potential data exfiltration or spam risks.
  • Unencrypted Wireless Transmission: Carrier SMS messages travel over unencrypted cellular networks, violating federal standards for transmitting facility health metrics, database paths, and equipment identifiers.
  • IIS App Pool Recycling Bug: Early implementations attempted to save SMS phone numbers directly into web.config, triggering immediate IIS App Pool recycles that kicked all active users offline and disrupted mobile sweeps.

✅ Modern iDash Alerts Architecture

  • In-App Visual Dashboards: Rich interactive status board on va_notifications.aspx with instant visual telemetry, color-coded status pills, and pulsing location mismatch indicators.
  • Asset Watch Lists: Clinical teams can monitor high-value, recalled, or missing assets by EE number or name, tracking when and where they are scanned during room sweeps.
  • Internal VA SMTP Relay: Administrative event alerts (SQL crash, missing autoload folders, print failures) route strictly through approved VA internal SMTP relays over TLS (ports 25/587) with authenticated deliverability.
  • Zero-Recycle JSON Storage: All recipient lists and trigger configs reside in isolated JSON files (config/email_recipients.json), preserving active user sessions and scanner connections.

2. System Automations & Event Triggers (va_automated_reports.aspx)

Administrative event alerts monitor background system health and dispatch structured alerts to technicians and system engineers when unexpected operational disruptions occur.

Event Trigger Key Monitored Component Trigger Condition & Action
Alert_DbFolderMissing Auto DB Update Processor Fires if the scheduled va_autodbupdate.aspx job starts but the configured \autoload network directory is inaccessible or missing.
Alert_DbCrash Database MERGE Pipeline Fires if a SQL transaction fails, encounters a syntax deadlock, or aborts mid-import, preventing silent inventory data drops.
Alert_PrintFailure Tag Team Scan Print Spooler Fires if the MQTT or REST print service encounters an HTTP 500 fatal internal server error when queuing RFID label print jobs.
Alert_TagAuditReport Diagnostic Test Trigger Fires whenever a user runs a Tag Audit Report export. Serves as a safe, non-destructive test to confirm end-to-end alert pipeline deliverability.
🛡 Master Kill-Switch & Granular Overrides: Section 1 of va_automated_reports.aspx provides a global master toggle to pause all outgoing alerts instantly during scheduled maintenance. Individual triggers can either inherit from the global email recipient list or declare dedicated on-call distribution groups.

3. Resilient Non-Recycling Configuration Architecture

In standard ASP.NET applications, modifying settings via WebConfigurationManager.Save() triggers an immediate IIS Application Pool recycle. To prevent session drops and ensure uninterrupted RFID sweeps, iDash stores dynamic alert routing outside of web.config:

Storage File Format Architectural Purpose
config/email_recipients.json JSON Array of email strings Stores distribution lists for automated reports and alerts. Updating recipients via the UI does not recycle IIS or log out field users. See Email Recipient Storage Guide.
config/report_automation.json Structured JSON Dictionary Persists per-site report schedules, recipient mappings, and trigger toggles cleanly on disk.

4. Developer C# Alerting API (App_Code/AlertingService.cs)

The AlertingService class is JIT-compiled at runtime and accessible globally across all ASP.NET Web Forms, WebMethods, and scheduled batch handlers. 

// 1. Dispatching a Rich HTML System Alert (Recommended)
AlertingService.SendSystemEmail(
    subject: "AWX CRITICAL: SQL Import Exception on Station 613",
    bodyHtml: "<h3 style='color:red;'>Import Failed</h3><p>Transaction rolled back at step 2.</p>",
    triggerKey: "Alert_DbCrash"
);

// 2. Legacy Method (Redirects to internal SMTP relay with newline sanitization)
AlertingService.SendAdminSms(
    message: "Autoload ingest directory not found at C:\\autoload",
    triggerKey: "Alert_DbFolderMissing"
);
🔑 Fail-Safe Exception Policy: The alerting dispatcher safely catches and logs transport exceptions during background triggers to guarantee that a network timeout communicating with an SMTP relay cannot crash the primary database transaction or interrupt an active RFID scan sweep.

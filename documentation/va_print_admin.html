1. Architecture Overview

Printing in iDash/iDash uses a message-based architecture where print commands flow through the iDash core API:

                    
   iDash UI    iDash API       MQTT    Print Server  BarTender 
  (Browser)         /api/printjob/          Broker          Service           Printer

Key Components

Component What It Does Location
iDash API Receives print requests, builds the label data payload, publishes to MQTT http://localhost/api/printjob/print
MQTT Broker Message bus that routes print commands to Print Server(s) Built into iDash API (port 8883 TLS)
Print Server Windows service that subscribes to MQTT, invokes BarTender SDK iDash.PrintServer.exe
BarTender Label design software that renders .btw templates and sends to physical printers C:\idash_prints\*.btw

2. How Printing Works

  1. User selects assets and clicks Print in iDash (Asset Master or TagTeam Scan)
  2. iDash calls IdashApiHelper.SubmitPrintJob() which:
    • Resolves the companyId from the selected template
    • Gets an OAuth token from the correct idash_XXX client app
    • POSTs to /api/printjob/print with the asset record ID and template ID
  3. The iDash API:
    • Creates a printjob row in the database
    • Looks up the asset data, template configuration, and label field mappings
    • Builds a full JSON payload with all label data
    • Publishes the payload to MQTT topic awrx/print/{PrintClientUsername}
  4. The Print Server (subscribed to the MQTT topic):
    • Receives the JSON payload
    • Opens the .btw BarTender template
    • Maps the asset data to template fields
    • Sends to the physical printer
    • Updates the printjob row: completed = 1, message = 'Print Successful'

3. Setting Up a New Site for Printing

💡 Easiest Method: Open Print Administration, go to the Site Overview tab, and click Quick Setup for any site marked "Incomplete". This auto-creates all three required items.

What "Quick Setup" Creates

For each site, three database records are needed:

Item Table Purpose Example
1. Template template Links the .btw file to this site and a printer AW_Std_Small, company 6 (Baltimore), MasterPrint
2. Site-Printer Mapping printclientcompany Authorizes this printer to handle jobs for this site MasterPrint company 6
3. API Client App clientapp OAuth credentials that produce a token with the correct cmpid idash_512 company 6

Manual Setup (SQL)

If you prefer to set up manually or need custom configuration:

-- Replace @cid with the company ID (e.g. 6 for Baltimore)
-- Replace @pcid with the print client ID (e.g. 10 for MasterPrint)

-- 1. Create template
INSERT INTO template (name, templatetype, filename, printmethod, companyid, printclientid)
VALUES ('AW_Std_Small', 'Asset', 'C:\idash_prints\AW_Std_Small.btw', 'Bartender', @cid, @pcid);

-- 2. Map printer to site
INSERT INTO printclientcompany (printclientid, companyid) VALUES (@pcid, @cid);

-- 3. Create API client app
INSERT INTO clientapp (clientid, granttype, secret, companyid)
VALUES ('idash_512', 'Client Credentials', 'YOUR_SECRET_HERE', @cid);

4. Managing Templates

Templates live in the template table and tie together:

  • Name — shown in the print dialog dropdown (e.g. AW_Std_Small)
  • Site — which company/site this template is for
  • BarTender File — the .btw file path on the server
  • Print Client — which printer/Print Server handles this template
  • Type — Asset, Location, or Employee
⚠ Important: Each site needs its own template row, even if they all use the same .btw file. The OAuth token's cmpid claim determines which site's templates are visible. Without a matching template, the API returns a 500 error.

5. Managing Print Clients

A Print Client is an MQTT-connected service that receives print commands. Each has:

  • Username — MQTT credentials (e.g. MasterPrint)
  • Password — MQTT password (must match appsettings.json)
  • Machine Name — hostname where the Print Server runs
  • Assigned Sites — which companies this printer serves

Currently there is typically one Print Client (MasterPrint) serving all sites. As you deploy to separate VA facilities with their own printers, each facility would get its own Print Client with its own MQTT credentials.

6. MQTT Configuration

MQTT is the message protocol that connects the iDash API to the Print Server. Configuration is in two places:

iDash API Side (appsettings.json)

C:\inetpub\wwwroot\iDash\appsettings.json

{
    "MqttServer": "localhost",
    "MqttServerPort": 8883,
    "PrintClientUsername": "MasterPrint",
    "PrintClientPassword": "V5MqttPrint2026!"
}

Print Server Side

The Print Server service reads its MQTT credentials from the printclient table. The username and password columns must match what's configured in appsettings.json.

MQTT Topics

Topic Direction Payload
awrx/print/MasterPrint API Print Server Full JSON with asset data, template config, label fields
awrx/print/status Print Server API Print completion status, error messages

7. BarTender Template Files

File Location

All .btw files are stored in: C:\idash_prints\

Requirements

  • The .btw file must exist on the server where the Print Server runs
  • The file path in the template table must exactly match the actual file path
  • BarTender must be installed and licensed on the Print Server machine
  • The Windows printer referenced in the .btw file must be configured

Printer Routing

The .btw file contains the Windows printer name. If you need to redirect to a different printer, configure printer_routing.json:

C:\idash_prints\printer_routing.json

{
    "AW_Std_Small.btw": "ZDesigner ZD621-203dpi ZPL",
    "AW_Large_Label.btw": "Zebra 4x6 Thermal"
}

8. Multi-Site Printing

How It Works

Each VA site (company) has its own:

  • Template in the template table pointing to the .btw file
  • Client App (idash_XXX) in the clientapp table
  • Print-Client-Company mapping linking the printer to the site

When a user logs into iDash, they only see templates for their site. The IdashApiHelper automatically:

  1. Resolves the companyId from the selected template's companyid column
  2. Picks the correct idash_XXX client credentials from the clientapp table
  3. Gets an OAuth token with the correct cmpid claim
  4. Posts to the API, which uses cmpid to find the right template and printer

9. Legacy PowerShell Print Server

⚠ Note: The PowerShell print spooler is the legacy/fallback method. The standard path is now through the iDash core API + MQTT. Use the PowerShell script only for scenarios where the API is unavailable or for one-off batch prints.

Scripts

Script Purpose
printing\Run_Bypass_Spooler.ps1 Polls the printjob table and sends jobs to BarTender. Runs as a background service.
downloads\Software\idash_prints\Run_Bypass_Print_Once.ps1 One-shot: processes all pending jobs then exits.
Assets\install_print_server.ps1 Installs the spooler as a Windows scheduled task.

When to Use the Legacy Script

  • The iDash API or MQTT broker is down and you need emergency printing
  • Batch printing from a machine without API access
  • Testing BarTender templates without full API setup
  • Sites that haven't migrated to the MQTT-based architecture yet

Legacy Script Requirements

  1. BarTender installed on the machine running the script
  2. Database connection string configured in the script
  3. Template files (.btw) accessible at the configured path
  4. Windows printer installed and configured
  5. No MQTT or API credentials needed — it reads directly from the DB

10. Printer Routing Configuration

printer_routing.json maps the .btw filename (key) to the exact Windows printer name (value). If a key is not found, BarTender falls back to the printer configured inside the .btw file itself.

Format

C:\idash_prints\printer_routing.json

{
    "AW_IQ350.btw":       "Metal_Small",
    "AW_Metal_Large.btw": "Metal_Large",
    "AW_Std_Small.btw":   "ZDesigner ZD621-203dpi ZPL"
}
✅ No Restart Required: printer_routing.json is read fresh on every print job. Save the file and it takes effect immediately.

Getting Exact Printer Names

The value must be character-for-character identical to the Windows printer name. Run on the target server:

Get-Printer | Select-Object Name | Sort-Object Name

Per-Server Routing

Each server has its own printer names. Maintain a separate printer_routing.json per server — do not copy between servers without updating the printer name values.

⚠ Multiple Copies Warning: The spooler reads printer_routing.json from $PSScriptRoot — the folder where the running script lives. If multiple copies exist, you may edit the wrong one. Find all copies: Get-ChildItem C:\ -Filter "printer_routing.json" -Recurse -ErrorAction SilentlyContinue

12. Print Method Comparison

There are three ways to print from iDash/iDash:

1. iDash Print Server (MQTT) 2. PowerShell Desktop Spooler
Status ✔ Primary (Recommended) ⚠ Legacy / Fallback
How it works iDash API MQTT Print Server BarTender Polls printjob DB table BarTender SDK direct
RFID Encoding ✔ Yes (BarTender) ✔ Yes (BarTender)
Multi-site ✔ Per-site OAuth tokens ✔ Direct SQL (all sites)
Session 0 safe ✔ Runs as Windows service ⚠ Must run on desktop (interactive session)
Setup needed Template + client app + MQTT credentials BarTender SDK + connection string + printer routing
⚠ Session 0 Note: The legacy PowerShell spooler exists because Windows background services (Session 0) cannot access interactive printer drivers. Some specialized printers (e.g., Printronix RFID encoders) throw interactive dialog prompts that freeze in Session 0. The spooler runs on the user desktop to avoid this. The MQTT-based Print Server resolves this differently consult BarTender documentation for your printer model.

13. Troubleshooting

Symptom Cause Fix
Print from iDash works but not from iDash Missing idash_XXX client app for the user's site, or template not associated with the correct companyid Go to Print Admin → Site Overview → Quick Setup
"NullReferenceException" in API logs The OAuth token's cmpid doesn't match any template in the template table Create a template row for the site's company ID
Print job created but never completes Print Server not running, or MQTT connection broken Check Print Admin Status tab. Restart the Print Server service.
No templates appear in print dialog User's site has no templates, or user has no company access Verify user's companyid in sysuser. Create template for that company.
"BarTender document could not be opened" The template.filename is a bare name without extension or full path UPDATE template SET filename = 'C:\idash_prints\AW_Std_Small.btw' WHERE id = X
All jobs go to the same printer (wrong routing) printer_routing.json key doesn't match .btw filename, or editing wrong copy Run Get-ChildItem C:\ -Filter "printer_routing.json" -Recurse to find all copies. Match keys to exact .btw filenames.
Routing shows correct printer but job goes wrong Printer name in JSON doesn't exactly match Windows printer name Run Get-Printer | Select-Object Name and compare character-for-character.
Auto-map always selects same template template.name doesn't match the tag type string from the mobile app (case-sensitive) Check tag type in mobile app, update template.name to match exactly.
"Asset not found" when printing Asset record ID doesn't exist for that company SELECT * FROM asset WHERE id = @recordId
"Topic Subscription Rejected NOT RECOGNIZED" Print client username exists in mqttclient table broker treats it as generic MQTT client instead of print client DELETE FROM mqttclient WHERE username = 'MasterPrint' then iisreset
"Print Client not currently connected" MQTT credentials mismatch between config files and database, or UseForPrinting is false Use Print Admin Config Files & Credential Sync panel. Click Auto-Fix. Restart IIS and Print Server service.
Password mismatch (case-sensitive) MQTT passwords are case-sensitive. V5MqttPrint2026! V5Mqttprint2026! Use the Config Sync panel to verify all three stores match exactly.

New Machine Setup Checklist

Complete checklist for setting up printing on a new iDash server. Follow these steps in order.

Key Lesson Learned

The printclient and mqttclient database tables serve different purposes. Print client usernames must ONLY exist in printclient, never in mqttclient. If a print client username also exists in mqttclient, the MQTT broker treats it as a generic MQTT client and rejects the awrx/print/ subscription.

Prerequisites

  1. iDash Web Portal installed and IIS configured
  2. BarTender installed (64-bit edition) with Integration & Licensing Services running
  3. iDash Print Server service installed (C:\Program Files (x86)\InfinID Technologies\iDash Print Server\)
  4. SQL Server Express with iDash database
⚠️ Critical Prerequisite: Install Order & System Reboot

The BarTender SDK DLLs (including Seagull.BarTender.Print.dll and Seagull.Interop.dll) required for printing from iDash will not be present or functional until:

  1. BarTender is installed (64-bit edition).
  2. iDash Print Server is installed (copies the Seagull assemblies into the Print Server directory).
  3. The server is rebooted to initialize BarTender system services, register native COM objects, and update the system environment PATH. Attempting to print prior to a reboot will fail with Could not load file or assembly 'Seagull.Interop.dll'.

Step-by-Step Setup

# Step Details
1 Create Print Client Print Admin Print Clients tab Add Print Client. Enter name, MQTT username (e.g. MasterPrint), password, machine name, and assign sites. This creates a row in the printclient table.
2 Verify mqttclient table Ensure the print client username does NOT exist in the mqttclient table. If it does, delete it:
DELETE FROM mqttclient WHERE username = 'MasterPrint'
3 Configure WebClient appsettings.json At c:\inetpub\wwwroot\iDash.WebClient\appsettings.json:
Set UseForPrinting = true
Set PrintClientUsername and PrintClientPassword to match step 1
Verify MqttServer = localhost and MqttServerPort = 8883
4 Configure Print Server appsettings.json At C:\Program Files (x86)\InfinID Technologies\iDash Print Server\appsettings.json:
Set PrintClientUsername and PrintClientPassword to match step 1
Set UseForPrinting = true
5 Create Templates Print Admin Templates tab Add Template. Map BarTender .btw files to sites and the print client.
6 Check Config Sync Print Admin Site Overview tab Config Files & Credential Sync panel. All rows should show Match. If issues exist, click Auto-Fix Config Issues.
7 Restart Services Run iisreset to restart the MQTT broker. Restart the iDash Print Server service via Services.msc.
8 Verify Print Admin Status & Logs tab. Print Server should show Running, MQTT should show Connected, and the print client should appear with a recent "Last Seen" timestamp.

Three Credential Stores (Must All Match)

Location File / Table Used By
WebClient appsettings.json c:\inetpub\wwwroot\iDash.WebClient\appsettings.json MQTT broker (validates connections) + iDash MQTT notifier (publishes jobs)
Print Server appsettings.json C:\Program Files (x86)\...\iDash Print Server\appsettings.json Print Server service (connects as MQTT subscriber)
DB printclient table SQL: SELECT username, password FROM printclient MQTT broker validates incoming connections against this table

14. Setup Wizard

🚀 Recommended for New Deployments

The Setup Wizard is the fastest way to configure printing on a new server. It replaces the manual steps described in sections 3, 6, 11, and 12 of this document with a single guided form that auto-configures everything.

What Is the Setup Wizard?

The Setup Wizard is a tab on the Print Admin page that consolidates all MQTT/printing configuration into a guided, 3-phase experience. Instead of manually editing appsettings.json files, running SQL, and restarting services separately, the wizard handles it all from one form.

When to use it:

  • Setting up printing on a brand new server
  • Adding a new site to an existing server
  • Fixing credential sync issues after a config change
  • Re-running setup after a database restore

How to Access

Navigate to Print Admin click the 🚀 Setup Wizard tab.

Phase 1: Configuration Form

The wizard auto-detects your current configuration and pre-fills all fields. Review and adjust as needed before running.

Field Auto-Detected From Purpose
MQTT Server appsettings.json ConfigSettings MqttServer Hostname of the MQTT broker (usually localhost)
Port appsettings.json ConfigSettings MqttServerPort MQTT port (8883 for TLS, 1883 for unencrypted)
PFX Certificate Path appsettings.json ConfigSettings AuthServerPfxPath TLS certificate for MQTT encryption (read-only display)
Display Name printclient.name (DB) Friendly name shown in the UI (e.g., "Master Print Server")
MQTT Username printclient.username (DB) or PrintClientUsername (config) MQTT authentication username for the print client
MQTT Password printclient.password (DB) or PrintClientPassword (config) MQTT authentication password (shown in plain text for verification)
BarTender File Path Default: C:\idash_prints\AW_Std_Small.btw Path to the BarTender label template file on the print server
Sites to Configure company table (DB) Checkboxes for each site. Sites with existing templates/API keys show green badges.

Config Files Detected The right column shows the existence and status of both appsettings.json files and the current UseForPrinting setting.

Phase 2: Execution (8 Steps)

After clicking Run Setup, the wizard executes 8 sequential steps. Each step shows a status icon ( pass, warning, failure) with a detailed explanation of what changed.

Step Action What It Does
1 Read WebClient appsettings.json Reads the current config and reports what it found (server, port, username, UseForPrinting status)
2 Set UseForPrinting = true Enables printing in the WebClient config. Reports oldnew value.
3 Sync credentials to WebClient config Writes PrintClientUsername, PrintClientPassword, MqttServer, MqttServerPort to the WebClient appsettings.json
4 Sync credentials to Print Server config Same as Step 3 but for the Print Server's appsettings.json. Shows if file not found (Print Server not on this machine).
5 Upsert printclient record Creates or updates the print client record in dbo.printclient with the entered username/password/name
6 Remove mqttclient conflicts Deletes any rows in dbo.mqttclient matching the print client username. These cause the MQTT broker to reject print subscriptions.
7 Create templates for sites For each selected site: inserts a template row in dbo.template and creates the printclientcompany mapping. Skips sites that already have templates.
8 Create clientapp API keys For each selected site: creates an idash_SiteName API client in dbo.clientapp. Skips sites that already have API keys.

Phase 3: Summary & Restart

After all steps complete, the wizard shows:

  • Results table Every step with its status, details, and file paths modified
  • Restart IIS Now button Triggers iisreset /restart from the web page. Shows a full-screen "Restarting..." overlay and auto-reloads the page after 12 seconds.
  • Action buttons "View Status & Logs" (switches to Status tab) and "Run Wizard Again" (returns to the form with refreshed defaults)
IIS Restart Behavior

Clicking "Restart IIS Now" will terminate all active user sessions. The page auto-reloads after ~12 seconds. If the page does not reload, IIS may need to be restarted manually via iisreset from an elevated command prompt. Users can also choose to restart manually instead of using the button.

Developer Reference

The wizard is implemented entirely in two files:

File What It Contains
va_print_admin.aspx HTML for the 3-phase wizard UI (#tab-wizard, #wizPhase1/2/3) + JavaScript functions (loadWizardDefaults(), runWizard(), animateStep(), showWizardSummary(), doRestartIIS())
va_print_admin.aspx.cs Three API handlers: GetWizardDefaults() (auto-detect), RunSetupWizard() (8-step execution), RestartIIS() (fires iisreset). Helper: MakeStep() builds step result dictionaries.

API Endpoints:

Endpoint Method Description
?action=api&cmd=getWizardDefaults GET Returns auto-detected settings from config files + DB for form pre-fill. Includes site list with hasTemplate/hasClientApp flags.
?action=api&cmd=runWizard POST Accepts form data as JSON body (mqttServer, mqttPort, username, password, clientName, btwPath, siteIds[]). Executes all 8 steps. Returns { success, steps[], summary{total,passed,warned,failed} }
?action=api&cmd=restartIIS GET Fires iisreset /restart via Process.Start(). Fire-and-forget; the response may not arrive since IIS shuts down.

Key Design Decisions:

  • The wizard does not auto-restart IIS it always requires user confirmation via a button click
  • Steps that produce warnings (e.g., Print Server config not found) do not block execution they are expected on servers without the Print Server installed locally
  • The wizard is idempotent running it multiple times is safe; existing templates/API keys are skipped, credentials are updated to the new values
  • Database credentials in the printclient table are the source of truth for the auto-fill. Config files are secondary sources.

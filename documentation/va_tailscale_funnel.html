🔗 Tailscale Funnel — Remote Access Setup

Networking Remote Access VISN5-8

Overview

This guide configures Tailscale Funnel on VISN5-8 to expose AssetWorx and iDash (running on IIS port 80) through a public HTTPS URL. VA staff can then access iDash, print labels, and use all web features from their desktop without VPN or firewall changes.

Prerequisites

  • Tailscale client installed on VISN5-8 and signed in as v5martinsburg@id-integration.com
  • IIS running and serving AssetWorx / iDash on port 80 (http://localhost/iDash works locally)
  • Admin access to the Tailscale admin console at login.tailscale.com/admin
  • Administrator PowerShell on VISN5-8

Step 1 — Enable Funnel in the Admin Console

These settings are account-wide and only need to be done once per tailnet.

1a. Enable MagicDNS

  1. Go to login.tailscale.com/admin/dns
  2. Scroll to MagicDNS — toggle it ON if not already

1b. Enable HTTPS Certificates

  1. On the same DNS page, find HTTPS Certificates
  2. Click Enable HTTPS
  3. This lets Tailscale auto-provision TLS certs for your .ts.net domain

1c. Allow Funnel in ACLs

  1. Go to login.tailscale.com/admin/acls
  2. Edit your access policy and add (or merge into existing nodeAttrs):
"nodeAttrs": [
  {
    "target": ["autogroup:member"],
    "attr":   ["funnel"]
  }
]

Click Save. This allows all members of your tailnet to use Funnel.

Step 2 — Enable Unattended Mode

This ensures Tailscale stays connected even when no user is logged in (critical for a server).

Option A — GUI:

  1. Right-click the Tailscale tray icon on VISN5-8
  2. Go to Preferences
  3. Check Run unattended

Option B — CLI:

tailscale up --unattended

Step 3 — Verify Tailscale Service

Make sure the Tailscale service starts automatically on boot:

# Run in elevated PowerShell on VISN5-8
Get-Service Tailscale | Select-Object Name, Status, StartType

# Should show: Running / Automatic
# If not:
Set-Service -Name Tailscale -StartupType Automatic
Start-Service Tailscale

Step 4 — Start Tailscale Funnel

Open an Administrator PowerShell on VISN5-8 and run both commands:

# Funnel 1: iDash / AssetWorx (IIS port 80 → public HTTPS 443)
tailscale funnel --bg 80

# Funnel 2: BarTender Print Portal (port 8080 → public HTTPS 8443)
tailscale funnel --bg --https=8443 8080

Tailscale will:

  • Auto-provision a TLS certificate for visn5-8.tail<xxxxx>.ts.net
  • Listen on public HTTPS port 443 → proxy to local IIS port 80
  • Listen on public HTTPS port 8443 → proxy to local BarTender port 8080
💡 The --bg flag is critical

Without --bg, Funnel only runs while the PowerShell window is open. With --bg, it runs as a background service and survives reboots.

📖 Funnel Port Limitations

Tailscale Funnel only supports public ports 443, 8443, and 10000. You cannot use 8080 as the public-facing port, which is why BarTender is mapped to 8443 instead.

Step 5 — Get Your Public URLs

# Check what URLs were assigned
tailscale funnel status

Output will show something like:

#
# https://visn5-8.tail12345.ts.net:8443/
# |-- proxy http://127.0.0.1:8080
# Funnel on (tailnet + public)

URLs for VA users:

App Public URL
iDash https://visn5-8.tail<xxxxx>.ts.net/iDash/
BarTender Print Portal https://visn5-8.tail<xxxxx>.ts.net:8443/

Step 6 — Test from Outside

  1. On a device NOT on the tailnet (e.g., a VA user's desktop, your phone), open a browser
  2. Test iDash: navigate to https://visn5-8.tail12345.ts.net/iDash/ — should see the login page
  3. Test BarTender: navigate to https://visn5-8.tail12345.ts.net:8443/ — should see the Print Portal
  4. Test printing to confirm the full stack works through the tunnel

Step 7 — Verify After Reboot

Restart VISN5-8 and confirm Funnel comes back automatically:

# After reboot, check status
tailscale funnel status
tailscale status

Both should show the node online and Funnel active.

Security Considerations

⚠ Funnel = Public Internet Access

Tailscale Funnel exposes your server to the entire internet, not just your tailnet. Anyone with the URL can reach IIS. Make sure:

  • iDash and AssetWorx have authentication enabled (login required)
  • IIS is not serving other sensitive apps on port 80
  • The WebClient API requires Bearer token auth (it does by default)
  • Consider IP allowlisting in IIS if only specific VA networks need access

Troubleshooting

Symptom Fix
funnel: not enabled ACL policy missing "funnel" attr — see Step 1c
HTTPS cert error Enable HTTPS Certificates in the admin DNS page — see Step 1b
502 Bad Gateway IIS is not running or not listening on port 80. Check with netstat -an | findstr :80
Funnel gone after reboot Re-run tailscale funnel --bg 80. Ensure Run unattended is on (Step 2). Verify Tailscale service is Automatic (Step 3).
Page loads but prints fail MQTT runs on a separate port (8883) not exposed by Funnel. Print jobs go DB → MQTT → Print Server, so MQTT only needs to work locally on the server. Printing should still work.
Can't reach from VA desktop VA firewall may block *.ts.net. The user needs outbound HTTPS (443) to Tailscale's relay. No inbound rules needed on the VA side.

How It Works (Architecture)

VA User's Browser
    |
    | HTTPS (port 443)
    v
Tailscale Edge (cloud relay)
    |
    | Encrypted WireGuard tunnel
    v
VISN5-8 Tailscale Client
    |
    | HTTP (port 80, localhost)
    v
IIS → AssetWorx WebClient → iDash
    |
    | MQTT (port 8883, localhost)
    v
AssetWorx Print Server → BarTender → Label Printer

Key: The VA user only needs outbound HTTPS. No VPN, no firewall rules, no port forwarding. Tailscale handles TLS termination and proxies to local IIS.
